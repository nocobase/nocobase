# Issue detail

An issue's page as presentational parts, for an application that composes the page over its own data hooks (the assembling
application over `@nocobase/app-plugin-projects/client/issues`). It installs into `client/extensions/nocobase-issue-detail/`
and brings `issue-table` (status badges), `issue-card` (the sub-issue and dependency rows), `property-fields` (the side column's card and fields),
`rich-text-editor`, `comment-thread`, `attachment-list` and `markdown-view` with it.

| File                   | Exports                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `issue-detail.tsx`     | `IssueDetailLayout`, `IssueSurface`, `ISSUE_SURFACE`, `IssueHeader`, `IssueDescription`, `IssueSection`, `IssueAddBar`, `IssueAddButton`, `IssueFilesButton`, `IssueFileDrop`, `IssueChecklist`, `IssueApprovalCard`, `IssueRecentApprovals`, `IssueSubtasks`, `IssueDependencies`, `IssueAttachments`, `IssueDeleteButton` |
| `issue-properties.tsx` | `PropertyColorPicker`, `IssueFollowers`, `IssueDates`, `IssueStartDialog`; the card and its fields are `property-fields`'                                                                                                                                                                                                   |
| `issue-picker.tsx`     | `IssuePicker`, an issue search over an async `onSearch`                                                                                                                                                                                                                                                                     |
| `labels.ts`            | `IssueDetailLabels` and the English defaults                                                                                                                                                                                                                                                                                |

Every part takes its data through props and reports changes through callbacks; a change that the server performs
answers a promise the part waits for (the editor stays open, the button stays busy). Links go through `link`, a
renderer the application gives (a router link), and default to a plain anchor. Every word comes from `labels`:
build an `IssueDetailLabels` from your locale resources and pass it to each part. The block ships no locale files.

`IssueDetailLayout` lays the page out on the application's background with its own padding: the main column stacks its cards, the side column (20rem from `lg` up) stacks the `property-fields` cards. The main column has two: the body in `IssueSurface` (or `ISSUE_SURFACE` on the `IssueFileDrop` that wraps it), and the activity in a second one below. The title and the description open the body. Every secondary part below them is an `IssueSection` inside the body's card: a heading row (icon, name, count, actions at the end) over its content, set off by a thin divider, with `ISSUE_SECTION_LIST` for a list of rows inside one. Draw the application's own sections (an agent's runs, pull requests, previews) with it too, so the page reads as one list. A part with nothing to show renders nothing: `IssueSubtasks`, `IssueAttachments` and `IssueDependencies` take no room while empty, and the buttons that add their first item go in `IssueAddBar` under the description (`IssueAddButton`, `IssueFilesButton`; `IssueDependencies` opens its search through `adding` and `onAddingChange`). `IssueFileDrop` around the body uploads files dropped on it or pasted while something in it has focus. Lay the activity line out with `comment-thread` in its own `IssueSurface`: it is what happened rather than what the issue is, and it grows without bound.
