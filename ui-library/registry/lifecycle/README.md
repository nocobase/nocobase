# Lifecycle diagram

Install `@nocobase/lifecycle-diagram` with `yes n | pnpm exec shadcn add @nocobase/lifecycle-diagram`. It installs `client/components/lifecycle-diagram.tsx` and its `@nocobase/flow-diagram` dependency. The lifecycle import is type-only; the diagram calls no runtime or HTTP APIs. Read `@nocobase/lifecycle-diagram-demo` for a complete example.

Pass `LifecycleDescription` from `runtime.describe()` or the hook's `description.description`, the current record state and the names of allowed `view.available` entries. The underlying graph model expands each declared source/destination pair; in the default `presentation="process"` mode, backward and self-transitions stay off the canvas layout and appear in hover/focus notes beside their endpoints (pass `presentation="classic"` to draw every pair on the canvas). Current state and available outgoing transitions are highlighted; initial and terminal states have distinct type icons and status captions. Executed paths remain solid, while available highlighted paths use a motion-aware dashed accent. The diagram displays possible destinations; availability does not identify which destination a dynamic route will actually choose.

Use `stateLabel` and `transitionLabel` to translate titles by stable names. `renderState` can display initial markers (from `description.initialStates`), state metadata and effect badges. `onStateClick` and `onTransitionClick` receive the full description entries, so the caller can display accepted fields, effects, triggers and success/failure continuations in its details panel. Clicking never fires a transition. Pass `history={view.history.transitions}` for executed paths: edges match the exact transition, source and destination, including retries and parallel paths. `visitedStates` can supplement node highlights but never implies an executed edge. A record's current state does not identify its history. Keep `toMermaid()` for Markdown documentation and export.

In the default `presentation="process"` mode, cards use 240×80 canvas units and boundary pills use 176×44 (176×64 with a description); explicit `presentation="classic"` uses 232×104 state cards with a type icon, title, separate status footer and parameter badge when bound. Bound transitions also include a translated Parameters caption, including threshold rules attached to submission rather than a state. The shared canvas includes semantic execution highlights and translated zoom/fit controls. The default is `presentation="process" direction="DOWN" autoHeight`: the canvas follows the full routed graph vertically instead of shrinking it into a fixed-height panel. Explicit `direction="RIGHT" autoHeight={false}` with a bounded height remains available for compact consumers. `initialMinZoom` also applies to automatic height (defaulting to `0.1` in process mode and `0.7` in classic mode); use `0.8` when you want larger initial text on narrow screens with panning. Use `stateActions` for explicit node configuration buttons and `nodeDescription` for real saved policy summaries.

Canvas dimensions, direction, layout errors and translation keys follow [Flow diagram](../components/README.md#flow-diagram). This component adds no locale keys of its own.

Pass a translated `endLabel` (for example, `endLabel={t('diagram.end')}`) to show a separate compact end marker after each explicitly final state. These markers are decorative and never invoke state/transition handlers. A non-final state without outgoing transitions is not treated as an ending.

Highlights use the application `--primary` token: current nodes have an accent border and ring, visited nodes a subtler accent border, and executed/available edges an accent stroke. Ordinary edges remain subdued; labels sit directly on their routes. Execution status is also shown as text and an icon, so it does not rely on color alone. The same theme tokens adapt to light/dark mode and application theme changes; do not replace them with a diagram-specific palette. Use `transitionLabel` to append `⚙` to automatic transitions when needed, rather than using dashed lines to distinguish them.

## Workflow management

`@nocobase/workflow-management` installs the workflow administration block: one page with Definitions and Executions tabs, definition and execution lists, diagram/parameter cards, and historical execution inspection. It takes application-owned data, labels and callbacks. See [the block contract](workflow-management/README.md) and `@nocobase/workflow-management-demo`; it imports no example plugins and installs no backend.

## Compact process presentation (default)

`LifecycleDiagram` defaults to `presentation="process"`, using the shared `FlowDiagramStep` boundary pills and work cards, compact spacing, multiline transition labels, fullscreen controls and a shape-aware overview. Pass `presentation="classic"` only when a consumer explicitly wants the legacy full-edge card layout; existing props, configuration bindings, state/transition callbacks and exact history matching continue to work in both modes. Both presentations use the same React Flow/ELK components and data adapter.

The default process presentation uses start pills for initial states, success pills for final states (defaulting folded `exitStates` to `negative` when `stateKind` is omitted), and work cards for intermediate states. Pass `stateKind(state)` to explicitly distinguish approval/work steps and negative/exception outcomes; the library does not infer business semantics from state names, and `stateKind` affects visual styling only. Pass `exitStates` (a list of final state names or a predicate on `stateInfo`) when a dense process has shared early-termination final states reachable from many stages (such as `rejected`, `voided`, or `cancelled`): those final states leave the main canvas so their fan-in wires never clutter the layout, and their outgoing routes appear inside each source node's hover/focus `FlowDiagramTransitionNotes` card (keeping `onStateClick` and any `configuration`/`stateActions` controls interactive right on those note entries). Non-final states passed to `exitStates` are ignored and remain on the canvas, and omitting `exitStates` keeps every final state on the canvas. In execution history views, when `currentState` is a folded exit state and `history` identifies the last transition's canvas source state, that source node carries the terminal outcome badge and accent directly (for example a red `Rejected` badge) instead of generic `Current`; if no canvas source is present in `history`, that active exit state remains on the canvas highlighted as current so execution status stays visible while any other folded exit states stay off the canvas. `renderState` customizes the title, `nodeDescription` provides an arrival or policy summary, and `stateActions` and `configuration` retain their existing authorized controls. Definitions without history show a plan; execution views distinguish current, visited and unreached states. The process presentation keeps all backward and self-transitions out of the canvas layout, including adjacent returns that ELK can route as long loops. These routes stay omitted during hover and focus, even if a caller supplies legacy `revealEdges`. Hovering or focusing either endpoint shows a card beside that node that lists each such transition once under Leaves to or Arrives from, with the states at the other end, and outlines those states while dimming the rest; this does not rerun layout or draw a long loop. When several forward edges of one transition reach the same state, only the edge from the nearest source carries the label; the others show it on hover. State declaration order defines forward progress for this presentation. Recorded transition data and history lists remain complete; explicit `presentation="classic"` retains every line. Dimensions are fixed by the presentation (240×80 cards, 176×44 pills, 208×44 pills with actions, or 176×64 / 208×64 with a description). Direction, sizing and canvas control props still accept explicit overrides.

The lifecycle and workflow-management demos use this default presentation for their definition and execution diagrams.

Node configuration controls are fixed-size icon-only buttons so long translated labels do not displace state titles. `configuration.label(target)` supplies the direct button's accessible name and hover hint; full labels remain visible in the configuration chooser. Keep additional `stateActions` compact and give icon buttons translated accessible names and hover hints.
