## Agent run history

`agent-run-history` presents the runs an agent made on one subject, such as an issue: a side-column panel with the open runs pinned (a running one counts its time, a queued one says when it was queued) and the last finished runs on two lines each (agent and status, then duration and when), "View all" opening every run filtered by agent and status, the pill that says who is working now, a run's row on an activity line, its transcript (or one event of it as a list item, `RunTranscriptRow`, for a list of one's own) and its brief. Map your runs to `AgentRunHistoryRun` (newest first) and their events to `RunTranscriptEvent`; `runHref` and `onOpenRun` open a run, `onStop` and `onRetry` report actions for you to confirm and perform. Every word comes from the `labels` props, English by default, and the component ships no locale keys. It installs into `client/components/` like the generic components; its source sits here because it is about agents and imports no other item.

## Agent composer

`agent-composer` is the box a person writes to an agent in: the page's context as removable chips inside the field, Enter to send and Shift+Enter for a new line, a round icon-only send button that turns into Stop while the agent works on an empty box, and a `toolbar` slot after the attach button for pickers such as the agent and the model. `inputClassName` styles the text box itself, such as a taller `min-h-28` where the box is a page's main content. Both variants are one bordered field holding the chips, the text and a bottom row with the toolbar and the send button. `variant='panel'` is the narrow box of a side panel; it is a container, and its keyboard hint shows only where the row has room for it on one line. `variant='page'` is the roomier field of a full page. `onSend` returns true, or a promise of true, once the message is taken, which empties the box; `sending` shows a spinner and `disabled` keeps the text editable while nothing may be sent. What ties it to a chat panel is optional: `context` (the chips from the plugin's `contextChips` and the context from `buildPageContext`), `draft` (text an "Ask agent" button puts in once) and `registerFocus`. The `agent-chat` block wires all three from `useChatPanel` and `useChatSources`. With `attachments` the box takes files too: an attach button, a pasted screenshot and files dropped on it (or on the view around it, which passes them in through `attachments.registerAdd`). Each file uploads as soon as it is added through `attachments.upload` and shows above the text, an image as a thumbnail and anything else as a chip, each removable (an uploaded one goes to `attachments.discard`); a file over `maxSize` (20 MB by default) or one whose upload failed is marked and keeps the message from being sent, at most `maxCount` (10) are taken, and a message sent while files upload goes once they are done. `onSend` then receives the uploaded files as its third argument. Every word comes from the `labels` prop, English by default, and the component ships no locale keys.

## Agent picker

`agent-picker` is the one way to pick an agent: a trigger with the agent's avatar, its availability dot on the avatar's corner, and its name, and a menu of the agents the viewer may pick, grouped by type (Online, Runner), each with its default and "only me" tags and its availability. Pass the agents (`ChatAgent`), `value` and `onSelect`. It has two appearances. `field`, the default, is for forms and settings: it looks exactly like the application's select trigger, shows no tags on the trigger, and takes `type` to offer only Online or Runner agents, `noneOption` for a "no agent" choice at the top (checked while `value` is null), `placeholder` while nothing is chosen, `disabled` while saving and `id` for a label; a value the list does not hold reads as `labels.unknown`, or as `shown` says. `toolbar` is for a composer's toolbar: the mode tag shows where the container is wide and the hint under the menu says what picking means; `bound` marks an existing conversation, whose agent cannot change, so picking another starts a new conversation and nothing is checked; `shown` overrides what the trigger shows, such as a conversation whose agent is gone or answered by the system default for now. The `agent-chat` block puts the toolbar appearance in `agent-composer`'s toolbar before a conversation's first message, beside the attach button and the model picker. `AgentIdentity` is the trigger's avatar, dot and name as one row, for a picker that lists agents among other things, such as an executor picker that offers people and agents; `AvailabilityDot`, `ModeTag`, `AgentTags` and `AgentTag` are exported for a page that shows an agent without the menu. Every word comes from the `labels` prop, English by default, and the component ships no locale keys.
