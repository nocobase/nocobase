# Notification Logs UI

Install `@nocobase/notification-logs-ui` from the UI Library for editable delivery and Provider attempt logs. The block uses the authenticated `GET /api/notifications/logs` API exposed by `@nocobase/app-plugin-notification`. It displays the newest 100 logs; the API's `meta.nextPageToken` can be passed back as `pageToken` when extending the application-owned UI with pagination.

Import `NotificationLogsPage` from the installed `index.ts` and mount it in an application-owned route. The block renders its own heading by default; pass `showHeading={false}` to `NotificationLogsPage` or `NotificationLogsView` when the page already titles the view, for example when it is one tab of a settings module beside Notification templates. The application chooses the route and its access policy; the block registers neither a plugin nor a route. `NotificationLogsView` accepts a `loadLogs(signal)` callback for a different data source or a static preview. Keep authorization on the server API.

Merge each installed `locales/<locale>.ts` default export into the matching application or consuming plugin resource, before local overrides, for example `...notificationLogs` in the application's `client/locales/en-US.ts` and the same locale's file in each other locale. The block uses the current namespace under `notificationLogs`, with English defaults. Twelve translations are included: de-DE, en-US, es-ES, fr-FR, id-ID, ja-JP, ko-KR, pt-BR, ru-RU, vi-VN, zh-CN and zh-TW. The exported resources carry no top-level `overrides`, so the merged application resource keeps its `AppResource` shape and every locale annotated with it still type-checks. It does not require the original plugin's namespace for presentation.

Inside the NocoBase repository, copy the files and dependencies declared in `ui-library/registry/notification/registry.json`, preserving workspace dependency ranges. Outside the repository, run `pnpm exec shadcn add @nocobase/notification-logs-ui` from the consuming project. Installed source belongs to the application: merge upstream changes while preserving its customizations, and remove only the installed block when it is no longer used.

The log view is a read snapshot with contextual Retry after a failed load; it has no persistent Refresh action. A host that presents it as a live progress monitor must wire its existing invalidation mechanism to the data source. Browser reload only reads the snapshot and never retries a delivery. Merge the `retryRead` locale key when reconciling an existing installed copy.

Dates follow the application's current language (`i18n.language`), not the browser's. Status badges use the theme's `--status-success` and `--status-warning` colors, so they follow the application's theme preset and dark mode. The logs table uses a fixed layout: the source column takes the remaining width and truncates with the full value in its tooltip, the notification ID shows its first group with the full ID in its tooltip, and status, deliveries and time are narrow columns.
