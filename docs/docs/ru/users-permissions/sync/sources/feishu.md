# Синхронизация пользовательских данных из Feishu

<PluginInfo commercial="true" name="feishu"></PluginInfo>

## Введение

Плагин **Feishu / Lark** синхронизирует пользователей и отделы организации Feishu с NocoBase. Поддерживаются ручная полная синхронизация и инкрементальные обновления через HTTP callback или соединение Stream.

## Перед началом работы

1. Установите и включите плагины **Feishu / Lark** и **Синхронизация пользовательских данных**.
2. Создайте корпоративное приложение на открытой платформе Feishu, см. [Аутентификация: Feishu / Lark](/auth-verification/auth-feishu/).
3. Выдайте права на чтение контактов и настройте область видимости контактов, как описано ниже.

## Права на контакты и область видимости

В разделе **Права** приложения включите следующие права:

| Право | Идентификатор (scope) | Обязательность | Назначение |
| --- | --- | --- | --- |
| Получение базовой информации о пользователе | `contact:user.base:readonly` | Да | Читает имя пользователя, `open_id` / `union_id` и другие базовые поля. |
| Получение базовой информации об отделе | `contact:department.base:readonly` | Да | Читает названия отделов и иерархию. |
| Получение организационной структуры отделов | `contact:department.organize:readonly` | Да | Обходит дочерние отделы; читает руководителей отделов. |
| Получение организационной структуры пользователя | `contact:user.department:readonly` | Да | Читает отделы пользователя и основной отдел. |
| Получение user ID пользователя | `contact:user.id:readonly` | Обязательно при идентификаторе `user_id` | Читает поле `user_id`. |
| Получение номера телефона пользователя | `contact:user.phone:readonly` | Для синхронизации телефонов | Читает телефон; обязательно при идентификаторе `mobile`. |
| Получение email пользователя | `contact:user.email:readonly` | Для синхронизации email | Читает email; обязательно при идентификаторе `email`. |

:::warning
Без права **Получение базовой информации о пользователе** API не возвращает имена пользователей, и никнеймы после синхронизации будут пустыми. Права API определяют, какие поля может читать приложение, а **область видимости контактов** — какие отделы и пользователей; настроить нужно и то, и другое. Область синхронизации следует области видимости: синхронизируются только разрешенные отделы и пользователи. После изменения прав или области выполните полную синхронизацию заново. Подписка на события не заменяет права на чтение: при каждом событии NocoBase всё равно запрашивает актуальные данные через API Feishu.
:::

## Добавление источника синхронизации Feishu

Перейдите в **Пользователи и права** → **Синхронизация** и добавьте источник типа **Feishu / Lark**:

| Поле | Описание |
| --- | --- |
| Имя источника | Уникальное имя источника синхронизации. |
| Включено | Запускает прием событий источника и позволяет выполнять задачи синхронизации. |
| Регион | `Feishu China` или `Lark Global`. |
| App ID / App Secret | Учетные данные приложения Feishu. Поддерживаются переменные окружения и секреты. |
| Поле уникального идентификатора пользователя | `user_id`, `union_id`, `open_id`, `mobile` или `email`; рекомендуется `union_id`. Должно совпадать с аутентификатором; пользователи без значения выбранного поля пропускаются. |
| Способ приема событий | **HTTP callback** или **режим Stream**, см. ниже. |

Сохраните и включите источник, затем нажмите **Синхронизировать** для первой полной синхронизации.

## Выбор способа приема событий

### Режим Stream

Режим Stream поддерживает постоянное WebSocket-соединение, инициируемое сервером NocoBase. Публичный адрес обратного вызова, токен и ключ шифрования не требуются.

1. Выберите **режим Stream** в NocoBase, сохраните и включите источник.
2. На платформе в разделе **События и обратные вызовы** переключите способ приема на **длинное соединение (WebSocket)** и подпишитесь на события контактов.

Соединение запускается автоматически при включении источника (с автоматическим переподключением) и обновляется или закрывается при изменении, отключении или удалении источника.

:::info
Режим Stream не требует публичного входящего адреса и обратного прокси — подходит для внутрисетевых развёртываний. Статус соединения можно проверить в журналах приложения по строке `Feishu stream client`.
:::

### HTTP callback

Режим HTTP callback принимает события Feishu по адресу обратного вызова NocoBase.

1. Выберите **HTTP callback** в NocoBase и задайте **Verification Token** и, при необходимости, **Encrypt Key** — требуется хотя бы один.
2. Сохраните источник и скопируйте **URL обратного вызова событий** из интерфейса.
3. На платформе в разделе **События и обратные вызовы** → **Настройка событий** выберите отправку событий на сервер, вставьте URL и подпишитесь на события контактов.

Адрес обратного вызова должен быть доступен для Feishu (в продакшене — HTTPS). При настроенном Encrypt Key содержимое обратных вызовов шифруется.

:::warning
Без Verification Token или Encrypt Key запросы отклоняются (401). После перевода источника в режим Stream HTTP-эндпоинт закрывается (403).
:::

## Поддерживаемые инкрементальные события

Оба способа поддерживают следующие события контактов Feishu:

| Событие | Обработка в NocoBase |
| --- | --- |
| `contact.user.created_v3` | Создание или обновление пользователя. |
| `contact.user.updated_v3` | Обновление пользователя. |
| `contact.user.deleted_v3` | Удаление синхронизированного пользователя. |
| `contact.department.created_v3` | Создание или обновление отдела. |
| `contact.department.updated_v3` | Обновление отдела. |
| `contact.department.deleted_v3` | Удаление синхронизированного отдела. |

Пользователи с ролью Root при синхронизации никогда не удаляются.

## Синхронизируемые поля

### Поля отделов

| Поле Feishu | Поле / назначение в NocoBase |
| --- | --- |
| `open_department_id` | Уникальный идентификатор отдела в источнике. |
| `name` | Название отдела. |
| `parent_department_id` | Родительский отдел для построения иерархии. Отделы с родителем вне области видимости синхронизируются как корневые. |

### Поля пользователей

| Поле Feishu | Поле / назначение в NocoBase |
| --- | --- |
| Значение поля идентификатора | Идентификатор источника и имя пользователя на основе **поля уникального идентификатора**. |
| `name`, иначе `en_name` | Никнейм; пустой, если оба отсутствуют. |
| `mobile` | Телефон. |
| `email` | Email. |
| `department_ids` | Отделы пользователя; только в пределах области видимости. |
| `main_department_id` | Основной отдел. |

### Руководители отделов

Руководители отделов (лидеры) из данных отделов синхронизируются как владельцы отделов в NocoBase: пользователь может руководить несколькими отделами, и руководимый отдел не обязан быть основным. Участвуют только отделы в области видимости. Снятые на стороне Feishu руководители снимаются при следующей синхронизации; вручную измененные в NocoBase руководители могут быть перезаписаны.

Другие поля пользователя Feishu (аватар, должность, табельный номер) в настоящее время не синхронизируются.

## Устранение неполадок

- Пустые результаты или отсутствующие отделы: проверьте права на чтение контактов и наличие отдела в области видимости.
- Пустые никнеймы: включите право **Получение базовой информации о пользователе** (`contact:user.base:readonly`) и выполните полную синхронизацию заново.
- Пользователи пропускаются: проверьте наличие у пользователя значения выбранного поля идентификатора и его совпадение с аутентификатором.
- HTTP callback возвращает 401: не настроен Verification Token или Encrypt Key, либо проверка токена не прошла; 403: источник переведен в режим Stream.
- Ошибки `redirect_uri` или адреса обратного вызова: убедитесь, что адрес на платформе точно совпадает с показанным в NocoBase, включая префикс вложенного пути (`APP_PUBLIC_PATH`).
- Задача синхронизации завершается ошибкой лимита API Feishu: дождитесь снятия ограничения и запустите синхронизацию вручную еще раз.
