# 用 AI Agent 部署

准备好应用源码和目标服务器的访问权限后，选择一个场景，把提示词中的 `<占位内容>` 换成自己的信息发送给 Agent。你不需要先写好部署命令或运行配置。Agent 负责检查环境、准备配置、构建和部署；无法自动确认的信息应向你询问，而不是猜测。

部署包不包含开发环境的数据库和上传文件。首次部署示例使用新数据；需要保留开发数据时，请明确告诉 Agent，需要另行迁移或恢复。

## 从哪里开始

| 你要做什么           | 在哪里开启 Agent 会话               | 对应示例                                                |
| -------------------- | ----------------------------------- | ------------------------------------------------------- |
| 在服务器运行单个应用 | 应用源码根目录，通过 SSH 操作服务器 | [用 app-installer 部署](#用-app-installer-部署到服务器) |
| 用 Docker 运行应用   | 应用源码根目录，通过 SSH 操作服务器 | [用 Docker 部署](#用-docker-部署)                       |

单个应用可优先选择 app-installer；已有容器运维环境时选择 Docker。不使用 Agent 时，按[手动部署：独立运行](./standalone)操作，不需要安装 Skill。

### 让 Agent 读到部署 Skill

应用通常在 `.agents/skills/` 中包含 `nocobase-deployment`。让 Agent 实际读取这些文件，不依赖工具是否自动发现它们。缺失时，先检查依赖和 Skill 同步状态；`pnpm nocobase skills sync` 可以同步已安装包提供的 Skill。

用 app-installer 安装应用时，在 Agent 运行的机器安装全局 Skill：

```bash
npx skills add https://github.com/nocobase/nocobase/tree/v3-develop/skills/nocobase-app-installer --skill nocobase-app-installer -g
```

安装后重新开启 Agent 会话。本机 Agent 通过 SSH 部署时，Skill 安装在本机；直接在服务器运行 Agent 时，安装在服务器。不要同时让两个会话操作同一个安装目录。

### 你需要准备的信息

- **服务器部署**：可用的 SSH 连接，例如已配置的别名 `crm-prod`；不要把 SSH 密码或私钥内容粘贴到对话。
- **访问地址**：域名、挂载路径、DNS 和 HTTPS 状态。
- **数据计划**：首次使用空数据库，还是保留已有数据库和上传文件。

凭据放入被 Git 忽略的文件或环境变量，只向 Agent 提供位置和变量名。SSH 不会自动把本机环境变量带到服务器；远端命令需要的变量应在远端环境准备。

## 提示词

每个首次部署示例都包含执行授权：Agent 先简要说明计划，再连续完成检查、配置、构建和部署。缺少必要信息、需要系统权限或发现目标已有数据时必须停下询问。更新与回滚使用后面的专用任务单。

### 用 app-installer 部署到服务器

在源码根目录开启会话，确保 Agent 可以通过 SSH 连接服务器。

```text
请通过 SSH 把当前 NocoBase 3 应用首次部署到服务器，用 app-installer 管理运行和后续升级。
SSH 目标：<例如 crm-prod>
安装目录：<例如 /srv/nocobase/crm，应该不存在或为空>
公网 origin：<例如 https://apps.example.com，不包含路径>
挂载路径：/crm；监听地址：127.0.0.1；端口：13000。
数据计划：新 SQLite 数据库，不复制开发数据库或上传文件。
域名和 HTTPS 状态：<实际情况>

读取项目部署 Skill 和全局 nocobase-app-installer Skill。先通过 SSH 检查 OS、CPU、libc、Node、全局 pm2、目录权限和端口，再说明计划。可以完成本地构建、传输、安装和启动；需要全局安装、sudo、修改 Nginx、非空目录、旧数据或外部数据库迁移时先停下。
按服务器实际平台构建归档，用 scp 传输并核对校验和，再用 JSON 模式安装。安装前告诉我如何安全填写初始管理员密码，不输出密码或完整配置，也不要失败后清空目录重装。
完成后检查本机健康接口和日志，报告版本、登录地址、持久目录、pm2 startup 步骤和反向代理配置。公网未打通时标记“本机运行正常，公网待配置”。
```

不能通过 SSH 时，本机 Agent 先按服务器平台构建并交付归档、SHA-256 和传输命令；复制到服务器后，在安装了全局 Skill 的服务器会话发送：

```text
请用 app-installer 安装已经准备好的 NocoBase 3 部署包，不构建源码。
归档：<服务器绝对路径>；预期 SHA-256：<构建时记录的校验和>。
安装目录：<目录>；公网 origin：<地址，或“暂未配置，只做本机验收”>。
挂载路径：/crm；端口：13000；数据计划：新的 SQLite 数据库。
读取 nocobase-app-installer Skill，核对归档、平台、依赖和目标目录，再完成安装和本机健康检查。目录非空或存在旧数据时停下；缺少凭据或权限时告诉我如何补齐。不要输出密码。最后报告安装结果和公网访问还需完成的步骤。
```

### 用 Docker 部署

在本机源码根目录开启会话。本机需要能构建镜像，服务器需要 Docker 和 Compose。以下使用 `docker save`、`scp`、`docker load` 传输镜像，无需先搭建镜像仓库。

```text
请把当前 NocoBase 3 应用用 Docker 首次部署到服务器，完成从构建到验收。
SSH 目标：<例如 crm-prod>
部署目录：<例如 /srv/nocobase/crm-docker，应该不存在或为空>
公网 origin：<例如 https://apps.example.com>；挂载路径：/crm；端口只绑定 127.0.0.1:13000。
数据计划：新 SQLite 数据库，不迁移开发数据。
域名和 HTTPS 状态：<实际情况>

读取项目部署 Skill，检查构建机和服务器的 Docker、Compose、CPU 架构、目录和端口。使用项目 Dockerfile 和 Dockerfile.dockerignore，按服务器架构构建唯一标签的镜像；不要把配置、密钥和数据打进镜像。
先说明计划，然后完成构建、docker save、scp、校验和核对、docker load 和 Compose 启动。基于镜像内的 config.example.yml 准备配置，生成并持久保存密钥，告诉我在哪里安全填写管理员密码。
创建 compose.yml，只读挂载 config.yml，持久挂载 storage，检查容器用户的写权限；执行 Compose 校验和镜像内的 config check 后再启动，不输出凭据。发现旧容器、非空目录、旧数据库或缺少权限时先询问，不重建数据卷。
最后检查容器健康、实际挂载路径健康接口和日志，报告镜像标识、登录地址和 HTTPS/反向代理待办。修改现有代理服务前等我确认；本机健康不等于公网可用。
```

## 更新与回滚

已有安装不能继续使用首次部署任务单。要先明确当前版本、配置和数据、备份如何恢复以及允许的停机窗口；Agent 应说明影响范围和估算依据。

### 更新 app-installer 安装的应用

在服务器会话发送；本机 Agent 操作时再补充 SSH 目标。新归档由源码侧构建并传输。

```text
请升级服务器上的 app-installer 应用。安装目录：<目录>；新归档：<路径>；SHA-256：<校验和>。
先读取 Skill 并运行 status，核对当前版本、归档平台、配置、备份范围和迁移风险。先运行不带 --yes 的预检，把停机和备份说明告诉我；我确认且外部数据库已备份后再执行。沿用密钥、数据库和 storage，完成后报告新旧版本、备份位置和验证结果；自动回滚时说明最终运行版本。
```

Docker 更新应指定新镜像标签或摘要，复用 Compose 配置和持久目录，确认备份及切换窗口并保留旧镜像。app-installer 回滚应先读取安装器确认说明，注意 SQLite 恢复可能丢失升级后的数据。不要把代码回滚当作数据库恢复，具体操作见[手动部署：独立运行](./standalone)。

## 验收

让 Agent 给出简短的部署报告，至少包含：

- 目标服务器、源码版本、归档校验和或镜像标识、最终运行版本。
- 配置与持久目录位置、迁移和初始化结果，不包含密钥内容。
- 健康检查地址及响应、正式访问地址、已完成的登录与业务检查。
- 更新时的旧版本、备份位置、回滚办法；未完成的检查、原因和具体下一步。

收到报告后，通过正式地址登录一次。首次部署可用约定的测试数据验证写入、上传及重启后的持久性；已有生产应用需先约定测试记录和重启窗口，不要为验收随意写业务数据、触发工作流或重启。Agent 无法操作浏览器时，这些检查由你完成并标为待验收。

“配置已生成”“请求已接受”“容器已启动”和“本机健康正常”都只是阶段结果；公网访问、业务验证或迁移结果未确认时，应明确保留待办。
