# 快速开始

:::warning 文档编写中
本章先整理文档结构与各页内容范围，完整操作说明和场景示例将继续补充。
:::

本页以采购申请为例：申请人提交，直属主管审批；主管可同意、驳回或退回修改。先做一个完整的小流程，再增加财务会签、加签和付款等规则。

## 开始之前

需要一个能够使用 Agent 开发的 NocoBase 应用，尚未创建时先看[创建应用](../../get-started/create-app.md)。Agent 先检查审批插件（`@nocobase/app-plugin-approval`）、应用内的插件 Skill、组织人员服务和流程存储，补齐接入所需的配置与迁移。

## 第一步：描述审批

```text
在当前应用中，使用审批插件（@nocobase/app-plugin-approval）做采购申请审批，先检查依赖和应用内的插件 Skill。

申请包含采购内容、金额和申请人。申请人提交自己的草稿后，由直属主管审批；申请人不能审批自己。主管可以同意、驳回或退回申请人修改，驳回和退回必须填写原因。驳回结束申请；退回后可修改并重新提交，重新提交由主管重新审批。不允许直接编辑审批中的采购内容和金额。没有合格主管时阻止提交并说明原因。

先不要写代码，给我完整流程图、审批环节表、各操作的权限和还缺少的业务决定。本次只完成审批，不做下单或付款。
```

## 第二步：确认流程与环节表

检查草稿、主管审批、退回修改、通过、驳回这些环节和出口；确认申请人、主管的身份来源，无人可审的处理方式，以及退回后从哪里恢复。撤回是否允许、谁可查看申请，也应在实现前明确。

## 第三步：实现单据与页面

```text
按确认的规则实现。把审批接到采购申请的完整流程上，完成迁移、接口、权限、测试和页面。申请人只能看到自己的申请，主管只能看到授权给自己的申请。本次不允许撤回。

提供申请列表、提交表单和详情页。详情页显示送审内容、审批进度、办理记录和当前可办操作。开发环境准备申请人、主管和无关用户三种测试身份，告诉我在哪里走一遍。
```

## 第四步：在页面上走一遍

| 情况                   | 应看到的结果                       |
| ---------------------- | ---------------------------------- |
| 提交后主管同意         | 申请结束为通过，记录主管和办理时间 |
| 主管驳回               | 申请结束为驳回，保留原因           |
| 主管退回后修改重提     | 原意见保留，新一轮主管任务重新生成 |
| 无关用户查看或办理     | 按已确认的权限拒绝                 |
| 审批中的申请被直接修改 | 拒绝修改送审字段                   |

## 第五步：验收

```text
请用测试证明：只有申请人能提交自己的申请；无合格主管时提交失败；只有被授权的主管能办理；驳回和退回必须给原因；退回修改后生成新任务，旧任务不能继续办理；审批中不能直接修改送审内容；重复请求不会重复办理；两个人并发办理不会覆盖；绕过页面调用接口同样受权限限制。运行受影响包的 lint、typecheck、test 和 build，并给出结果。
```
