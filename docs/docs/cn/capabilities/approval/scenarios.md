# 场景示例

:::warning 文档编写中
本章先整理文档结构与各页内容范围，完整操作说明和场景示例将继续补充。
:::

本页按业务组织场景，每个示例采用“业务规则 → 可改写的提示词 → 页面表现 → 验收重点”的结构。以下先确定场景范围和需要讲清楚的规则，后续逐个补充完整示例。

## 请假：主管链与条件审批

直属主管审批，超过规定天数增加上级审批，特定假别可免审；明确无主管、申请人回避、代理、退回重提。通过后登记到考勤系统，登记失败显示执行失败并允许重试。

## 采购与合同：会签、或签和职责席位

采购按金额进入不同路线；合同要求法务和财务各出一份意见，每个职责由团队中的一人办理。明确会签驳回策略、认领、转交、加签、退回目标及抄送。

### 多人怎样共同决定

| 业务说法     | 结果规则                                         |
| ------------ | ------------------------------------------------ |
| 单人审批     | 一名指定人员决定                                 |
| 会签         | 全部同意才通过；一人驳回立即结束或收齐意见后结束 |
| 或签         | 一人同意即通过，全部反对才驳回                   |
| 首个意见决定 | 首个同意或驳回就决定结果                         |
| 顺序审批     | 按顺序轮到每个人，反对则驳回                     |
| 指定票数通过 | 达到票数即可；可选弃权、一票否决和等待全员表态   |

## 报销：逐项核准与部分通过

按费用明细分配审核，记录核准金额、逐项退回与部分通过结果；决定已通过项目是否可以先付款。每项付款使用稳定的业务标识，防止重试重复支付。

## 付款：预算占用与执行失败

提交时占用预算，在各结束出口释放。批准后按计划付款；银行明确拒绝、暂时故障和结果未知分别处理。结果未知先核对，重试不重复审批，金额变化则重新送审。

## 合同变更：申请与生效数据

变更申请记录合同原版本，冻结拟修改内容；最后确认时检查原版本，再写入正式合同。版本已变时拒绝结论并回滚，基于当前版本重新申请；外部同步失败单独重试。

## 团队办理：认领、补充材料与管理员介入

候选人认领团队任务，超时释放；审批人可要求申请人补材料。没有合格人员时等待管理员补派，改派保留责任历史；催办、延长时限按业务需要扩展并限制权限。

## 并行部门与子流程

各部门独立办理、各有流程和结果时，使用子单据并由父单据汇总；同一环节多人共同决定一个结果时使用会签。页面展示每条分支和阻塞原因。

## 通知确认、后续工作与统一待办

抄送表示阅知，不投票。要求每个人确认后才生效的通知、入职清单、采购下单等工作，按各自业务流程建模。统一待办汇总审批任务与其他工作，各来源保留自己的权限和操作。
