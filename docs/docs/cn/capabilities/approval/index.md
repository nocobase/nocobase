# 审批概览

**审批用于组织业务申请的审核与决策，定义由谁审批、按什么顺序审批，以及满足什么条件才算通过。**它可以协调多个审批人的意见，支持加签、转交和退回，并保留每次决策与责任变化的记录。

## 提供哪些能力

| 能力                                      | 可以做什么                                                         |
| ----------------------------------------- | ------------------------------------------------------------------ |
| [多级与条件审批](./stages.md)             | 依次经过主管、财务等审批环节，按金额或类型决定路线。               |
| [会签、或签与通过规则](./joint-review.md) | 多人共同决策，按全部同意、任一人同意或指定票数等规则汇总结果。     |
| [加签与转交](./handover.md)               | 临时增加审批人，或将当前任务交给其他符合条件的人。                 |
| [申请处理与进度](./requests.md)           | 退回补充、撤回、重新提交、抄送阅知，以及查看进度、意见和处理记录。 |

本章用 Northstar 的特殊运输申请展示这些能力：申请人提交额外费用，主管和财务按规则决策，其他人员按需要参与。

## 页面如何呈现

审批页面可根据业务需要自由设计：可以直接放在订单、报销单等业务详情中，也可以集中呈现“我的申请”“待我审批”“已审批”和“抄送给我”。提交前可以展示预计路线，提交后展示当前审批人和处理进度。

## 接入审批能力

审批使用 Pro 插件 `@nocobase/app-plugin-approval`，需要相应授权和兼容版本。向 Agent 描述审批业务需求，即可按业务需要搭建申请页面、审批待办和详情页；连接凭据保留在服务端配置中。

简单的单人确认可以使用[工作流](../workflow/index.md)；需要多级流转、多人决策和任务管理时使用审批能力。

:::tip 重要提示

审批通过是决策结果，付款、预留资源或更新正式数据是后续执行。需要同时展示执行结果，并为失败安排重试或人工处理，避免把“已批准”当成“已经执行成功”。

:::

## 在示例中认识审批

安装 `@nocobase/app-plugin-approval` 与 `@nocobase/app-plugin-approval-example` 后，打开 **Approvals**。**To-do center** 汇总当前演示身份的待办、已办、发起和抄送；业务页面按请假、采购、合同、报销、付款等分类；**Approval lab** 展示场景、任务、记录和模拟服务。

![英文审批中心](https://static-docs.nocobase.com/images/capabilities/approval/inbox-8c49a6543c924c96.png)

顶部的身份选择器用于扮演申请人、主管、财务等示例人员，选择会在各业务页面间共享。它不是登录用户切换：示例允许已登录用户扮演这些身份并查看示例记录。生产应用必须从登录用户确定操作者，另行实现单据、任务、附件及管理操作的授权。

## 怎样调整审批规则

规则写在应用的代码里，不能在界面中拖拽修改。需要调整时，在本地让 Agent 修改并测试，再重新部署；同时明确正在审批的申请如何处理，保留它们仍需使用的环节和出口。

## 示例的范围

示例有真实的业务表、审批任务、操作历史与后台任务，但组织目录、消息、考勤登记、付款与外部事件是模拟服务。真实银行支付、第三方消息卡片、回调认证及组织同步需要接入相应服务。实验室的故障开关用于观察失败和恢复，不代表已经验证网络丢失响应或所有并发故障。

规则与页面均由代码定义；示例不是可拖拽配置的通用审批产品。固定五人委员会的比例投票、逐项报销和限额授权是具体业务实现，不能据此推断任意比例、任意事项都自动支持。
