# 概览

:::warning 文档编写中
本章先整理文档结构与各页内容范围，完整操作说明和场景示例将继续补充。

报销、请假、采购、用印、合同这类业务，核心是“谁来审、按什么顺序审、怎样算通过”。简单的提交、审批和驳回可以直接用[工作流](../workflow/index.md)完成；安装审批插件后，可以在一个环节中协调多人办理，并保留每个人的意见和责任记录。

审批跟随业务单据的完整流程：草稿、审批、退回修改、审批后执行和最终结束都在同一条流程中。一个环节的部分审批意见不会直接改变单据状态；满足该环节的汇总规则后，单据才进入下一环节。

## 审批插件提供什么

| 能力           | 要讲清楚的业务规则                                               |
| -------------- | ---------------------------------------------------------------- |
| 多级与条件审批 | 主管、财务等按顺序审批；金额或类型决定是否增加环节               |
| 多人共同决定   | 会签、或签、首个意见决定、顺序审批、达到指定票数通过             |
| 人员与职责     | 按主管链、角色或部门找人；团队认领；无人可审时拒绝进入或等待补派 |
| 办理操作       | 同意、驳回、退回、转交、前加签、后加签、并行加签、补充材料       |
| 抄送与阅知     | 抄送对象查看进度并确认已读，抄送不计入审批意见                   |
| 时限           | 自动提醒、到期升级、认领超时释放；可按工作日历计时               |
| 审批依据       | 保存送审内容、意见和责任变化；退回后是否沿用意见需明确规定       |

按比例通过时，需要先明确人数口径、比例和取整方式，再换算成通过票数。业务特有的逐项核准、部分通过、弃权或一票否决，见[场景示例](./scenarios.md)和[扩展](./extension.md)。

## 做好之后用户看到什么

- 提交前：业务表单和审批路线预览，说明预计由谁审批；实际进入环节时再确定人员。
- 申请人：我的申请、当前进度，以及规则允许的撤回、修改和重新提交。
- 审批人：待办、已办、送审内容、当前能做的操作及不能办理的原因。
- 抄送人：抄送给我的单据、审批记录和已读确认。
- 详情页：审批进度、意见汇总、办理记录，以及审批后的执行结果。
- 管理员：按业务授权补派、改派，处理执行失败；这些操作同样留下记录。

插件提供任务、规则和界面所需的数据；业务页面、接口和可见范围由 Agent 按应用需要接入。可以把审批放在已有单据详情里，也可以建设跨业务的审批中心。安装插件不会自动生成这些页面。

## 审批通过之后

“审批通过”和“执行成功”分别记录。例如付款已获批准，银行接口却失败，应显示执行失败并允许授权人员重试；付款内容不变时，无需重新走人工审批。通知和外部调用使用流程的提交后执行能力。

合同或价格变更等业务还要区分“变更申请”和“当前生效的数据”。审批结论应用到正式数据之前，需检查正式数据是否已经被别人修改，避免覆盖新版本。

## 怎样调整审批规则

规则写在应用的代码里，不能在界面中拖拽修改。需要调整时，在本地让 Agent 修改并测试，再重新部署；同时明确正在审批的申请如何处理，保留它们仍需使用的环节和出口。
