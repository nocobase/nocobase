# 申请处理与进度

审批可以覆盖提交、审核、退回补充、重新提交和结束的完整过程。申请人查看进度，审批人处理待办，抄送人查看资料与意见；不同人员拥有对应的操作入口。

## 退回、驳回与撤回

| 操作     | 对申请的影响                                       |
| -------- | -------------------------------------------------- |
| 退回     | 返回指定环节，允许按规则补充或修改，再重新提交。   |
| 驳回     | 结束当前申请，保留拒绝原因和意见。                 |
| 撤回     | 申请人在允许的阶段主动撤回，当前审批任务随之结束。 |
| 补充材料 | 审批人等待补充资料，申请人提交后继续原任务。       |

### 示例：资料不足时退回补充

```text
Northstar 特殊运输申请缺少必要资料时，允许主管填写原因并退回申请人补充。
申请人修改后重新提交，保留之前的意见；重新进入审批时再次确定处理人。
提交后、尚未结束时允许申请人撤回，审批人不能再处理已撤回的任务。
页面明确区分退回、驳回和撤回，并显示下一步由谁处理。
在申请详情用流程图展示退回补充、重新提交与驳回结束的处理路径。
```

在特殊运输申请详情查看「审批流程」，退回与驳回的处理路径与申请资料、审批进度显示在同一页面。

![申请详情内展示退回与驳回的审批流程](../assets/northstar-approval-return-flow-en.png)

**退回可以补充后继续，驳回结束当前申请，两者保留各自的原因和记录。**

## 抄送与阅知

需要让相关人员了解审批结果时，可以设置抄送和已读确认。抄送人查看进度、资料和意见，阅知不计入审批票数。

```text
将 Northstar 特殊运输申请抄送给负责客户经理。
提供「抄送给我」列表和已读确认，抄送人可查看进度及意见，但不参与审批决策。
```

## 时限与任务分配

审批可以按约定时限提醒、升级给负责人，也可以让团队成员认领任务。认领后超时未处理时，可以释放任务供其他人继续；需要时按工作日历计时。

```text
Northstar 主管审批超过一个工作日时提醒，超过两个工作日时升级给主管负责人。
团队待办允许符合岗位的人员认领，认领超时未处理时释放。
显示当前处理人、截止时间和任务分配记录。
```

![审批完成后保留主管与财务的处理意见](../assets/northstar-approval-completed-en.png)

**申请人可以查看最终结论、审批人及各环节意见。**

:::tip 重要提示

需明确哪些阶段允许撤回、退回到哪里，以及重新提交后是否沿用之前的意见。抄送阅知与审批决策分开；超时处理也应明确为提醒、升级或转交等动作。

:::

## 退回后的审批依据

重新提交时，保留历史不等于沿用原来的同意意见。默认重新审批；允许沿用时，明确哪些内容必须保持不变。补充材料可以在当前任务中等待回复，不必退回整张申请；过期页面和旧任务不能确认新内容。

## 审批后的执行与页面权限

批准、执行安排、执行成功与失败应分别显示。占用预算时，需明确驳回、撤回、终止和退回等出口如何释放；付款结果未知时先核对再重试，避免重复支付。抄送只阅知，不计入决策。

```text
Northstar 特殊运输申请重新送审后重新审批，保留原意见和修改记录，旧待办不能再办。申请人只看自己的申请，审批人和抄送人只看有权查看的内容；不能办理时说明原因，别人处理后可看到最新进度。
批准后通知申请人和客户经理，本次不自动支付。以后启用付款时，批准、付款安排和支付结果分开显示；只有有权人员可以重试，结果未查清前不能再次付款。先和我确认预算占用与各出口的释放规则。
```

## 验收、上线与排查

按申请人、审批人、抄送人和管理员核对可见范围、操作、金额路线、多人规则、退回重提、时限和执行结果。提醒按自然时间还是工作日历计时、节假日怎样处理、重新提交后是否重新计时，都应明确；重启后仍需按约定处理。

```text
请给我 Northstar 审批的试用步骤和逐条验证结果：各金额路线、会签、退回修改、加签和转交符合约定；旧任务和过期页面不能继续审批，无关人员不能查看或办理；重复点击和同时操作不会重复审批或付款。说明还没验证的地方，以及上线前人员、权限和通知需要我确认的事项。
调整规则前列出仍在审批的申请，让我确认按原规则继续还是重新送审，说明原任务、意见和期限怎样处理。申请卡住时先查看当前环节、等待谁、任务、历史及执行结果，再由有权人员处理并留下记录。
```

反馈问题时提供申请、自己的身份、操作、预期结果和实际结果；页面错误可以原样交给 Agent，不需要猜测缺少什么包。接入与自定义规则的技术边界见[开发参考](./extension.md)。
