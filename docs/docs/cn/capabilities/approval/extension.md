# 扩展

:::warning 文档编写中
本章先整理文档结构与各页内容范围，完整操作说明和场景示例将继续补充。

本页面向需要了解接入和扩展边界的开发者与 Agent。业务设计先看[使用 Agent 开发](./develop.md)，接口细节以应用内审批插件 Skill 和已安装版本为准。

## 接入已有单据与业务流程

一张申请记录标识完整流程；`defineApproval` 定义草稿、审批、修改、执行及最终环节，`approvalState` 为业务环节附加多人办理规则。每次进入审批环节创建本轮任务，退回重进创建新任务并保留旧记录。

应用提供流程运行时、业务表、流程存储、组织服务、鉴权接口与界面，插件迁移提供审批任务和记录存储。接入时收口直接改状态和送审字段的表单、导入及接口。变更已有合同等业务，应独立保存申请和正式数据。

## 自定义汇总策略

标准策略覆盖单人、会签、或签、首个意见、顺序和票数汇总。特殊逐项审核或部分通过使用 `StagePolicy`：声明任务安排、可产生的结果和结果出口；策略负责计算结论，数据写入由业务流程执行。

## 自定义操作与人员规则

通过 `defineApprovalAction` 增加弃权、逐项退回、催办等业务操作，并在需要的环节显式注册。声明输入、权限、候选人范围、界面呈现与记录文案，补齐表单及测试。转交、加签、补派和改派后重新检查职责规则。

## 冻结内容、审批输出与意见沿用

`freeze` 定义送审字段，确认时携带页面展示内容的哈希。审批人填写的核准金额、日期等使用环节输出声明，结论产生时再与单据状态一起写入。

默认重新进入环节要重新审批。`reuse: 'unchanged'` 仅在明确授权且所覆盖内容、规则版本和责任身份等条件满足时沿用旧意见，新任务保留来源证据。

## 页面与审批中心

| 契约                                | 用途                           |
| ----------------------------------- | ------------------------------ |
| `previewRoute`                      | 提交前路线预览                 |
| `runViewsFor` / `upcomingStagesFor` | 当前与历史审批轮次、后续环节   |
| `actionsFor` / `runActionsFor`      | 当前用户可做的任务或本轮操作   |
| `candidatesFor`                     | 转交、加签等操作的合格候选人   |
| `perform` / `performBatch`          | 办理与逐项返回结果的批量办理   |
| `tasksOf`                           | 汇总审批任务；接口仍需业务鉴权 |

UI Library 的 `approval-ui` 提供进度、时间线、路线预览、操作栏、分支和阅知展示组件；Agent 将服务端数据映射到组件，业务表单与页面由应用实现。审批中心可汇总其他工作来源，每个来源独立校验权限与执行操作。

## 通知、时限与可靠执行

任务提醒、到期升级和认领超时由应用定期调用 `ApprovalService.sweep()`；`calendar` 可提供工作日历。将检查接入流程后台任务，通知与外部调用在事务提交后执行。部分意见只更新审批任务；最终结论、业务状态和下一环节任务在同一事务内处理。

资源占用与释放、正式数据版本检查放在业务事务中；外部付款、登记、同步使用流程的可靠执行能力，设置重试、失败出口和稳定业务标识。

## 规则版本、升级与测试

升级应用迁移，显式管理规则版本，保留正在使用的环节与出口。测试覆盖自定义策略、操作权限、结论事务回滚、意见沿用、重复请求、并发和时限；外部执行覆盖成功、明确失败、暂时故障及结果未知。
