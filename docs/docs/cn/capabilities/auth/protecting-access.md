# 保护页面和接口

[← 认证概览](./index.mdx) · [查看页面与接口场景](./index.mdx#protect)

Northstar 可以向访客开放运输服务介绍，同时将客户资料、运输订单和内部工作台保留给员工。认证决定访问者是否已登录，权限决定登录后可以访问什么。

> 本页的 /main/services、/main/orders 和 /main/api/northstar 均为 Northstar 示例路径。请让 Agent 根据当前应用的实际页面、接口和基础路径完成接入。

## 公开介绍与内部业务

应用可以同时包含公开页面和内部业务。面向访客的内容无需登录；客户资料、内部记录等受保护内容要求先登录，再按权限访问。

```text
为 Northstar 增加公开的运输服务介绍页，访客无需注册或登录。
页面采用 Northstar 的蓝色品牌风格，介绍长三角服务网络、区域运输、企业配送和运输过程协同。
展示联系邮箱，并提供“员工订单”入口；员工登录后也可以浏览公开介绍。
用于读取公开介绍的接口允许访客读取，不能返回内部订单或客户资料。
运输工作台、客户页面、订单页面及其数据接口继续要求登录并检查业务权限。
未登录访问内部页面时进入登录页。
```

### 不登录浏览公司介绍

打开公开页面 `/main/services`，访客可以直接看到 Northstar 的运输服务介绍，包括上海、杭州、苏州的服务网络，以及区域运输、企业配送、运输过程协同三个业务板块。页面不要求先注册或登录，也不展示内部客户和订单。

![访客无需登录即可浏览Northstar运输服务介绍](../assets/northstar-public-services-en.png)

这张页面由上面的业务提示词搭建，品牌、版式和服务内容都可以按公司的需要调整。

### 进入内部订单时要求登录

在介绍页点击 **Open employee orders**，进入内部订单地址 `/main/orders`。未登录的访客会跳转到登录页，完成登录后再按岗位权限使用订单系统。

直接在浏览器输入内部订单地址，也会先进入登录页。知道地址不会自动获得内部业务访问权。

![未登录访问内部订单地址后进入登录页](../assets/northstar-internal-orders-login-en.png)

可以用下面两个地址对照查看本例：

| 地址                                   | 未登录时的结果             |
| -------------------------------------- | -------------------------- |
| `http://localhost:13200/main/services` | 直接显示公开的运输服务介绍 |
| `http://localhost:13200/main/orders`   | 跳转到应用登录页           |

### 公开页面与接口分别保护

公开介绍页从独立的 `GET /main/api/public/company` 接口读取公司名称、服务区域、服务条目和联系邮箱。访客调用该接口可以取得公开数据，接口不会查询或返回内部客户、员工和订单。

内部业务接口继续要求认证。本例未登录调用 `GET /main/api/northstar`，返回 **401**，不会返回订单数据。网页访问内部页面时跳转登录；脚本调用内部接口时收到认证错误，需要先提供有效身份。

页面和接口分别声明访问要求。只隐藏导航或在浏览器中判断登录状态，不能代替服务端保护。

## 使用当前员工身份

业务记录需要追踪实际操作人时，可以直接使用当前登录身份。由服务端记录操作者，避免用户手工填写错误或冒用他人身份。

```text
创建运输订单时，由服务端从当前登录状态取得操作人并记录到订单。
员工无需填写操作人，也不能通过提交另一个人的编号冒用身份。
订单负责人可以按业务规则另行分配，不要把负责人和创建人混为一谈。
```

订单负责人、创建人、被分配的司机是不同业务字段。认证提供可信的当前用户身份；具体字段与访问范围由业务规则决定。

## 页面与接口的区别

| 场景                   | 页面行为           | 接口要求                         |
| ---------------------- | ------------------ | -------------------------------- |
| 运输服务介绍           | 访客与员工都能浏览 | 只返回公开内容，可使用可选身份   |
| 员工工作台、客户和订单 | 未登录先进入登录页 | 必须认证，再检查业务权限         |
| 登录与密码恢复页       | 面向未登录用户     | 使用相应认证流程                 |
| 脚本读取订单           | 不需要浏览器页面   | 使用 API key，并遵守所属用户权限 |

需要登录的接口在缺少身份时返回 401；已登录但缺少权限时返回 403。API key 是接口认证方式，不能绕过业务授权。

## 账号停用与部署

离职或暂停访问时，管理员禁用账号并撤销会话。与人事系统联动时，对执行账号停用的调用方同样需要认证与授权。

部署负责人需要维护应用密钥、用户实际访问的公开地址和路径、Cookie，以及多实例需要的共享存储。身份平台回调和重置邮件链接应与实际访问地址一致。应用经反向代理访问时，也要正确转发协议、Host 和 Cookie。

通过 Agent 开发时，可以直接提出上述访问需求，由 Agent 结合应用的认证和授权能力完成页面与接口接入。

## 完成后如何检查

- 用未登录浏览器打开公开介绍与内部页面，确认两者行为不同。
- 绕过页面直接请求接口：公开接口只返回公开数据，内部接口拒绝未认证请求。
- 使用有权限和无权限的账号分别请求业务接口，验证登录身份不能替代业务授权。
- 提交其他人的操作人编号，确认服务端仍使用可信的当前用户身份。
