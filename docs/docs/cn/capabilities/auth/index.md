# 认证

认证用于确认当前访问应用的用户或程序身份。NocoBase 提供账号登录、会话和 API keys 等能力，应用可以复用这些功能，也可以接入企业账号或第三方登录，减少账号体系的重复开发。

## 提供什么能力

| 能力                                         | 可以完成什么                                   | 使用方式                                                       |
| -------------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------- |
| [密码认证](./methods/password)               | 使用用户名或邮箱登录，注册账号、找回和重置密码 | 默认模板提供登录及相关页面；密码找回和邮箱验证需要接入发件服务 |
| [API keys](./methods/api-keys)               | 让脚本或外部系统以用户身份调用应用接口         | 在设置中创建和管理 Key                                         |
| [增加认证方式](./custom/sign-in-methods)     | 使用 GitHub、企业身份平台等已有账号登录        | 根据身份平台接入登录流程                                       |
| [定制登录页面](./custom/login-pages)         | 调整品牌、文案和登录入口布局                   | 让开发 Agent 修改应用的登录页面                                |
| [保护接口和页面](./advanced/protecting-apis) | 为自定义业务声明登录要求，读取当前用户身份     | 在业务页面和服务端接口中接入认证                               |

用户登录后，应用通过会话识别当前用户；退出后结束当前会话。账号禁用和会话撤销也由认证能力处理。

认证说明“你是谁”，[权限](../authorization)决定“你能做什么”。例如，登录采购系统使用认证，限制采购员只能处理本人订单则由权限规则决定。

第三方登录、企业登录和无密码登录通过底层 Better Auth 的扩展机制接入，并非默认模板中已经启用的登录入口。按你的业务选择需要的方式即可。
