# 数据范围与规则

数据范围决定一项操作能访问哪些记录。两个员工都可以查看订单，但客户经理只查看本人负责的订单，司机只查看分配给自己的任务。

## 示例：负责人与司机使用不同范围

同一页面中的记录可以按负责人、任务分配或其他业务条件划分。用户拥有相同的操作权限，也可以只查看和处理与自己职责相关的数据。

```text
客户经理查看和编辑本人负责的订单，以订单负责人字段关联当前用户。
司机查看和办理分配给自己的任务，以分配司机对应的员工账号判断范围。
调度员可以查看需要统筹的全部订单，分配司机仍按订单当前状态执行。
在「团队访问」中分别提供各操作的范围选项，并在列表、详情、修改接口中执行同一规则。
```

「本人」需要说明对应哪个业务字段。负责人、创建人和司机可能是不同的人，不能一律用创建人判断所有岗位的范围。

## 可以怎样划分

| 范围       | 运输业务中的用途                             |
| ---------- | -------------------------------------------- |
| 本人负责   | 客户经理跟进自己负责的订单                   |
| 分配给本人 | 司机办理自己的运输任务                       |
| 全部记录   | 调度员统筹运输业务                           |
| 业务条件   | 查看待调度订单、某区域订单或金额范围内的申请 |
| 团队或部门 | 已接入组织关系时按团队职责访问               |

查看、编辑、分配司机、审批分别定义操作与范围。列表只能返回有权查看的记录；打开详情或提交动作时，服务端也需要检查，不能只靠列表筛选。

## 与其他规则配合

[默认数据范围](./default-access.md)加入共同可查记录，[共享规则](./sharing-rules.md)增加指定协作记录，[限制规则](./restriction-rules.md)收窄最终范围。它们不替代页面和业务操作权限。

## 查看不同岗位的订单

先只应用岗位范围。Alice 的订单列表有 6 笔本人负责的订单；Emma 的调度岗位可查看全部 10 笔订单。两人使用同一个订单页面，返回的数据由服务端按各自授权决定。

![Alice 查看本人负责的六笔订单](../assets/northstar-alice-orders-en.png)

**只应用岗位范围时，Alice 可见本人负责的 6 笔订单。**

![Emma 查看全部十笔订单](../assets/northstar-dispatch-orders-en.png)

**调度岗位的 Emma 可见全部 10 笔订单。**

以上是加入共同范围、共享与限制之前的结果。后续规则会进一步改变可见订单，原负责人字段仍保持不变。
