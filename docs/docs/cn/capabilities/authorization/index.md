# 权限

权限用于决定用户能进入哪些页面、执行哪些操作，以及查看或处理哪些数据。例如，采购申请人查看本人订单，审批人处理待审批订单，应用管理员维护岗位权限和人员分配。应用可以复用这些能力，按自己的业务划分职责。

## 提供什么能力

| 能力                              | 用途                                                   |
| --------------------------------- | ------------------------------------------------------ |
| [权限集与分配](./permission-sets) | 将页面、业务操作和数据范围组合为岗位职责，再分配给用户 |
| [数据范围与规则](./data-scopes)   | 为每项操作选择可访问的记录，例如本人申请的订单         |
| [默认数据范围](./default-access)  | 让已有操作权限的用户共同访问一部分记录                 |
| [共享规则](./sharing-rules)       | 让指定协作人员访问额外记录                             |
| [限制规则](./restriction-rules)   | 进一步限定可访问的数据范围                             |
| [权限检查器](./inspector)         | 查看用户的权限结果和来源                               |

[认证](../auth)确认用户身份，权限决定这个用户可以做什么。订单页面需要登录属于认证；采购申请人只能查看本人订单属于权限。

## 接入与管理

开发 Agent 将应用的页面、业务操作和数据范围接入权限能力。例如，为订单提供「查看订单」「处理审批」操作和「本人申请」范围。管理员随后在「设置 → 权限」中配置权限集、分配人员和调整规则。

默认应用模板已接入权限集、权限检查器及三种数据规则。各页以采购订单为例，介绍如何描述业务需求、在设置中管理，以及查看实际效果。业务提示词可以按自己的应用改写。
