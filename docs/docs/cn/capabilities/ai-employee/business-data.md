# 查询业务数据

AI 员工可以把自然语言问题转成允许的业务查询，整理记录并提供页面入口。接入真实业务读取操作后，回答可以使用当前数据，而不只给出一般性建议。

## 示例：查询待调度订单

```text
为 Northstar 的运输助理接入订单查询。
员工可以询问哪些订单待调度，并按客户、阶段或线路查询。
查询沿用当前用户的数据权限，显示订单号、客户、线路和负责人。
把每笔结果显示为可打开的订单卡片；没有结果时说明当前范围内没有符合条件的订单。
用户追问某一笔订单时，继续使用这笔订单的上下文。
```

## 查看效果

在订单列表打开运输助理，询问：

```text
有哪些订单还在等待调度？列出客户和运输线路。
```

结果卡片将订单号、客户、线路和负责人放在一起。示例中的 **NS-2026-001、NS-2026-002、NS-2026-007** 均处于待调度，员工可以选择其中一笔进入详情。

![运输助理以订单卡片展示待调度查询结果](../assets/northstar-ai-order-query-en.png)

**业务查询结果与订单页面连接，用户可以从对话继续处理对应记录。**

## 从查询扩展到业务操作

需要处理记录时，可以继续向开发 Agent 说明要接入的动作，例如分配司机、创建跟进记录或准备通知。同时明确所需输入、人员权限、是否需要确认，以及完成后在哪里查看结果。

查询、建议和写入是不同的操作。只提供下一步建议时不修改记录；接入写入后，页面应展示实际操作结果与处理记录。
