# 邮件

在 NocoBase 中，**邮件插件（Mail）**让每位用户关联自己的邮箱，在业务应用里阅读、整理、回复和发送邮件。你可以先搭建一个邮件中心，也可以让 Agent 把邮件放进客户、项目等业务页面，让处理邮件和跟进业务记录在同一个地方完成。

Mail 是 NocoBase Pro 插件。使用前先确认当前应用已安装并启用 Mail；邮件插件缺失时，让 Agent 检查当前 Pro 环境是否提供该插件，再继续接入。

如果你要发送审批结果、验证码或系统提醒，请使用[通知](../notification.md)的邮件渠道。Mail 用于用户关联的邮箱；通知邮件由应用发出，两者的配置和记录分开管理。

## 能做什么

- 一个用户可以关联多个邮箱，在同一个工作区切换账户、文件夹并查找邮件
- 阅读邮件会话和附件，标记已读、星标，添加应用内标签、备注和待办
- 写信、回复和转发邮件，使用附件、签名、模板、草稿和定时发送
- 让 Agent 按你定义的规则，把往来邮件接入客户、联系人、项目等业务页面

## 适合什么场景

Mail 适合销售、客服、项目团队在 NocoBase 中处理真实邮箱往来。比如销售可以在客户详情里查看与联系人的邮件、直接回复，并在模板中填入客户和联系人信息。

邮箱和业务记录之间的关系由应用需求决定。Mail 不会自动猜测某封邮件属于哪个客户；你需要告诉 Agent 按联系人邮箱匹配，还是让用户手动选择客户。

## 使用前需要知道

| 邮箱接入方式         | 适合的情况                                             | 需要留意                                                                                             |
| -------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| Gmail、Microsoft 365 | 服务商支持 OAuth，希望同步草稿、发件别名或启用推送同步 | 需要有权限创建或配置 OAuth 应用                                                                      |
| IMAP/SMTP            | 邮箱服务提供标准 IMAP 和 SMTP 接入                     | 主要同步新邮件，不完整同步其他客户端的已读、删除和移动；不支持服务商草稿、发件别名、推送和移动文件夹 |

Mail 的服务商设置由应用搭建者配置，用户再在邮件页面关联自己的邮箱。第一次接入不需要手动填写大量 YAML 或了解插件 API；先看[快速开始](./quick-start.md)，让 Agent 检查当前应用并引导你完成必要设置。
