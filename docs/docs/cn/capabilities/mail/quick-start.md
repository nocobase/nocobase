# 快速开始

本指南以销售人员在客户详情中查看和回复往来邮件为例，说明接入前要准备什么、如何向 Agent 描述需求，以及完成后如何确认效果。

## 开始前准备

- 确认当前应用已安装并启用 NocoBase Pro 的 Mail 插件；如果没有，先让 Agent 检查当前 Pro 环境是否提供 Mail，不要用自建邮件页面代替插件。
- 确认要接入的邮箱类型。Gmail 和 Microsoft 365 通常需要管理员准备 OAuth 应用；其他邮箱可使用 IMAP/SMTP，具体以邮箱服务商支持情况为准。
- 确认客户联系人资料中保存了可用于匹配的邮箱地址，并准备一个可用于测试的邮箱账户。

服务商凭据通常由应用管理员在部署配置中维护，具体入口以当前安装版本为准；用户在应用的 Mail 账户页面关联自己的邮箱。不要把密码、授权码或 OAuth 密钥粘贴到对话中。准备细节见[准备邮箱接入](./configuration.md)。

## 示例：在客户详情中处理邮件

把下面的提示词交给应用 Agent，并按实际情况补充联系人字段名和目标页面：

```text
请基于当前 NocoBase 3 应用，在客户详情页加入邮件区，让销售人员查看和处理与该客户有关的邮件。

开始前先检查当前应用是否已安装并启用 Mail Pro 插件，并阅读当前安装版本随附的 Mail Skill。若插件不可用，请说明需要安装或启用什么，不要从头自建邮件收发功能。

业务规则：
- 仅展示发件人或收件人邮箱与当前客户联系人邮箱匹配的邮件。
- 只使用当前用户已关联且有权访问的邮箱；不要让普通销售人员看到其他用户的邮箱或邮件。
- 支持在客户详情中阅读邮件、查看附件和回复邮件。
- 写信时允许选择该客户的联系人作为收件人，并可在主题或正文模板中使用客户名称、联系人姓名。
- 如果联系人没有邮箱、邮箱重复或一封邮件匹配多个客户，请明确提示并避免错误关联。

请先检查现有客户、联系人字段和权限，再实现页面。告诉我需要管理员在哪配置邮箱服务商、普通用户从哪里关联自己的邮箱；不要假设这些设置一定在 Settings 页面。需要 OAuth 或服务器信息时，列出由谁提供以及应在哪里安全填写，不要要求我把密钥发在对话里。

完成后请给出页面入口、权限说明和验证结果，并确认：匹配邮件能显示、不匹配邮件不会显示、普通用户不能访问他人的邮箱、写信收件人和客户信息正确、测试邮件可以正常发送和回复。
```

## 预期效果

销售人员打开客户详情后，可以看到与该客户联系人邮箱匹配的往来邮件，在同一页面阅读、查看附件和回复；新建邮件时可以选择联系人并带入客户信息。每位销售人员仍只会看到自己有权访问的邮箱内容。

## 验收结果

- 使用一个已关联的测试邮箱，确认来自或发给客户联系人的邮件出现在客户详情中。
- 确认与该客户无关的邮件不会出现在页面中；没有邮箱的联系人不会被错误匹配。
- 使用另一个普通用户账户检查，确认不能查看第一个用户的邮箱和邮件。
- 发送一封测试邮件并回复一封来信，在收件邮箱中检查实际内容和附件。

如果还没有完成服务商接入，先看[准备邮箱接入](./configuration.md)；想扩展签名、模板和其他业务页面时，继续看[进一步使用](./usage.md)。
