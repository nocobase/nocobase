# 进一步使用

完成[快速开始](./quick-start.md)后，可以继续告诉 Agent 邮件要怎样配合你的业务。描述谁在什么页面处理什么邮件、邮件如何与业务记录匹配，以及哪些人可以访问；实现方式交给 Agent 按当前 Mail 插件版本处理。

## 在订单页发邮件

适合需要根据订单状态联系客户、但希望员工发送前检查内容的场景。把字段名替换成应用中的实际字段：

```text
请在订单详情页加入“联系客户”邮件操作。收件人从当前订单关联的客户联系人中选择，主题和正文可以使用订单编号、客户名称和订单状态。发送前展示完整预览，让员工确认收件人、主题和正文后再发送，不要在订单状态变化时自动向客户发信。记录发送结果，并保证员工只能使用自己有权访问的邮箱。请检查当前 Mail Skill 和订单字段后再实现；如果模板变量或发送记录有任何版本限制，先告诉我。
```

**预期效果：**员工从订单页发起邮件时，收件人和订单信息来自当前记录；正式发送前能检查预览，发送后能查看结果。

## 设置团队签名和模板

适合复用统一的公司介绍、客服说明或常用回复。不要让 Agent 把模板内容硬编码到页面里；应明确哪些内容由管理员维护、哪些内容允许个人修改。

```text
请为销售团队配置可复用的邮件签名和模板。销售人员可以使用公司统一维护的模板，并保留自己的姓名、职位和联系方式；发送前可以检查最终内容。请基于当前 Mail 插件实际支持的管理方式实现，并告诉我由谁在哪里维护模板，以及员工从哪里选择模板。不要把密钥或客户隐私数据放进模板。
```

**预期效果：**员工选择模板后，主题和正文按模板填入，个人信息和当前业务记录中的字段正确显示；发送前仍可编辑和检查。

## 设计团队可见范围

适合需要主管查看团队处理进度的场景。先明确“查看进度”是否意味着查看邮件内容；这两种权限不应默认等同。

```text
请为销售团队增加邮件处理权限：销售人员只能访问自己关联邮箱中的邮件；主管可以查看团队的处理状态和发送结果，但除非我明确批准，不要让主管读取邮件正文或附件。先检查 Mail 插件和应用权限是否能区分这些范围，再列出权限设计让我确认，确认后再实现。不要仅通过隐藏页面或按钮限制访问。
```

**预期效果：**普通销售人员只能处理自己的邮箱；主管只获得已确认的管理范围。若当前版本不能安全地区分处理状态与邮件内容，Agent 应指出限制，而不是扩大主管权限。

## 日常使用时留意

- 首次关联邮箱时选择合适的同步起始日期；历史邮件越多，首次导入通常越久。
- 刷新页面只会重新显示已经同步到应用的内容。需要获取新邮件时使用应用提供的同步操作。
- IMAP/SMTP 主要同步新邮件，不保证同步其他客户端中的已读、删除和移动操作；服务商草稿、发件别名、推送同步和移动到服务商文件夹也不可用。
- 发送记录显示结果不确定时，先确认收件邮箱和原发送记录，再决定是否重试，避免重复发送。
- 如果需求是审批结果、验证码或系统提醒，而不是通过用户个人邮箱往来，请使用[通知能力](../notification.md)。

需要定制 Mail 页面、权限或服务商扩展时，见[高级定制](./development.md)。
