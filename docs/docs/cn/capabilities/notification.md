# 通知

通知能力用于在业务事件发生时，向指定人员发送消息。应用可以通过站内信、邮件或群机器人传递处理结果和提醒，消息也可以包含业务记录的链接。

例如，订单审批完成后通知申请人，任务分配后提醒执行者，或在资质即将到期时提醒负责人。

## 提供什么能力

| 通知方式         | 适合的场景                             | 需要准备                                  |
| ---------------- | -------------------------------------- | ----------------------------------------- |
| 站内信           | 向应用用户发送审批结果、任务提醒等消息 | 应用用户和启用的站内信渠道                |
| 邮件             | 向邮箱发送业务结果或提醒               | SMTP 或 Resend 发件服务、发件人和收件地址 |
| 飞书、钉钉群消息 | 向指定群发送团队提醒                   | 群机器人及其 Webhook 配置                 |

通知负责消息投递，何时发送、发给谁、消息写什么，由应用的业务规则决定。接入多个渠道时，需要分别说明各渠道的收件人和发送条件。

这里的邮件是应用发出的业务通知。关联个人邮箱、阅读往来邮件和回复客户，请看[邮件](./mail)。

## 接入前准备

用户邀请邮件也通过通知渠道发送。Users 插件默认使用 `system-email`；需要在 `notification.channels.system-email` 中配置并启用 SMTP 等邮件服务。模板的 `config.example.yml` 提供了 SMTP 配置示例。未配置可用渠道时，创建邀请仍会成功，但结果会包含「邮件未发送：未配置邮件渠道」和邀请链接，供管理员手动转发。

下面的示例使用站内信，不需要邮箱服务或群机器人。开始前需要：

- **一个已启动的 NocoBase 应用**：开发 Agent 能读取和修改应用源码。还没有应用时，先按[用 Coding Agent 创建应用](../get-started/create-app-with-agent)完成创建。
- **申请人和审批人的账号**：申请人用于接收消息，审批人用于处理订单。可以使用已有业务账号，也可以让 Agent 创建示例账号。

你需要告诉 Agent 的是：什么事件触发通知、通知发给谁、消息包含什么，以及点击后去哪里。业务触发和消息链接由 Agent 接入应用；管理员可在设置中查看通知日志。

## 完整示例：订单审批结果通知

在订单审批业务中，申请人提交订单，审批人通过或驳回。希望审批完成后，申请人能收到一条站内信，并从消息打开对应订单。

将下面的需求交给开发 Agent。已有订单功能时，复用现有数据和页面；没有时，让 Agent 一并建立。

```text
我要在当前应用中做订单审批，并用站内信通知申请人审批结果。

订单包含编号、名称、申请人、金额和审批状态。
申请人可以查看自己的订单，审批人可以查看待审批订单并通过或驳回。
如果已有订单和审批功能，请直接复用。

审批完成后，只给该订单的申请人发送一条站内信。
消息标题说明通过或驳回，正文包含订单编号、名称和审批结果。
点击消息可以打开对应订单详情。
待审批时不发送，同一次审批结果只通知一次。

申请人在收件箱查看消息，管理员可以在通知日志中查看投递记录。
通知发送失败不影响已保存的审批结果。
```

### 完成接入并审批订单

Agent 完成后，应用应提供订单列表、审批操作，以及从通知打开订单的入口。收件箱和通知日志复用应用已有功能。

用审批人账号打开订单列表（Orders），进入一张待审批订单的详情，点击通过（Approve）。也可以打开另一张订单，点击驳回（Reject）并确认。

下面展示这两种结果：申请人 Alice 的订单 `PO-2026-001` 已通过，`PO-2026-002` 已驳回。

### 结果演示

**第一步：进入通知中心，查看审批结果。**

换回申请人 Alice 的账号，点击右上角带有未读数量的收件箱图标，进入通知中心（Inbox）。这里可以看到 `Order approved` 和 `Order rejected` 两条消息，正文包含订单编号、名称和审批结果。

![点击右上角收件箱图标进入通知中心，查看审批消息](./assets/notification/inbox-open-center.svg)

**第二步：点击消息，查看对应订单详情。**

在左侧选中 `Order rejected` 消息，再点击右侧的消息标题链接。

![点击通知中心右侧的 Order rejected 标题链接](./assets/notification/inbox-open-order.svg)

应用会打开这条消息对应的订单 `PO-2026-002`，详情中的状态为 `Rejected`（已驳回）。这是从通知进入对应业务记录的过程。

![从驳回通知打开对应订单详情，查看已驳回状态](./assets/notification/inbox-rejected-order-detail.png)

消息会保留在收件箱中，刷新页面后仍可查看。本例的收件人是订单申请人；其他业务也可以按同样的方式通知任务执行者或负责人。

## 查看通知日志

通知能力自带「通知日志」设置页面，用于查看应用发送的通知及其投递状态。有相应权限的管理员可以从「设置 → 通知 → 通知日志」进入。这个页面会记录不同业务发出的通知，本例中的两次订单审批分别产生一条记录，状态均为 `completed`。

![英文通知日志中显示两次订单审批通知的投递记录](./assets/notification/notification-logs.png)

「通知日志」页面右上角的「发送测试通知」（Send test notification）也是通知能力提供的功能。管理员可以选择已配置的渠道和收件人，直接发送一条消息，确认渠道能否投递，无需先审批订单。

如果申请人没有收到审批消息，先在这个页面查找对应记录：没有记录时，让 Agent 检查业务是否触发了通知；有失败记录时，再检查渠道配置和收件人。

## 进一步使用：邮件和群通知

邮件和群通知需要先接入外部服务，由负责应用开发或部署的人完成渠道配置。

| 通知方式         | 由谁提供什么                                                                   | 在应用中怎样配置                                                          |
| ---------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| SMTP 邮件        | 邮箱服务负责人提供 SMTP 服务器地址、端口、发件账号、密码或授权码，以及发件地址 | 开发或部署人员在 `config.yml` 的 `notification.channels` 中配置 SMTP 渠道 |
| Resend 邮件      | Resend 账号负责人提供 API Key 和可用的发件地址                                 | 开发或部署人员在同一配置位置添加 Resend 渠道                              |
| 飞书、钉钉群消息 | 有权限管理目标群的人添加群机器人，取得 Webhook 地址                            | 开发或部署人员在同一配置位置添加对应群机器人渠道                          |

可以让开发 Agent 根据所选服务准备配置项；密码、授权码、API Key 和 Webhook 地址由负责配置的人在应用运行环境中填写。「通知日志」页面用于查看投递记录和发送测试消息。

渠道配置完成后，再将业务要求交给 Agent。例如，在现有站内信之外增加邮件通知：

```text
请在现有订单审批通知中增加邮件，使用应用已配置的邮件渠道。

订单审批通过或驳回后，向申请人账号中的邮箱发送审批结果。
主题包含订单编号，正文包含订单名称和审批结果。
保留已有站内信；申请人未填写邮箱时，只发送站内信。
邮件发送失败不影响审批结果和站内信，管理员可在通知日志中查看投递记录。
```
