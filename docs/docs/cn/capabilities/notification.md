# 通知

通知可以把审批结果、任务变化和业务提醒发送给应用用户或外部渠道。让应用 Agent 接入时，你主要需要说明什么时候发送、发给谁、消息包含什么，以及点击后要打开哪里。

通知邮件由应用发出，适合业务提醒。如果员工要关联个人邮箱、阅读往来邮件或回复客户，请使用[邮件能力](./mail/index.md)。

## 能做什么

- 用站内信通知应用用户
- 用邮件通知客户或申请人
- 用飞书、钉钉机器人向团队群发送提醒
- 扩展自定义 Provider，接入短信或其他尚未内置的通知服务

通知不会自动判断触发条件、收件人和业务数据权限，也不会在一个渠道失败后自动切换到另一个渠道。这些规则需要在需求中说明。

## 接入前要准备什么

应用默认模板已注册通知能力并配置站内信渠道。使用自定义应用时，让 Agent 先检查当前已安装的插件和渠道。

站内信可直接用于应用用户。邮件和群消息需要管理员准备发件服务或机器人 Webhook，并在服务端的 `config.yml` 中安全配置；凭据不需要也不应该发给 Agent。通知设置页用于发送测试消息和查看投递日志，测试邮件或群消息会真实发送。

## 示例：审批后通知申请人

把下面的提示词交给应用 Agent，再按实际业务替换页面和字段：

```text
订单审批结果变为通过或驳回时，请通过站内信通知该订单的申请人。消息包含审批结果和订单编号，点击后打开对应订单详情。

先检查当前应用中的订单字段、申请人、审批流程、通知渠道和用户权限，不要猜字段或让用户看到无权访问的订单。同一次审批结果重复执行时只能发送一条通知；通知发送失败不能撤销已完成的审批。

完成后告诉我从哪里查看通知，并用两个不同的申请人账号验证接收范围、订单链接和重复执行行为。
```

### 预期效果

申请人收到包含审批结果和订单编号的站内信，点击后能打开对应订单；其他申请人看不到这条消息。管理员能在通知日志中查看投递结果。

## 进一步使用

要扩展到邮件，告诉 Agent 收件人邮箱从哪个业务字段取得、邮件主题和正文要写什么，以及发送前是否需要员工确认。要发送飞书或钉钉消息，则说明目标群、触发条件和消息内容；管理员负责安全配置对应的机器人 Webhook。

### 接入新的消息服务

NocoBase 已提供站内信、SMTP、Resend、飞书和钉钉等 Provider。Provider 负责把消息提交给具体服务；Channel 是应用中配置和选择的命名通道。要接入尚未支持的短信或其他服务商，需要 Agent 在应用插件中扩展 Provider，单靠 Settings 页面配置并不能增加一种新服务。

准备服务商的官方 API 文档，并告诉 Agent 消息类型、收件人格式和发送要求。凭据由管理员安全配置在服务端，不要放进提示词。把下面的需求交给能读取当前项目 Skill 的应用 Agent：

```text
请为当前 NocoBase 应用增加对 [服务商名称] 的通知支持，用它发送 [短信或其他消息类型]。

先阅读当前应用提供的通知 Skill 和服务商官方 API 文档，检查现有通知插件及 Provider。告诉我接入还缺哪些信息，再按现有通知能力完成集成。凭据只能保存在服务端安全配置中，不能写进前端、代码仓库或日志。

完成后请验证：业务流程能通过新渠道发送消息；通知日志能查看投递结果；发送测试不会暴露凭据；服务商明确接受、明确拒绝和结果不确定时都能得到合适处理。说明管理员如何配置和测试新渠道，以及业务 Agent 后续如何选用它。
```

如果 Agent 需要确认当前应用支持哪些渠道或如何处理投递结果，让它检查当前安装版本提供的通知 Skill。更多完整场景见[发通知教程](../tutorials/notifications.md)。
