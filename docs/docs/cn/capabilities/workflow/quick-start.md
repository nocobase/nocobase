# 快速开始

本页带你在自己的应用中做出第一个流程：订单支付。客户下单后，订单要等支付平台的通知才算已支付；30 分钟不付款自动过期；订单取消后才到账的钱要退回去。整个过程分五步，每一步都给出可以直接使用的提示词。

## 开始之前

你需要一个 NocoBase 应用，并能在其中用 Agent 开发；还没有的话，先看[创建应用](../../get-started/create-app.md)。

不需要提前准备订单表，也不需要真实的支付平台账号。Agent 会检查应用里已有的内容，把缺少的一并补上，支付平台先用模拟服务代替。

## 第一步：描述流程

用业务语言说清楚三件事：订单从下单到结束经过哪些环节；每个环节由什么推进（客户的操作、支付平台的通知、时间到）；出意外时怎么办。这一步先不让 Agent 写代码，只要环节表和流程图。

```text
我想在当前应用中管理订单支付，要求如下。

客户下单后订单进入待支付。客户点支付时打开支付平台的收银台，只有支付平台的通知才能把订单标记为已支付，要确认通知确实来自支付平台，伪造的通知不能改变订单状态；同一个通知重复送达只算一次。30 分钟未支付的订单自动过期；待支付时客户可以取消订单。订单过期或取消后才收到的付款，自动退款。支付成功后通知客户。

先不要写代码。给我一张环节表（环节、什么会推进它、谁或什么系统推进、要记下什么、到哪个环节、之后会发生什么）、一张流程图，以及你认为还缺少的业务决定。
```

## 第二步：确认环节表和流程图

拿到环节表和流程图后，重点检查三点：

- 待支付、已支付、已取消、已过期这几个环节都在，每个没有结束的环节都有出路。
- 只有支付平台的通知能把订单变成已支付，客户和客服都不能手动改。
- 支付通知晚于取消或过期到达时，结果是退款，而不是把订单改回已支付。

然后回答 Agent 列出的问题，直到没有疑问。在这一步改流程最便宜，写完代码再改就要重新测试。

```text
补充决定：已支付的订单本次不支持取消；退款失败时自动重试 3 次，仍失败就停下来，在订单上标出“退款失败”。请更新环节表和流程图。
```

## 第三步：让 Agent 实现

让 Agent 同时做好页面和一个可以手动操作的模拟支付平台，这样下一步你就能自己验证各种情况。完成后让它告诉你在哪里看、怎样走一遍。

```text
环节表没问题，开始实现。支付平台先用一个模拟服务代替，在页面上提供一个面板，可以手动付款、扣留通知、放行通知、重复发送通知。订单详情页显示流程图（标出当前环节和走过的环节）、当前能做的操作和办理记录。完成后告诉我在哪个页面看订单，以及怎样走一遍完整流程。
```

## 第四步：在页面上走一遍

先走通正常路径：下单 → 打开收银台 → 付款 → 收到支付通知。订单应进入已支付，办理记录应说明是支付平台推进的。

下面的截图来自示例应用的“工作流 → 订单支付”，使用英文界面和模拟支付平台。示例将未支付时限缩短为 3 分钟，本文要求 30 分钟；截图中的发货等操作不在本次练习范围内。

**打开收银台**：选择订单后，先点订单上的“去付款”。订单进入待支付，“支付服务商（沙箱）”中的“付款”按钮才可用。这里的付款动作模拟发生在支付平台，订单要等 webhook 才会变为已付款。

![打开收银台后的待支付订单与沙箱付款入口](https://static-docs.nocobase.com/order-awaiting-payment-00bb6335875c9bf1.png)

**正常支付**：在沙箱中点“付款”，不勾选“暂扣 webhook”。收到通知后，订单显示“已付款”，并保存支付单号；Webhook 区域显示“已应用”。

![支付通知已应用，订单进入已付款并保存支付单号](https://static-docs.nocobase.com/order-paid-b6b1944c9e482001.png)

### 检查异常情况

正常路径走通后，再检查重复通知、取消后的迟到付款和超时未支付。

**重复通知**：点同一条通知的“再次投递”。通知结果变为“重放”，订单仍为已付款，不会再入账。

![再次投递同一支付通知后显示重放，订单状态不变](https://static-docs.nocobase.com/order-replayed-43f5d67da8ae48a6.png)

**先取消、后到账**：换一张未支付订单，点“去付款”，勾选“暂扣 webhook”，再在沙箱点“付款”。此时平台已经收款，但通知还未送达，订单仍停在待支付。

![支付已发生但 webhook 暂扣，订单仍停在待支付](https://static-docs.nocobase.com/order-held-e016bd6dea47a3df.png)

接着点订单上的“取消订单”，再点通知的“投递”。示例会经过“退款中”进入“已退款”，显示退款单号，不会恢复为已付款。你的订单可以保留已取消状态，同时单独显示退款进度；验收以第二步确认的环节表为准。

![取消后的迟到付款已自动退款，订单显示已退款和退款单号](https://static-docs.nocobase.com/order-refunded-014dfd556b48f8b1.png)

**超时未支付**：新建一张订单，不付款。到期后应自动过期，办理记录中的办理人是“系统”。可以让 Agent 提供一个较短的演示时限，并在验收后恢复为 30 分钟。

## 第五步：验收

向 Agent 提出业务验收要求，让它提供验证结果，包括不容易在页面上手动复现的情况：

```text
请核对这次订单支付的结果：正常付款后订单变为已支付；只有真实的支付平台通知能改变付款状态；重复通知不会重复入账；30 分钟未支付会自动过期；取消或过期后到账会自动退款；退款失败重试 3 次后显示“退款失败”。请逐条告诉我是否符合要求，有哪些问题尚未解决，并确认演示时限已恢复为 30 分钟。
```

对照环节表和验证结果确认这次练习完成。接入真实支付平台属于后续开发，需要另外确认正式账号和付款、退款结果。
