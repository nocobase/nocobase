# 快速开始

本页带你在自己的应用中做出第一个流程：订单支付。客户下单后，订单要等支付平台的通知才算已支付；30 分钟不付款自动过期；订单取消后才到账的钱要退回去。整个过程分五步，每一步都给出可以直接使用的提示词。

## 开始之前

你需要一个 NocoBase 应用，并能在其中用 Agent 开发；还没有的话，先看[创建应用](../../get-started/create-app.md)。

不需要提前准备订单表，也不需要真实的支付平台账号。Agent 会检查应用里已有的内容，把缺少的一并补上，支付平台先用模拟服务代替。

## 第一步：描述流程

用业务语言说清楚三件事：订单从下单到结束经过哪些环节；每个环节由什么推进（客户的操作、支付平台的通知、时间到）；出意外时怎么办。这一步先不让 Agent 写代码，只要环节表和流程图。

```text
在当前应用中，用 NocoBase 的流程能力（@nocobase/lifecycle）为订单支付做一个流程。先检查应用是否已具备这个能力，缺少的先补齐。

客户下单后订单进入待支付。客户点支付时打开支付平台的收银台，只有支付平台的通知才能把订单标记为已支付，通知要验签；同一个通知重复送达只算一次。30 分钟未支付的订单自动过期；待支付时客户可以取消订单。订单过期或取消后才收到的付款，自动退款。支付成功后通知客户。

先不要写代码。给我一张环节表（环节、什么会推进它、谁或什么系统推进、要记下什么、到哪个环节、之后会发生什么）、一张流程图，以及你认为还缺少的业务决定。
```

## 第二步：确认环节表和流程图

拿到环节表和流程图后，重点检查三点：

- 待支付、已支付、已取消、已过期这几个环节都在，每个没有结束的环节都有出路。
- 只有支付平台的通知能把订单变成已支付，客户和客服都不能手动改。
- 支付通知晚于取消或过期到达时，结果是退款，而不是把订单改回已支付。

然后回答 Agent 列出的问题，直到没有疑问。在这一步改流程最便宜，写完代码再改就要重新测试。

```text
补充决定：已支付的订单本次不支持取消；退款失败时自动重试 3 次，仍失败就停下来，在订单上标出“退款失败”。请更新环节表和流程图。
```

## 第三步：让 Agent 实现

让 Agent 同时做好页面和一个可以手动操作的模拟支付平台，这样下一步你就能自己验证各种情况。完成后让它告诉你在哪里看、怎样走一遍。

```text
环节表没问题，开始实现。支付平台先用一个模拟服务代替，在页面上提供一个面板，可以手动付款、扣留通知、放行通知、重复发送通知。订单详情页显示流程图（标出当前环节和走过的环节）、当前能做的操作和办理记录。完成后告诉我在哪个页面看订单，以及怎样走一遍完整流程。
```

## 第四步：在页面上走一遍

按下面四种情况各走一遍：

| 情况           | 怎么操作                               | 应该看到                                     |
| -------------- | -------------------------------------- | -------------------------------------------- |
| 正常支付       | 下单 → 支付 → 放行通知                 | 订单变为已支付；办理记录写明是支付平台推进的 |
| 先取消、后到账 | 支付时扣留通知，先取消订单，再放行通知 | 订单保持已取消，钱被自动退回                 |
| 重复通知       | 把同一个通知再送一次                   | 提示已处理过，不会重复入账                   |
| 不付款         | 下单后不付款，等到时间                 | 订单自动过期，办理记录中的办理人是“系统”     |

验证“不付款”时不必真的等 30 分钟，可以让 Agent 临时把时长改短，验证完再改回来。

## 第五步：验收

页面上走通还不够，有些情况手动很难覆盖。让 Agent 用测试证明每种情况都正确，并给出构建结果：

```text
请补充测试并把结果给我：只有支付平台的通知能把订单标记为已支付；重复的通知只算一次；30 分钟未支付自动过期（测试中快进时间）；取消或过期后到账自动退款；退款失败 3 次后停在退款失败。最后运行 lint、typecheck、test 和 build。
```

测试全部通过、构建成功，第一个流程就完成了。
