# 场景示例

每个场景给出交给 Agent 的提示词、做出来的效果，以及它用到了哪些流程能力。提示词可以按自己的业务改写后直接使用；每个提示词都要求 Agent 先给环节表和流程图，确认后再写代码，开发步骤见[使用 Agent 开发](./develop.md)。

| 场景                          | 主要难点                         |
| ----------------------------- | -------------------------------- |
| [电子发票开具](#电子发票开具) | 等外部回调，迟迟不来时主动查询   |
| [数据导出](#数据导出)         | 对方不通知，只能定时查询         |
| [秒杀下单](#秒杀下单)         | 后一步失败时撤销前一步           |
| [订阅续费](#订阅续费)         | 按周期推进，失败后定期重试       |
| [物流发货](#物流发货)         | 等两件事都完成，忽略过期的旧通知 |
| [客服工单](#客服工单)         | 人工操作和等待交替，限期重开     |

下面的截图来自示例应用的工作流页面，展示这些能力的一种实现。开票平台、支付、库存和承运商由沙箱模拟；为了方便试用，部分时限比提示词更短。

## 电子发票开具

客户在已完成的订单上申请开票，发票由外部开票平台开出。

**效果**：发票详情页显示流程图、当前环节和办理记录；开票成功后可以下载 PDF；开票失败时，财务能看到失败原因和“重新开票”按钮。

**用到的能力**：等待外部回调、超时后主动查询、失败自动重试、同一张发票不重复开具。

在“工作流 → 电子发票开具”中，三张草稿分别演示正常开票、提交失败和回调超时。订单号、客户和金额来自已完成的沙箱订单；这是独立的演示订单目录。未载入样例数据时，可以运行 `pnpm nocobase db sample` 补充。

选择订单 #1024 的“星河科技有限公司”，点“申请开票”，再在“开票平台（沙箱）”点“开具成功”。收到通知后，页面保存平台请求号和发票号码，并提供“下载演示 PDF”。PDF 标有沙箱说明，不用于实际报税。同一条通知可以“再次投递”，系统只处理一次。

![电子发票开具成功：发票号码和演示 PDF 下载](https://static-docs.nocobase.com/invoice-issued-44bcc68532e60ba7.png)

选择订单 #1025 的“晨光书店有限公司”并提交。这张样例故意让提交失败三次，页面显示失败原因；点“重新开票”后可继续办理。

![电子发票提交三次失败后，可手动重新开票](https://static-docs.nocobase.com/invoice-failed-6fbd81574d42e659.png)

![重新开票后进入等待开票，沿用同一条发票记录](https://static-docs.nocobase.com/invoice-retry-8a2d53f0f88a854e.png)

选择订单 #1026 的发票并提交，勾选“暂扣 webhook”，再点“开具成功”。平台已经完成开票，但系统尚未收到通知。示例等待 30 秒后主动查询结果，展示查询次数并进入开票成功；与下方提示词的 10 分钟不同。之后投递暂扣的旧通知，也不会再次开具。

![平台已开票但暂扣结果通知，系统仍在等待回调](https://static-docs.nocobase.com/invoice-held-d994198ebe245d00.png)

![回调超时后主动查询，取得发票号码和 PDF](https://static-docs.nocobase.com/invoice-queried-49252fc060aabec5.png)

```text
我想在当前应用中为订单开具电子发票做一个流程，先给我环节表和流程图，确认后再写代码。

客户在已完成的订单上申请开票，填写抬头和税号。系统把开票请求提交给开票平台：提交失败自动重试 3 次，仍失败则进入“开票失败”，财务可以手动重试。提交成功后等待开票平台的结果通知，结果通知里有发票号码和 PDF 地址，收到后保存到发票上并通知客户。10 分钟没有收到结果通知，就主动向开票平台查询一次结果。同一张发票无论重试多少次，开票平台只能开出一张；重复送达的结果通知只算一次。
```

## 数据导出

导出任务交给外部服务处理，对方不会主动通知结果。

**效果**：导出任务列表显示每个任务的进度和当前环节；完成的任务给出下载链接，超时失败的任务写明原因。

**用到的能力**：定时查询外部进度、整体截止时间、超时后通知外部停止。

在“工作流 → 数据导出”中，选择“9 月订单明细”并点“开始导出”。任务显示当前环节、轮询次数和截止时间，进度以上一次查询的结果为准。示例每 15 秒查询一次，3 分钟后放弃，与下方提示词的 30 秒、10 分钟不同。

![导出处理中：轮询次数、截止时间和上一次查询得到的进度](https://static-docs.nocobase.com/export-processing-19f5f7ad7dc3494a.png)

完成后，页面显示结果文件地址和 100% 的进度；示例地址是沙箱地址，真实应用需接入实际导出服务并提供可用的下载链接。

![导出完成后的结果文件地址和进度](https://static-docs.nocobase.com/export-completed-cee3d4b02ec8cbc7.png)

```text
我想在当前应用中为数据导出做一个流程，先给我环节表和流程图，确认后再写代码。

用户提交导出后，系统把任务交给外部导出服务，对方不会主动通知结果。每 30 秒查询一次进度并显示在页面上；完成后保存下载地址并通知用户；从提交起超过 10 分钟仍未完成，标记为失败，通知外部服务停止任务，并告诉用户失败原因。
```

## 秒杀下单

先占库存再扣款，扣款失败要把库存还回去。

**效果**：订单的办理记录清楚地显示“已预留库存 → 扣款失败 → 已释放库存”；释放也失败时，订单停在“待人工释放”，运营在后台一键重试。

**用到的能力**：多个对外事项按顺序执行、失败后撤销已做的事、撤销也失败时停下等人处理。

在“工作流 → 限时抢购”中，选择“机械键盘 × 1”并点“下单”。这条示例故意让银行卡被拒：步骤面板显示锁定库存成功、扣款失败、释放库存成功，订单进入已取消，仓库的已预留数量回到 0。

![秒杀扣款失败后的库存补偿：锁定成功、扣款失败、释放成功](https://static-docs.nocobase.com/purchase-compensated-28a1a04bfbf90947.png)

```text
我想在当前应用中为秒杀下单做一个流程，先给我环节表和流程图，确认后再写代码。

客户下单时先在仓库系统预留库存，预留成功后再扣款。扣款成功则订单完成；扣款被拒时释放预留的库存，订单进入已取消。释放失败最多重试 3 次，仍失败则停在“待人工释放”，运营可以在后台重试。每一步调用外部系统都不能重复执行。
```

## 订阅续费

按周期自动扣款，扣款失败时补缴。

**效果**：订阅详情页显示当前周期、下次扣款日期、是否待补缴，以及每次扣款的记录。

**用到的能力**：按单据上的日期推进、失败后定期重试、多次失败后自动取消。

在“工作流 → 订阅续费”中，点列表右上角的“订阅”，展开“演示选项”，可以设置银行卡拒付的次数，用来验证补缴和重试。下图展示提交前的表单；示例周期为 3 分钟，失败后每 1 分钟重试，与下方提示词的按月扣款、每天重试不同。

![订阅表单与演示选项：客户、套餐和银行卡拒付次数](https://static-docs.nocobase.com/subscription-options-d3c2f63f07fbc61c.png)

```text
我想在当前应用中为订阅续费做一个流程，先给我环节表和流程图，确认后再写代码。

用户开通订阅后，每月在开通日自动扣款，成功后进入下一个周期。扣款失败进入“待补缴”，每天重试一次；用户更新银行卡后立即重试；连续 3 次失败自动取消订阅并通知用户。用户可以随时取消，取消后当前周期结束时停止。
```

## 物流发货

发货要等支付和拣货都完成，物流轨迹由快递平台推送。

**效果**：发货单详情页显示两个前置条件各自是否完成，以及按时间排列的物流轨迹。

**用到的能力**：等待多个外部结果且不限先后、按发生时间处理通知、忽略过期的旧通知。

在“工作流 → 发货物流”中打开备货中的发货单，详情中的支付确认、拣货时间都为空。下方沙箱可分别发送“支付已确认”和“仓库已拣货”，哪个先到都可以；收到两个信号后才能交给承运商。承运商面板提供扫描发生时间和暂扣事件的入口，可继续验证迟到或乱序通知。

![备货中的发货单与支付、拣货两个前置条件及承运商事件面板](https://static-docs.nocobase.com/shipping-prerequisites-b983ba83f6554190.png)

```text
我想在当前应用中为发货做一个流程，先给我环节表和流程图，确认后再写代码。

发货要等两件事都完成：支付平台确认收款、仓库完成拣货，两者到达的先后顺序不固定，都完成后进入待交接。交给快递后，快递平台会推送揽收、运输、派送、签收等轨迹；按轨迹发生的时间处理，比已记录的轨迹更早的推送直接忽略；签收后发货完成并通知客户。
```

## 客服工单

客服处理客户问题，中间要等客户回复。

**效果**：工单详情页按时间显示完整对话；不能操作的按钮置灰并显示原因，例如“已超过重开期限”。

**用到的能力**：人工操作与等待交替、超时自动关闭、限期重开、办不了时说明原因。

在“工作流 → 客服工单”中打开“发票抬头填错了，能否重开？”，可以看到客户提问、客服受理、客服回复和客户补充信息。右上角的“当前身份”可以切换演示角色，查看各自能办理的操作。

![客服工单中的完整对话、负责人和当前可办操作](https://static-docs.nocobase.com/ticket-conversation-8145cf7198dd2368.png)

```text
我想在当前应用中为客服工单做一个流程，先给我环节表和流程图，确认后再写代码。

客户提交后进入待分派；客服从队列领取，或由主管指派。客服回复客户后进入“等待客户回复”，客户回复后回到处理中。客服可以标记已解决；客户 72 小时没回复自动关闭；关闭后 7 天内客户可以重开，超过 7 天按钮置灰并提示“已超过重开期限”。只有工单的处理人可以回复和标记已解决；主管可以改派，改派必须写原因。客服回复时给客户发邮件，发送失败自动重试。工单详情按时间显示完整对话。
```

## 需要多人处理的业务

一个环节需要多人共同处理时，例如会签、或签、多人分别办理后汇总、加签，安装[审批插件](../approval/index.md)后搭建起来更方便。
