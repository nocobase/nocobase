# 工作流概览

**工作流用于定义和执行业务流程，将操作步骤、执行条件和流转规则连接起来。**它控制业务按什么顺序推进、满足什么条件才能进入下一步，以及等待、超时或执行失败时如何处理。

例如，运输订单从分配司机、接单到签收，各步骤都有对应的操作和条件；工作流按这些规则推进订单，并保留执行进度和处理记录。

## 提供哪些能力

| 能力                                   | 可以做什么                                                                   |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| [流程定义与操作控制](./definition.md)  | 定义阶段、操作、条件和分支，检查必填信息，防止跳过步骤或覆盖他人的处理结果。 |
| [等待、超时与可靠执行](./execution.md) | 等待人员或外部结果，按时限自动处理，失败后重试，避免重复处理同一请求。       |
| [流程进度与处理记录](./progress.md)    | 展示当前阶段、已走过的路径，以及操作人、时间和提交资料。                     |

下面通过 Northstar 运输订单介绍操作控制和处理记录，再用后台导出报表展示等待与执行结果。

## 什么情况需要工作流

业务包含多个阶段，需要停下来等待，或需要处理失败后的后续动作时，适合使用工作流。订单交付、开票、数据导出、订阅续费和异常工单都属于这类需求。

数据变化后只发送一条消息，可以直接使用[通知](../notification.md)；每天固定时间执行一次任务，可以使用[定时任务](../scheduler.md)。工作流的重点是这些动作怎样围绕同一笔业务连接起来，并持续推进到结束。

简单的确认或驳回可以作为流程操作；多级审批、会签、加签、转交等人工决策使用[审批](../approval/index.md)。

## 如何搭建与调整

向 Agent 描述阶段、操作条件、等待时间和失败处理，Agent 将流程开发到应用中。流程页面可根据业务需要自由设计。
