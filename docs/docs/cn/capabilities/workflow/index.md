# 概览

很多业务都不是一步完成的：一笔订单要等客户付款、等仓库发货、等快递签收；一张发票要等开票平台返回结果；一个工单要等客户回复。这些业务会持续几分钟到几个月，中间要停下来等人、等外部系统、等时间到。每一步由谁或什么推进、超时了怎么办、失败了怎么办、办完要通知谁，这就是流程。

在 NocoBase 中，你用业务语言把流程讲给 Agent，Agent 把它做进你的应用。流程等待期间应用重启，也不会丢失任何一张单据的进度。

## 一笔订单的流程

以一笔订单为例：

1. 客户下单后，订单进入“待支付”。付款结果以支付平台的通知为准，客户和客服都不能手动改成已支付。
2. 30 分钟没有付款，订单自动取消。
3. 付款成功后通知仓库；仓库发货时必须填写快递单号。
4. 快递平台的签收通知到达后，订单进入“已签收”，7 天后自动完成。
5. 已付款的订单被取消时自动退款；退款失败自动重试，无论重试多少次都只退一次。

还有一些容易被忽略的情况，流程同样给出明确的结果：支付平台的同一个通知送达两次，只算一次；付款通知在订单取消之后才到，钱会被退回，订单不会被改回已支付。

## 做好之后用户看到什么

- **流程图**：每张单据都能看到流程图，标出现在走到哪一步、之前经过了哪些环节。
- **只显示能办的操作**：暂时办不了的操作会置灰并说明原因，例如“只有仓库人员可以发货”。绕过页面直接调用接口，也会得到同样的拒绝。
- **办理记录**：每一步是谁办的、什么时候办的、填了什么，都有记录。系统自动执行的操作，办理人显示为“系统”。
- **自动处理时限**：超时自动提醒、转交或关闭。
- **可靠的对外事项**：办完自动通知相关的人；调用外部系统失败会自动重试，同一件事不会重复执行。
- **不会互相覆盖**：两个人同时处理同一张单据，只有先提交的生效，后一个会被提示刷新。

## 适合用流程的业务

| 类型         | 例子                                                       |
| ------------ | ---------------------------------------------------------- |
| 交易         | 订单支付、发货、退款、秒杀                                 |
| 对接外部系统 | 开票、电子签章、物流、数据导出：等对方回调，或定时查询结果 |
| 周期性业务   | 订阅续费、合同到期续签                                     |
| 服务         | 客服工单、投诉、售后、设备报修                             |
| 审批         | 简单的提交、审批、驳回                                     |

简单的审批可以直接用流程完成。多级审批、会签、或签、加签、转交、抄送，以及一个环节由多人共同处理的业务，安装[审批插件](../approval.md)后搭建起来更方便。

以下情况不需要流程：数据变化后只是发一条通知；一次操作就完成、没有中间环节的事情。

## 怎样调整流程

流程写在应用的代码里，不能在界面上修改，也没有拖拽画流程的设计器。需要调整时（包括修改超时时长、金额标准），在本地让 Agent 修改并测试，再重新部署应用。这样每一次调整都经过测试和评审，并且能说清楚对正在流程中的单据有什么影响。
