# 检查权限结果

权限检查帮助管理员理解一个用户能做什么、条件是什么，以及权限来自哪里。它用于解释授权，不统计符合条件的实际记录数量。

## 示例：为什么 Bob 能看这笔订单

用户获得了额外访问或无法查看某笔记录时，管理员需要查明权限来源和适用条件。权限检查帮助定位应调整的岗位、共享或限制规则。

```text
在 Northstar 的「访问规则」中提供权限检查入口，仅对获得授权的管理员开放。
选择实际员工，查看页面、业务操作和数据条件，展开权限集、人员或组织分配、默认范围、共享及限制来源。
以 Bob 的订单查看权限为例，说明他本人的范围与 NS-2026-001 临时共享分别来自哪里。
检查结果用于解释规则，不把它显示成可访问订单数量；不允许普通员工查看其他人的权限详情。
```

选择 Bob 后，管理员检查订单查看操作及其来源。岗位可能提供本人负责范围，共同规则增加完成订单，临时共享增加指定记录；若有适用限制，最终结果还要满足限制条件。

## 根据来源调整

| 想改变什么             | 应调整哪里     |
| ---------------------- | -------------- |
| 岗位职责与操作         | 权限集         |
| 谁承担某个岗位         | 人员或组织分配 |
| 共同可查资料           | 默认数据范围   |
| 指定人员临时协作       | 共享规则       |
| 所有来源共同遵守的条件 | 限制规则       |

检查页解释结果，实际修改在相应规则管理中完成。选择具体用户时核对该用户的实际授权；选择团队时看到的是团队本身的分配，不能直接当作所有成员的完整权限。

超级管理员具有不受限访问。展示岗位差异时使用客户经理或司机账号；查看真实业务效果时打开对应页面，不能把检查器里的条件数当成订单条数。

## 查看实际权限来源

进入 **访问规则 → Inspect access（权限检查）**，选择 Bob，点击 **Inspect access**。结果显示客户经理岗位，以及当前适用的共同范围、订单共享和费用限制；展开 **View decision conditions** 可查看服务端返回的条件。

![查看 Bob 的岗位及共同范围、共享与限制来源](../assets/northstar-inspector-en.png)

**检查结果列出岗位及共同范围、共享和限制来源。**

本例最终应用的规则是：本人订单与完成订单共同范围、NS-2026-001 共享先合并，再限制为运输费用不超过 2,000 元的订单。实际订单列表见[限制规则](./restriction-rules.md)，检查页不会把条件决定显示为订单数量。
