# 工作流概览

工作流把业务的办理顺序、操作条件和处理记录组织起来。以 Northstar 运输订单为例：调度员安排司机，司机接单并运输，提交签收资料后由主管核对完成。员工打开订单就能知道当前进度、下一步要做什么，以及谁已经处理过。

## 可以为业务提供什么

| 能力           | 对业务的作用                                     |
| -------------- | ------------------------------------------------ |
| 办理环节与操作 | 按待调度、待接单、运输中、已送达、已完成推进订单 |
| 办理条件与输入 | 指定司机才能接单；拒单必须填写原因；签收需要凭证 |
| 分支与退回     | 拒单后返回待调度，重新安排司机                   |
| 进度与办理记录 | 查看当前阶段、操作人、时间、前后阶段和提交资料   |
| 时限与自动处理 | 未接单时提醒，超过约定时间通知负责人跟进         |
| 通知与外部协作 | 办理后通知客户经理，等待外部结果，处理失败与重试 |

后两项按具体业务需求接入，[时限与外部协作](./automation.md)说明怎样提出需求和处理结果。

## 本例先搭建什么

本节先为已有运输订单搭建基本办理流程。完成后，订单详情同时显示阶段、可办理动作和历史，无须另到一个工作流管理页面。

## 工作流与审批

司机接单、提交签收是业务办理动作。特殊运输需要主管和财务依次同意，则使用[审批](../approval/index.md)。审批通过之后是否继续运输、预留车辆或支付费用，需要按业务规则连接后续动作。

流程由 Agent 根据业务需求开发，当前没有拖拽设计器。修改流程后需要部署更新，并安排已有未完成订单怎样继续。
