# 扩展参考

本页供需要审核 Agent 生成代码或扩展流程的开发者参考。业务使用可以从[快速开始](./quick-start.md)开始。

## 事务内与事务后

流程使用 `@nocobase/lifecycle`。单据自身保存当前环节，每次办理在事务中检查条件、更新数据并保存办理记录。调用外部系统在提交后执行。

| 需求                   | 扩展点                                              | 边界                           |
| ---------------------- | --------------------------------------------------- | ------------------------------ |
| 检查能否办理并解释原因 | `guard`、`runtime.addGuard()`                       | 事务内，写入前                 |
| 同步更新单据字段       | `set`                                               | 与办理一起提交                 |
| 写入其他业务表         | `onTransition`                                      | 同一事务                       |
| 建立或结束环节内往来   | `onEnterState`、`onLeaveState`                      | 同一事务                       |
| 同时办理多张单据       | `runtime.transaction()`、`tx.fire()`、`tx.create()` | 全部成功或回滚                 |
| 可靠通知与外部调用     | `effects`、`onEnter`                                | 提交后重试，最终失败有处理出口 |
| 页面刷新与索引更新     | `completed`、`entered`、`announce` 事件             | 尽力投递，失败不重发           |

事务内扩展不调用外部系统。可靠事项与尽力事件不同；对外调用还需要按业务键幂等，库的重试不能代替外部服务避免重复执行的约定。

## 已有表与环节内处理

接入已有订单时补齐当前环节、环节时间和并发版本字段，建立办理历史与对外事项记录；确定旧数据对应的环节，再收口直接修改状态的表单、导入与接口。

默认字段是 `status`、`statusChangedAt` 和 `lifecycleVersion`，可在定义中改名。库不自带业务建表迁移，应用或拥有该流程的插件维护自己的表结构。

补充材料等环节可以有多轮对话，记录在专门的表中；结束往来与推进单据需要一致提交。无需为每一条回复新建环节，已经结束的往来不能被迟到回复重新打开。

## 扩展与开发接口

其他插件可以用 `addGuard()` 追加操作条件，并保留返回的移除函数；创建单据的条件由创建规则单独声明。通过事件订阅获得办理、进入环节或待办宣布结果，需要可靠执行时使用对外事项。

| 入口                          | 用途                         |
| ----------------------------- | ---------------------------- |
| `@nocobase/lifecycle`         | 定义、运行时、存储和流程图   |
| `@nocobase/lifecycle/jobs`    | 对外事项执行、时限检查及恢复 |
| `@nocobase/lifecycle/react`   | 读取单据、可办操作和提交办理 |
| `@nocobase/lifecycle/testing` | 内存存储与可推进的测试时钟   |

常用方法包括创建与办理 `create()` / `fire()`、查看条件 `available()` / `can()`、视图与历史 `view()` / `describe()` / `history()`，以及对外事项查看、重试与继续处理。库不提供业务 HTTP 路由，应用负责认证、授权和接口。

不允许用户直接调用的操作声明为 `manual: false`。条件拒绝、输入错误、状态不适用和版本冲突应转成应用错误提示；冲突不覆盖他人的办理结果。

## 能力边界

当前没有拖拽设计器、嵌套环节或通用并行分支；需要并行的业务可以拆分子单据协调。权限使用应用授权能力，复杂人工决策使用审批插件。

运行时还提供 `transaction()`、`addGuard()`、`on()`、`listEffectRuns()`、`retryRun()`、`continueRun()`、`runTriggers()`、`reclaim()` 和 `recover()`，分别用于事务协作、追加规则、事件、事项管理与后台恢复。

常见错误包括 `GUARD_REJECTED`（条件不满足）、`INVALID_STATE`（环节不适用）、`INVALID_INPUT`（输入有误）、`CONFLICT`（版本冲突）、`NOT_MANUAL`（系统专用操作）及 `REQUEST_REUSED`（请求标识被另一项办理使用）。使用标准错误转换向调用方返回原因，不将异常当作办理成功。

业务术语对应代码中的 `lifecycle`（流程）、`state`（环节）、`transition`（操作）、`validate` / `accept`（输入）、`route`（条件分支）、`parameters`（规则数值）与 `trigger`（时限）。插件声明流程库为 peer 依赖，由应用提供同一运行时依赖。
