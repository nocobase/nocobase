# 场景示例

同一流程能力可以用于运输以外的业务。下面保留六类常见场景；先让 Agent 给出环节表和流程图，确认后实现。这些是可改写的需求示例，不要求为每个场景另建一套系统。

## 运输费用开票

```text
为已完成运输订单增加电子发票流程，先给环节表和流程图。
客户填写抬头和税号，系统提交开票平台；提交失败重试3次，仍失败由财务处理。
提交成功后等待结果，保存发票号码和文件地址并通知客户。
10分钟未收到回调时主动查询，同一业务请求不重复开票，重复通知只处理一次。
```

重点是等待回调、超时查询、重试与避免重复开具。结果页显示开票进度、失败原因及可下载文件。

## 运输月报导出

```text
为运输月报增加外部导出流程，先给环节表和流程图。
提交后每30秒查询进度；完成时保存下载地址并通知申请人。
10分钟仍未完成则标记失败，通知外部服务停止，页面说明原因。
```

重点是轮询、整体截止时间和停止外部任务，页面展示最近查询进度与结果。

## 预留失败后的补偿

```text
特殊运输先向外部系统预留车辆或仓位，再完成后续确认。
后续确认失败时释放预留；释放失败重试3次，仍失败进入待人工处理。
每一步都按业务标识避免重复执行，记录预留、失败和释放结果。
先给环节表、流程图及所有退出路径的资源释放方案。
```

这与秒杀先预留库存、扣款失败后释放库存属于同类补偿问题。补偿也是对外事项，需要自己的失败出口。

## 配送服务协议续费

```text
客户配送协议按周期续费；扣款成功进入下一周期。
失败进入待补缴，每天重试一次；连续3次失败按约定停止服务并通知客户。
更新付款方式后可立即重试；客户取消后本周期结束时停止。
先给环节表和流程图，列出需要确认的金额与停服规则。
```

重点是按记录日期推进、周期重试和明确取消何时生效。

## 多个外部条件与乱序事件

```text
运输交接需要仓库就绪与费用确认，两者没有固定先后顺序，都满足后才进入待交接。
承运商轨迹按事件发生时间处理，忽略早于已记录进度的旧事件。
验证外部事件来源，重复事件只应用一次。先给环节表和流程图。
```

重点是汇总外部条件和处理迟到结果。等待多个信号不等于界面提供了通用并行分支设计器。

## 运输异常工单

```text
客户报告运输异常后进入待分派，客服领取或主管分派。
回复客户后等待客户补充，客户回复后继续处理；72小时未回复自动关闭。
关闭7天内可重开，超过期限说明原因；改派必须记录理由。
详情保存对话，回复邮件失败重试。先给环节表和流程图。
```

重点是人工办理与等待交替、时限、有限期重开，以及环节内多轮往来。多人共同决策的需求见[审批](../approval/index.md)。
