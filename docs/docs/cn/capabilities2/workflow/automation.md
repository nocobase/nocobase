# 时限与外部协作

基本运输流程完成后，再补“没人处理怎么办”和“需要其他系统返回结果怎么办”。这些规则同样通过业务提示词交给 Agent，不需要再学习一套开发流程。

## 接单超时后提醒负责人

待办长期无人处理时，可以按等待时长提醒，并在超过约定时间后升级给负责人。提醒与业务办理分开，避免把发送消息当作已完成处理。

```text
订单进入待接单后，30 分钟未处理先提醒指定司机；60 分钟仍未处理时通知调度员与主管。
提醒不能把订单自动当成已接单，同一轮提醒不要重复发送。
运输超过预计送达时间时显示延误，让调度员跟进。
重启应用后继续检查未处理订单，保留提醒与处理记录。
```

用户看到的结果应是提醒消息、对应订单入口和仍待办理的订单。提醒需要后台持续执行，关闭页面后也应生效。这是本例下一步可接入的需求，现有运输办理截图没有演示自动超时提醒。

## 签收后通知客户经理

业务办理完成后，相关人员需要及时收到结果。可以在保存业务结果后发送通知，发送失败时继续处理通知，不丢失已保存的业务数据。

```text
司机提交签收后通知负责客户经理，消息链接打开同一订单。
签收结果与凭证先保存；通知失败时保留失败原因并重试，不把已送达订单改回运输中。
在通知记录中显示发送结果，最终仍失败时交给负责人处理。
```

这里影响业务的是：货物已送达，消息暂时没发出去，这两件事需要分别看结果。不能因为通知失败丢掉签收资料，也不能只显示“办理成功”却让用户无处查看发送情况。

[通知](../notification.md)一节已有 Northstar 的消息和发送记录截图，可以复用该能力接入流程。该通知演示与本页提出的自动签收通知需求分开说明。

## 等待外部系统的结果

例如提交开票申请后，发票平台可能稍后才返回文件。页面需要明确显示“等待开票结果”，收到结果后保存发票号码与下载地址，再通知申请人。

```text
为已完成运输订单增加开票流程。客户填写抬头和税号后提交开票平台。
提交失败最多重试3次，仍失败交给财务；10分钟未收到结果时主动查询。
同一业务请求不能重复开票，重复或迟到的结果不能覆盖已经完成的结果。
页面显示开票进度、失败原因与发票文件，保留外部请求和处理记录。
```

真实平台需要提供连接方式、身份凭据及回调或查询接口。以上是扩展需求，当前演示尚未接入真实开票平台。

## 还可以扩展哪些业务

下面是沿同一运输背景可继续搭建的需求，不是本轮已经搭建并配图的功能。已实现的运输办理结果见[快速开始](./quick-start.md)。

| 业务需求       | 要补充的规则                                                  | 用户需要看到的结果                   |
| -------------- | ------------------------------------------------------------- | ------------------------------------ |
| 运输月报导出   | 每30秒查询进度，10分钟未完成则停止并说明原因                  | 进度、下载入口或失败原因             |
| 车辆或仓位预留 | 后续确认失败时释放预留，释放失败重试后交给人工                | 是否仍占用资源、释放结果和处理人     |
| 配送协议续费   | 扣款失败每天重试，连续3次失败按约定停服；取消在本周期结束生效 | 服务有效期、欠费与下一次处理时间     |
| 仓库与费用确认 | 两项条件都完成才能交接，没有固定先后顺序                      | 哪项已满足、还在等谁                 |
| 承运商轨迹接入 | 验证来源，重复事件只处理一次，迟到事件不倒退进度              | 最新有效轨迹与处理记录               |
| 运输异常工单   | 等待客户72小时后关闭，关闭7天内可重开，改派说明理由           | 对话、当前处理人、截止时间与重开入口 |

## 调整正在使用的流程

已有未完成业务时调整流程，需要安排旧记录怎样继续办理。新规则上线应保留必要的衔接路径，避免升级后记录无法推进。

```text
在运输出发前增加交接确认，请先分析已有订单怎样继续。
保留在途订单的可办理路径，说明新旧流程的衔接和部署安排。
订单停滞时先查看当前阶段、分配人员、办理历史和外部执行记录，说明还在等什么，再提出处理建议。
```

用户关心的是旧订单会不会卡住、已保存的结果是否保留，以及下一步由谁处理。流程改名或新增环节，应先安排这些问题，再实施更新。

需要核对实现接口时，另见[开发参考](./extension.md)。
