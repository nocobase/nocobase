# 邮箱接入配置

管理员配置应用连接邮箱服务所需的信息，用户再关联自己的邮箱。已有可用服务商时，用户可以直接在邮箱账号页完成关联。

## 管理员准备服务商配置

| 接入方式      | 需要准备的信息                                             |
| ------------- | ---------------------------------------------------------- |
| IMAP/SMTP     | 收信服务器、发信服务器、端口和安全连接方式。               |
| Gmail         | Google OAuth 应用、客户端信息和当前应用的回调地址。        |
| Microsoft 365 | Microsoft OAuth 应用、客户端信息，以及组织要求的授权审批。 |

应用开发者或负责部署的管理员在服务端 `mail.providers` 配置这些信息。服务商配置由应用维护；个人邮箱通过应用中的邮箱账号页关联。

例如，使用 mailbox.org 时，可将以下服务器信息交给 Agent：

```text
为应用配置 mailbox.org 邮箱接入：
- IMAP 收信服务器：imap.mailbox.org，端口 993，使用 SSL/TLS。
- SMTP 发信服务器：smtp.mailbox.org，端口 465，使用 SSL/TLS。
添加邮箱账号页，让用户填写自己的邮箱地址、用户名和密码，并选择首次同步的起始日期。
```

使用 OAuth 时，管理员需要把当前应用的回调地址登记到服务商平台，并完成服务商要求的权限审批。

## 用户关联自己的邮箱

打开邮箱账号页，点击 **Connect account**：

- **IMAP/SMTP**：选择服务商，填写邮箱地址、用户名和密码或授权码；具体凭据以服务商要求为准。
- **Gmail、Microsoft 365**：选择服务商，前往服务商页面登录并授权。
- 选择首次同步的起始日期，应用从该日期开始导入邮件。

邮箱密码在关联表单中填写；OAuth 密钥由管理员在部署配置中保存。

## 接入方式的差异

Gmail 和 Microsoft 365 提供较完整的同步与邮箱整理能力。IMAP/SMTP 主要收取新增邮件和发送邮件，不完整同步其他客户端中的已读、删除和移动状态，也不支持服务商草稿、发件别名、推送同步或移动到服务商文件夹。应用内的本地草稿仍可用于暂存未发送内容。

## 常见问题

### 应用中没有邮箱入口

请 Agent 将邮件中心和邮箱账号页加入应用导航，并接入 Mail 能力。

### OAuth 授权后没有回到应用

请管理员核对服务商平台登记的回调地址与当前应用配置，并确认授权后的返回页面可以访问。

### 关联后没有看到邮件

检查同步起始日期是否包含目标邮件，并查看同步是否完成。首次导入大量历史邮件需要时间；后台任务运行异常时，请管理员查看同步记录和应用服务状态。
