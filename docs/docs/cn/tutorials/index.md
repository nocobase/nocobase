# 订单系统教程

这套教程带你完成一个小型订单系统：业务员选择客户并创建订单，提交后由主管审批，申请人通过站内信查看结果。你会把数据、页面、权限和后台流程接在一起，最后构建并运行生产版本。

## 教程定位

| 项目     | 说明                                                             |
| -------- | ---------------------------------------------------------------- |
| 适合谁   | 已能创建和运行应用，希望跟着业务案例继续学习的应用搭建者和开发者 |
| 案例     | 客户与订单管理，包含提交、审批和结果通知                         |
| 开发方式 | 在应用项目中与 AI Agent 协作，逐章实现并检查                     |
| 所需基础 | 能运行终端命令、打开项目目录和切换登录账号；会说明业务规则       |
| 学习结果 | 理解一个业务功能如何从数据结构接到用户操作和后台处理             |

如果还没有运行过应用，先完成[开始](../get-started/)。如果经常遇到 AI Agent 理解错需求或不知道怎么检查结果，可以配合阅读[和 AI Agent 协作](../get-started/ai-agent/writing-requirements.md)。

## 要解决什么业务问题

团队需要统一管理客户订单。业务员负责录入和提交，主管负责判断是否通过；申请人不必反复询问主管，可以在应用中查看状态和通知。

这套系统中的分工如下：

| 角色   | 日常操作                       | 数据范围                             |
| ------ | ------------------------------ | ------------------------------------ |
| 业务员 | 创建订单、提交审批、查看结果   | 自己的订单                           |
| 主管   | 查看订单、通过或驳回、填写意见 | 全部订单                             |
| 管理员 | 创建账号、分配权限、配置通知   | 负责配置，不代替业务账号完成权限检查 |

一个订单会经历“草稿 → 待审批 → 已通过或已驳回”。被驳回的订单可以再次提交。每次审批结果对应一条通知，重复派发同一个结果不会再生成一条消息。

## 数据模型预览

你会创建两张业务表。账号、权限和通知使用应用提供的能力，不需要为它们另外设计一套业务表。

| 数据表                   | 保存什么                             | 与其他数据的关系                 |
| ------------------------ | ------------------------------------ | -------------------------------- |
| 客户 `tutorialCustomers` | 客户名称、联系人                     | 一个客户可以对应多张订单         |
| 订单 `tutorialOrders`    | 订单号、金额、状态、申请人和审批意见 | 每张订单关联一个客户和一个申请人 |

比如，“远山科技”是一位客户，`SO-001` 是它的一张订单。客户名称从客户记录读取，订单自身保存金额和状态。字段类型、关系和保存规则会在第一章逐一说明。

## 开始前准备

按[创建应用](../get-started/create-app)准备练习项目，安装依赖并成功登录。需要 Node.js 24 或以上、项目要求的 pnpm 版本，以及能读取应用源码和执行命令的 AI Agent。教程使用 SQLite，所有命令在应用根目录执行。

```bash
pnpm dev
```

打开终端打印的地址。页面代码中的路径相对于应用地址，不把默认的 `/main` 挂载路径写进业务路由。

本教程使用独立的表名和 `/tutorial-orders` 页面路径，不依赖快速开始中 AI Agent 生成的订单实现。即使已做过第一个功能，也从这里约定的数据模型开始，保留已有表和数据。

## 怎样跟着做

每章先理解本章目标和业务规则，再把需求交给 AI Agent。生成后亲自操作页面，检查数据和权限是否符合预期。页面样式可以不同，业务结果要一致。

按章节顺序推进，前一章的结果是后一章的起点。准备三个普通测试账号，并在权限章节分配角色；不要一直使用管理员来判断普通用户可以做什么。

完成一章后保留代码和检查结果。中途暂停时记录已经完成到哪一步，继续时打开同一个项目，无需重新创建应用或清空数据库。

## 常见问题

### 不熟悉编程，可以跟着做吗？

可以让 AI Agent 编写代码，但你需要能启动项目、描述规则和检查结果。遇到不理解的字段或文件，先让 AI Agent 解释它与业务的关系，再决定是否修改。

### 要先配置应用中的 AI 员工吗？

不需要。这里使用的是项目目录中的AI Agent，应用内的 AI 员工不是教程前提。

### 完成后就是完整的订单产品了吗？

这个案例集中在订单提交、主管决策和站内信。商品明细、库存、收付款、多级审批和完整审批历史需要根据自己的业务继续设计。

准备好后，从[建表：订单和客户](./data-model)开始。
