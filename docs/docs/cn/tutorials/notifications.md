# 5. 发通知

订单通过或驳回后，申请人需要知道处理结果，并能回到订单查看详情。本章用一个站内信示例说明如何把业务规则交给应用 Agent、确认通知入口和检查发送结果。

## 开始前准备

- 前面的章节已经搭建订单和审批流程，并能区分通过与驳回状态
- 应用使用的模板已经注册通知和站内信插件
- 准备一个申请人账号和一个主管账号，用于验证收件人隔离

本例先使用站内信，不需要配置邮箱或群机器人。通知渠道、管理员测试发送和投递日志的入口见[通知能力说明](../capabilities/notification.md)。

## 让 Agent 接入审批结果

把下面的需求交给应用 Agent，并将页面名称替换成前面章节中的实际名称：

```text
请在当前订单审批流程完成后通知申请人。

订单审批结果变为通过或驳回时，给该订单的申请人发送一条站内信，内容包含审批结果和订单编号。点击消息后打开对应订单详情。待审批、草稿和没有发生审批结果变化的订单不发送通知。

先检查当前订单和申请人字段、审批流程、通知插件和用户权限。复用应用已有的通知渠道；如果申请人还没有查看站内信的入口，请增加一个清楚的「我的通知」入口，并确保登录用户只能读取发给自己的消息。

同一订单的同一次审批结果即使被重复处理，也只能发送一条通知。通知失败时不要撤销已经完成的审批；请告诉我去哪里查看失败原因，以及什么情况下可以安全重试。

完成后用申请人和主管两个账号验证：审批通知只发给申请人，消息能打开正确订单，重复触发不会重复发送。
```

## 预期效果

申请人提交订单并由主管审批后，可以在「我的通知」中看到审批结果；点击消息后打开对应订单。换成另一个申请人账号后，不会看到第一位申请人的通知。

## 检查发送结果

1. 用申请人账号创建并提交一张新订单
2. 用主管账号审批通过或驳回订单
3. 换回申请人账号，打开「我的通知」
4. 确认消息内容和订单入口正确，再刷新页面确认消息仍然可查看
5. 换另一个申请人账号登录，确认无法读取前一位申请人的通知

管理员可以在「设置 / 通知 / 通知日志」查看通知和投递记录。工作流执行成功只说明业务流程走完；管理员还需要确认站内信已保存、接收人正确。邮件或群机器人出现结果不确定时，先查目标邮箱或群聊，再决定是否重试，避免重复发送。

## 扩展到邮件或群机器人

要增加邮件或即时通讯渠道时，先让管理员准备发件服务或群机器人，并在服务端配置凭据。然后告诉 Agent 收件人、消息内容、触发频率和测试目标。具体配置入口和注意事项见[通知能力说明](../capabilities/notification.md)。
