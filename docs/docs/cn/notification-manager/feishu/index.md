# 通知:飞书 / Lark

## 介绍

**飞书 / Lark** 插件支持应用向飞书用户发送通知消息。

## 前置条件

首先需要在 NocoBase 上添加并配置一个飞书认证器,参考[认证:飞书 / Lark](/auth-verification/auth-feishu/)。只有经过飞书登录绑定的系统用户,才可以通过飞书接收系统通知。

发送消息使用认证器对应的飞书应用,该应用还需满足以下条件:

1. 在飞书开放平台 **应用能力** 中添加 **机器人** 能力——未添加机器人时发送消息会失败;
2. 在 **权限管理** 中开通 **以应用身份发消息**(`im:message:send_as_bot`)权限,并发布新版本;
3. 接收消息的用户需在应用的 **通讯录权限范围**(可用范围)内。

修改应用能力或权限后需要发布版本并重试。

## 添加飞书通知渠道

进入 **通知管理** → 通知渠道,添加 **飞书 / Lark** 渠道,选择已配置的认证器。

可选配置 **接收人 ID 类型**(`open_id`、`user_id`、`union_id`、`email`),默认跟随认证器的用户唯一标识字段。

## 消息类型

| 类型 | 说明 |
| --- | --- |
| 文本消息 | 纯文本内容。 |
| 富文本消息 | 飞书 Post 格式的富文本。 |
| 交互卡片 | 以 JSON 配置飞书卡片(Card JSON)。 |

接收人解析顺序:用户与认证器绑定的飞书标识(按接收人 ID 类型),未绑定用户回退到邮箱或用户名。

## 工作流通知节点配置

在通知工作流节点中选择配置好的飞书渠道,即可向工作流上下文中的用户发送飞书消息。

## 故障排查

- 发送失败并提示无权限(如错误码 `230002`):检查是否已添加 **机器人** 能力、开通 **以应用身份发消息** 权限,并确认已发布最新版本。
- 发送失败提示接收人无效(`receive_id` 相关错误):接收用户不在应用的通讯录权限范围内,或接收人 ID 类型与渠道配置不一致。
- 任务失败但只显示笼统错误:查看服务端日志中 `FeishuNotificationChannel.send failed` 的记录,新版插件会同时输出飞书返回的错误码与消息。
