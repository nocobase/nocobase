# AI ビルダー クイックスタート

AI ビルダーは NocoBase が提供する AI アシスト構築機能です。自然言語でビジネス要件を記述すると、AI Agent がシステムを構築します。データモデリング、UI 構築、ワークフロー構成、権限設定から、最終的なリリースまで、一連の流れをすべてカバーします。

**画面をどう構築するか**については、2 つの方式があります：

- **AI + ノーコード Portal 構築** — AI が NocoBase のノーコード設定機能を使ってシステム画面を構築します。成果物はデータベースに保存される設定です。標準的な CRUD や社内管理画面に適しており、業務担当者が後から自分で画面上で調整することもできます
- **AI Portal 構築** — NocoBase が基盤機能（データ、認証、権限など）を提供し、AI Agent がローカルで直接コードを書きます。成果物はそのまま Git にコミットできます。ビルドしてデプロイすれば [AI Portal](./ai-portal/index.md) からアクセスできます。カスタムインタラクション、複雑なビジネスシステム、特別なビジュアル要件がある場合に適しています

どちらの方式を選んでも、データテーブル、権限、ワークフローは同じ Skill 群を使います。AI Agent はページを書きながら、データテーブルの作成や権限の設定も併せて行い、対話を通じて完全なビジネスシステムを段階的に構築していきます。

## 2 つの構築方式の選び方

上記の 2 つの方式は、それぞれ 1 つのアクセス入口に対応します。1 つの NocoBase アプリケーションは複数の入口を持つことができ、同じデータを共有します。アクセスパスを見れば、どちらの入口か分かります：

```text
/v/<name>    ノーコード Portal
/x/<name>    AI Portal
```

![two types of portal](https://static-docs.nocobase.com/20260804091849.png)

具体的な違いは次のとおりです：

| | ノーコード Portal | AI Portal |
| --- | --- | --- |
| アクセスパス | `/v/<name>` | `/x/<name>` |
| ページの作り方 | 画面上で設定し、AI が設定変更を支援 | React ソースコードを AI Agent が記述 |
| 成果物 | データベースに保存される設定 | Git にコミットできるソースコード |
| 反映の仕方 | 画面上で操作するか、AI に設定を変更させる | コードを変更し、`dev` → `deploy` |
| バージョン管理 | [バージョン管理](./version-control.md)でスナップショットを保存 | Git、または NocoBase の source storage |
| 画面の自由度 | ブロックの機能に制約され、レイアウトとインタラクションに既定の型がある | 思いどおりに作れる |
| 既製の機能 | ダッシュボード、カレンダー、カンバンビューなどのブロックがすぐに使える | 提供している標準テンプレートコードを参考にするか、AI Agent が自前で実装 |
| 習得コスト | NocoBase のブロックやフィールドなどの知識が必要 | AI Agent の使い方にある程度慣れている必要がある |
| 適した用途 | 標準的な CRUD、社内管理画面 | カスタムインタラクション、複雑なビジネスシステム、特別なビジュアル要件 |

次のようなケースでは、ノーコード Portal で十分です：

- ページ構造が非常に標準的で、通常のテーブルとフォームの組み合わせであり、設定するほうがコードを書くより速い
- コードを書かない業務担当者に、自分でページを調整してもらう必要がある
- ダッシュボード、カレンダービュー、カンバンビューなど、NocoBase 組み込みのブロック機能だけを使いたい
- 一人で構築する、または複数人での共同構築が不要

それ以外のケースでは、[AI Portal](./ai-portal/index.md) での構築をおすすめします。ノーコード Portal での構築は、AI が学習すべきコンテキストが多すぎます。ブロックの種類、設定構造、連動ルールなど、複雑な構築が必要なビジネスシステムにとっては、構築効率、保守性、複数人での協働のいずれも十分とは言えません。

そこで発想を変えました。**フロントエンドのコードを書くことは AI が最も得意とすることです**。得意なことをやってもらいましょう。NocoBase はシステムカーネルの基盤を担い、フロントエンドは AI に自由に任せます。同じ要件でも、より速く、より良い結果が得られます。**AI が自由に作り、NocoBase が信頼性を担保する。**

2 つのモードを併用することもできます。社内管理画面はノーコード Portal で素早く設定し、社外向けの顧客ポータルは AI Portal で細かくカスタマイズする。両者は同じアプリケーション内にあり、同じデータとユーザー体系を共有します。

## クイックスタート

::: warning 注意
AI Portal 構築を試す場合は、alpha 版の NocoBase CLI をインストールしてください（`npm install -g @nocobase/cli@alpha`）。
:::

すでに [NocoBase CLI](../ai/quick-start.md) をインストール済みの場合は、このステップをスキップできます。

### ワンクリック AI インストール

以下のプロンプトを AI アシスタント（Claude Code、Codex、Cursor、Trae など）にコピーすると、インストールと設定が自動的に完了します：

```
NocoBase CLI をインストールして初期化を完了してください：https://docs.nocobase.com/ja/ai/ai-quick-start.md（リンクの内容を直接参照してください）
```

### 手動インストール

```bash
npm install -g @nocobase/cli@alpha
nb init --ui
```

ブラウザが自動的にビジュアル設定ページを開き、NocoBase Skills のインストール、データベースの設定、アプリケーションの起動をガイドします。詳細な手順は[クイックスタート](../ai/quick-start.md)を参照してください。

## 会話で手動設定を置き換える

NocoBase CLI のインストールが完了したら、AI アシスタントで自然言語を使って NocoBase を操作できます。以下はいくつかの実際のシナリオです。テーブルの作成からシステム全体の構築まで、AI ビルダーの能力を体験してみてください。

### 業務要件を伝えると、AI がテーブルとリレーションを設計

どんなシステムを作りたいか AI に伝えるだけで、データテーブル、フィールドタイプ、リレーションを自動的に設計します。ER 図を自分で描く必要はありません。

```
CRM を構築しています。データモデルを設計して構築してください
```

![AI が CRM データモデルを設計](https://static-docs.nocobase.com/202604162126729.png)

AI が顧客、連絡先、商談、注文などのデータテーブルと、それらの間のリレーションを自動生成しました：

![CRM データモデルの結果](https://static-docs.nocobase.com/202604162201867.png)

データモデリングの詳しい使い方は、[データモデリング](./data-modeling)を参照してください。

### 一区切りつくたびに、AI が復元可能なバージョンを保存

ページ、データテーブル一式、またはワークフローを仕上げたら、AI に現在の状態をバージョンとして保存させましょう。設定がおかしくなっても、いつでも直前の明確なマイルストーンに戻せます。

```
現在の構築結果をバージョンとして保存してください：顧客管理ページ、フィルターエリア、編集フォームの設定が完了しました
```

![AI が構築後にバージョンを作成](https://static-docs.nocobase.com/20260611115804.png)

AI はフィールドを 1 つ変更するたびにバージョンを保存するのではなく、明確なマイルストーンを完了して検証した後にのみ保存します。これによりバージョンリストが読みやすくなり、どこに戻すべきかも判断しやすくなります。

バージョン管理について詳しくは、[バージョン管理](./version-control)を参照してください。

### 一言で自動化ワークフローを構築

業務フローのトリガー条件と処理ロジックを記述すると、AI がトリガーとノードチェーンを自動的に作成します。

```
注文作成後に商品在庫を自動的に減らすワークフローを構築してください
```

![注文在庫減少ワークフロー](https://static-docs.nocobase.com/20260419234303.png)

ワークフローの詳しい使い方は、[ワークフロー管理](./workflow)を参照してください。

### 業務用語でページを記述すると、AI が構築

NocoBase はデフォルトで **AI Portal** と **ノーコード Portal** を 1 つずつ提供しています。設定ルールを学ぶ必要はありません。検索ボックス、テーブル、フィルター条件など、欲しいページを直接伝えるだけで完成します。

![portal manage](https://static-docs.nocobase.com/20260804104517.png)

ノーコード Portal で構築する場合（デフォルトの Portal 名は admin）は、次のように伝えます：

```
admin に顧客管理ページを作成してください。名前検索ボックスと顧客テーブルを含め、テーブルには名前、電話番号、メール、作成日時を表示してください
```

![顧客管理ページ](https://static-docs.nocobase.com/20260420100608.png)

AI Portal モードで構築する場合（デフォルトの Portal 名は main）は、次のように伝えます：

```
main portal に顧客管理ページを作成してください。検索ボックスと顧客テーブルを含め、テーブルには名前、電話番号、業種を表示してください
```

![portal ページ](https://static-docs.nocobase.com/20260803204422.png)

UI 設定の詳しい使い方は、[UI 設定](./ui-builder)または [AI Portal 構築](./ai-portal/index.md)を参照してください。

## セキュリティと監査

AI Agent に NocoBase を操作させる前に、認証方式、権限制御、操作監査について理解しておくことをお勧めします。AI が適切な操作のみを行い、すべてのステップが記録されるようにしましょう。[セキュリティと監査](./security)を参照してください。

## NocoBase Skills

[NocoBase Skills](https://github.com/nocobase/skills) は AI Agent にインストール可能なドメイン知識パッケージで、AI が NocoBase の設定体系を理解できるようにします。NocoBase は複数の Skills を提供し、構築プロセス全体をカバーしています：

- [環境管理](./env-bootstrap) — 環境チェック、インストール、アップグレード、トラブルシューティング
- [データモデリング](./data-modeling) — データテーブル、フィールド、リレーションの作成と管理
- [UI 設定](./ui-builder) — ページ、ブロック、ポップアップ、インタラクション連動の作成と編集
- [ワークフロー管理](./workflow) — ワークフローの作成、編集、有効化、診断
- [権限設定](./acl) — ロール、権限ポリシー、ユーザー割り当て、リスク評価の管理
- [ソリューション](./dsl-reconciler) — YAML による業務システムの一括構築
- [プラグイン管理](./plugin-manage) — プラグインの一覧表示、有効化、無効化
- [リリース管理](./publish) — クロス環境リリース、バックアップ復元、マイグレーション
- [バージョン管理](./version-control) — 完了したマイルストーンの後に復元可能なバージョンを保存
- [AI Portal 構築](https://github.com/nocobase/skills/blob/main/skills/nocobase-ai-builder/SKILL.md) - AI Agent が AI Portal 内でコードを書いてシステム画面を構築

:::tip ヒント

NocoBase CLI は初期化プロセス（`nb init`）で Skills を自動的にインストールするため、手動でのインストールは不要です。

:::
