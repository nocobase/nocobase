# 通知：Feishu / Lark

## はじめに

**Feishu / Lark** プラグインは、Feishu ユーザーへの通知メッセージ送信を可能にします。

## Feishu 認証器の追加と設定

まず NocoBase に Feishu 認証器を追加・設定します。[認証：Feishu / Lark](/auth-verification/auth-feishu/)を参照してください。Feishu でログインしたシステムユーザーのみが、Feishu 経由でシステム通知を受信できます。

メッセージは選択した認証器の Feishu アプリから送信され、次の条件が追加で必要です：

1. オープンプラットフォームの**アプリ機能**で**ボット**機能を追加していること。ない場合送信は失敗します；
2. **権限管理**で**ボットとしてメッセージを送信**（`im:message:send_as_bot`）権限を有効化し、新しいバージョンを公開していること；
3. 受信ユーザーがアプリの**連絡先権限範囲**（利用可能範囲）内にいること。

アプリ機能や権限を変更した後は、新しいバージョンを公開してから再試行してください。

## Feishu 通知チャネルを追加

**通知管理** → チャネルで **Feishu / Lark** チャネルを追加し、設定済みの認証器を選択します。

オプションで**受信者 ID タイプ**（`open_id`、`user_id`、`union_id`、`email`）を設定できます。デフォルトは認証器の一意識別子フィールドに従います。

## メッセージタイプ

| タイプ | 説明 |
| --- | --- |
| テキストメッセージ | プレーンテキスト。 |
| ポストメッセージ | Feishu ポスト形式のリッチテキスト。 |
| インタラクティブカード | JSON で設定する Feishu カード。 |

受信者は認証器に紐づく Feishu 識別情報（受信者 ID タイプ）で解決され、未紐付けユーザーはメールまたはユーザー名にフォールバックします。

## ワークフローの通知ノード

ワークフローの通知ノードで設定済みの Feishu チャネルを選択すると、ワークフローコンテキストのユーザーに Feishu メッセージを送信できます。

## トラブルシューティング

- 権限エラー（例：コード `230002`）で送信失敗：**ボット**機能の追加と**ボットとしてメッセージを送信**権限、最新バージョンの公開を確認。
- 受信者無効（`receive_id` 系エラー）で送信失敗：受信ユーザーが連絡先権限範囲外、または受信者 ID タイプがチャネル設定と不一致。
- 汎用エラーのみ表示される場合：サーバーログの `FeishuNotificationChannel.send failed` を確認。新しいプラグインは Feishu のエラーコードとメッセージも出力します。
