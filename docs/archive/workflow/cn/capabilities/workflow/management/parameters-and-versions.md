# 参数、启停与版本

这些操作会影响后续业务运行。修改前确认目标工作流、当前版本和应用开发者给出的业务说明。

## 设置管理员参数

如果开发者在工作流中声明了参数，可以从列表或详情页的“更多操作 → 参数设置”进行修改。

参数支持字符串、数字和布尔值等少量运行配置，例如目标库存或风险阈值。输入框的占位值表示开发者提供的默认值；保存后，新运行会使用管理员设置的值，已经开始或完成的运行不会变化。

当前参数设置界面适合编辑字符串和数字。布尔参数虽然是 DSL 支持的类型，但当前界面没有对应的开关控件；需要覆盖布尔参数时，应由应用开发者提供适配的管理入口，不能在文本框中填写 `true` 或 `false` 并假设会转换为布尔值。

:::warning 注意

参数不是秘密存储。不要填写密码、访问令牌、Cookie 或其他凭证。

:::

保存前检查数值类型和开发者说明。参数必须符合源码声明的类型与枚举，否则服务端拒绝更新。

## 首次启用工作流

应用部署了新工作流后，它可能先显示为未发布、已停用状态。确认业务说明后打开启用开关，它会成为当前运行版本。

启用只改变工作流可否接受正常业务触发，不会自动产生一次运行。

## 停用工作流

关闭启用开关后，正常业务操作不会再创建这个工作流的新运行，历史记录仍然保留。手动运行是独立的管理操作，仍需按其页面说明确认版本和影响。

停用不等于撤销已经发生的业务副作用。对于已经创建的运行，应进入执行详情确认其最终状态；不要假设切换开关能够回滚数据或外部调用。

## 启用新版本

Agent 完成修改和验证、应用部署后，新候选版本会出现在管理页面。确认变更后启用目标版本，它将成为当前运行版本。

启用新版本前确认：

- 输入字段是否变化；
- 现有管理员参数是否仍然适用；
- 新节点会产生哪些写入、通知或外部调用；
- 业务触发代码是否已与新版本一起部署；
- Agent 是否提供了测试、构建和必要的运行验证结果。

旧运行不会迁移到新版本，仍保留开始时使用的版本、路径和结果。

## 常见问题

### 为什么有些工作流没有参数设置

只有开发者声明了管理员参数时，菜单才可用。每次调用输入不属于参数设置。

### 修改参数是否影响正在运行或已经完成的实例

不影响。每次运行使用启动时解析出的快照。新设置用于之后创建的运行。

### 新版本是否会自动启用

不会。部署和启用是两个阶段，管理员需要确认目标版本后启用。

### 启用新版本是否会修改历史执行

不会。历史执行保留原版本、输入快照、节点路径和结果。

### 停用是否会删除工作流或历史记录

不会。停用只阻止后续普通业务触发，定义和历史记录仍保留。
