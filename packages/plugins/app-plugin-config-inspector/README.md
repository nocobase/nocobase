# Config Inspector

Open System settings → Application configuration to inspect a running application. Both the route and its read-only API require the page grant `config-inspector/access`.

The page has three views of the same configuration. **By module** groups every running setting into modules, each field with its value, its source (config file, environment variable or code default), the environment variable declared for it, and the file value an environment variable overrides; search by title, path, value or variable, or show only the settings that differ from `config.example.yml`. **Environment** lists the variables the application declares and whether each one is set. **Full config.yml** shows the loaded file with its comments, in full or as a line diff against `config.example.yml`.

Credentials never leave the server: a value is replaced when a declared variable marks its path as a secret, when its key names a credential (`password`, `secret`, `token`, `key`, `credentials`, `webhook`, `dsn` and similar, a whole `secrets` or `apiKeys` subtree included), or when it is text that may hold one: a key with any word naming a credential (`accessTokenEnc`), an inline credential such as `--password=…`, or a URL carrying a user name, a password, a credential query parameter or a webhook path. Commented-out settings in the file are masked the same way, together with any commented-out block below one, such as a private key under `# key: |`; a file that does not parse is not shown. Switches and counts such as `maxConcurrentAuthorizations` are always shown. Files too long to diff in a browser are shown in full. The page is a diagnostic view, not a backup; to change a setting, edit config.yml or the environment and reload.
