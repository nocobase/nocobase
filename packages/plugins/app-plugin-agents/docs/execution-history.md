# Execution history

`Run.executions` contains claim snapshots in attempt order. Each snapshot preserves `attempt`, `runnerId`, `runnerName`, `runnerOwnerUserId`, `runnerOwnerName`, `runnerTrust`, `tool`, `toolVersion`, `modelService`, requested `model`, reported `actualModels`, `effort`, `dispatchedAt`, `finishedAt` and `failureReason`. Renaming or removing a runner does not change these facts. Online runs identify the application holder as `server:<instance>` and have no machine owner or coding-tool version.

`Run.runnerId` continues to mean the current holder. A retry releases it to null; `executions.at(-1)` still identifies the preceding attempt. Flat `runnerName`, `runnerOwnerUserId`, `runnerOwnerName`, `toolVersion` and `actualModels` describe the latest captured attempt in both run lists and details. Do not replace the current holder with historical data when authorizing a report.

`model` and `effort` are requested settings, not actual values. `actualModels` lists unique models reported by the primary tool in live usage events or ending reports; online model calls populate it immediately. Usage from other tools does not replace the primary model. Multiple reported models remain visible. Always label the requested and actual values separately, including when they match. An empty model array means the actual model was not reported; action badges must not substitute the requested model. Null requested models are a legacy default configuration; the default/actual wording is for these records, not a new execution configuration (explicit-model enforcement belongs to PM-88).

`actualEffort`, `actualEffortSource` and `actualEffortAt` are the latest tool report and its provenance/time, present on the snapshot and flat run view. `effortReports` retains value/source changes for that attempt. A primary-tool status event reports `meta.execution: { effort: string | null, source: string }`; its event time is the change time. Helpers, bare request metadata and reasoning token counts never establish actual effort. Repeated reports do not change the original change time; delayed older reports do not replace newer values. Null means unreported, including when an override invalidates a previously reported default. Render “Actual reasoning not reported” rather than inferring a value.

The Codex adapter reports the value returned by `thread/start` or `thread/resume`. A per-turn effort override has no resolved effort in the `turn/start` response, so that adapter explicitly reports null with source `codex.turn/start`; the requested effort remains visible. Other adapters/providers without a resolved report leave the actual value unknown. This contract needs the updated runner as well as the updated plugin.

Stored snapshots are internal facts. The agents HTTP routes apply `runForViewer`/`executionForViewer` with the same machine rights as runner routes: the snapshot's owner, runner managers, or readers of all runners who may invoke an agent. Others receive null `runnerName`, `runnerOwnerName` and `runnerTrust`, with `machineHidden: true`; the UI displays a generic team runtime and never falls back to its id. The projects viewer defaults to owner-only machine visibility; its host can supply `Viewer.seesExecutionMachine` after checking these same rights. Activities, thread pages, issue detail and comment mutations apply that projection; internal comment reads with no viewer deny machine visibility. Custom application run/CLI/workload outputs must apply the agents projection too, and action enrichment must reapply it after lookup.

Older runs have no execution snapshots. Their primary-tool usage still supplies `actualModels`, but these models cannot reliably be assigned to individual historical attempts. Do not construct historical machine names or tool versions from a runner's current configuration. The migration does not manufacture snapshots or attempt boundaries.

An application rendering UI Library's `agent-run-history` maps `executions` directly into `AgentRunHistoryRun.executions`; `execution` can supply a legacy or specific action's execution. `previousRunnerId` enables comparison with the preceding run on the same subject. `RunHeader`, the list and activity rows show these facts, and `RunAttempts` shows individual attempts. Supply `labels.execution` for translated wording. `RunExecutionBadge` accepts `href` and `onOpen` to open an originating run from an action.

For projects actions, pass the originating `runId`, `agentId` and `execution` snapshot through `Actor.trace` with `via: 'agent'`. Activities return these as `Activity.via`; comments return them as `IssueComment.source` while preserving the existing transport `via`. The projects plugin treats execution ids as opaque and has no dependency on agents. If the action precedes model reporting, its persisted snapshot remains what was known at that moment; the application may enrich the badge from an authorized lookup of the matching run and attempt, never a later retry's model.
