# Execution history

`Run.executions` contains claim snapshots in attempt order. Each snapshot preserves `attempt`, `runnerId`, `runnerName`, `runnerOwnerUserId`, `runnerOwnerName`, `runnerTrust`, `tool`, `toolVersion`, `modelService`, requested `model`, reported `actualModels`, `effort`, `dispatchedAt`, `finishedAt` and `failureReason`. Renaming or removing a runner does not change these facts. Online runs identify the application holder as `server:<instance>` and have no machine owner or coding-tool version.

`Run.runnerId` continues to mean the current holder. A retry releases it to null; `executions.at(-1)` still identifies the preceding attempt. Flat `runnerName`, `runnerOwnerUserId`, `runnerOwnerName`, `toolVersion` and `actualModels` describe the latest captured attempt in both run lists and details. Do not replace the current holder with historical data when authorizing a report.

`model` is the requested model, with null meaning a coding tool's default. `actualModels` lists unique models reported by the primary tool in live usage events or ending reports; online model calls populate it immediately. Usage from other tools does not replace the primary model. Multiple reported models are retained rather than choosing one arbitrarily. Before any model is reported the array is empty; the display can show the requested model or an unknown actual default.

Older runs have no execution snapshots. Their primary-tool usage still supplies `actualModels`, but these models cannot reliably be assigned to individual historical attempts. Do not construct historical machine names or tool versions from a runner's current configuration. The migration does not manufacture snapshots or attempt boundaries.

An application rendering UI Library's `agent-run-history` maps `executions` directly into `AgentRunHistoryRun.executions`; `execution` can supply a legacy or specific action's execution. `previousRunnerId` enables comparison with the preceding run on the same subject. `RunHeader`, the list and activity rows show these facts, and `RunAttempts` shows individual attempts. Supply `labels.execution` for translated wording. `RunExecutionBadge` accepts `href` and `onOpen` to open an originating run from an action.

For projects actions, pass the originating `runId`, `agentId` and `execution` snapshot through `Actor.trace` with `via: 'agent'`. Activities return these as `Activity.via`; comments return them as `IssueComment.source` while preserving the existing transport `via`. The projects plugin treats execution ids as opaque and has no dependency on agents. If the action precedes model reporting, its persisted snapshot remains what was known at that moment; the application may enrich the badge from an authorized lookup of the matching run and attempt, never a later retry's model.
