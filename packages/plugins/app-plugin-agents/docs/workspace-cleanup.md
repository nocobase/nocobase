# Workspace cleanup integration

Heartbeats announce `workspaces.decisions: true` alongside the report interval. New runners retain the existing `workspaces` and `remove`/`keep` exchange and additionally report `directories`, including legacy directories without a last run, with a unique `reportId`. Decisions echo the report, directory path, optional last run and last use. A mismatched or duplicate decision is not usable as cleanup authority.

Register optional `SubjectWorkspaces.resolveKeys(conn, keys)` to map application directory keys to subject ids. Return an array per key so ambiguity can be represented rather than choosing an arbitrary match. The framework verifies a current runner or saved execution history for the resolved subject. Resolution alone never proves ownership. A directory with a last run is resolved by that run first, without falling back to the directory key on failure.

Keep `settled(conn, ids)` conservative: deleted or unknown subjects and missing pull request records must not settle. The framework additionally excludes any subject with a nonterminal run. Register optional `commits(conn, ids)` to supply trusted merged pull request head commits by subject. Each item contains the repository URL used by the checkout and its full `headSha`; use the head at merge time, including for squash merges, rather than the resulting merge commit. A closed, unmerged pull request supplies no commit evidence. Never derive this evidence from runner input.

The runner checks every repository and initialized submodule against local objects. An ended workspace may discard untracked files only when tracked files are clean and every HEAD has push evidence. Missing objects or failed Git checks preserve the workspace; collection performs no network fetch. The planning check and locked deletion use the same response evidence, and a changed last run or use cancels deletion. Evidence is not written into the runner's general pushed-commit record.

The runner reports its local cleanup result against the prior decision before attempting deletion. The server accepts it only while the prior report id, directory, run, last use, settlement and commit evidence still match. `allowed` means permission to attempt cleanup, never proof that a directory was removed. A missing directory in a later report is likewise not a deletion receipt.

Runtime views expose `canSeeMachine` using the existing machine-information permission. Without an explicit true value, clients hide directory diagnostics. The disk summary remains subject to the existing aggregate visibility. Display the report's `measuredAt` and interval, not heartbeat time; offline or expired readings are previous reports, and unknown disk data never implies healthy space. Low disk warnings already flow through the runner collection logger; deployments should verify those service logs are visible.
