# Notification template directory design

The supplied long notification screenshot is an information reference: retain business classification, trigger, recipients, channel information, actual message languages, original content and variables. Do not reproduce its repeated full-height message panels or invent its ticket scenarios. The directory uses a compact toolbar (search plus category and channel selects whose labels sit inside the trigger and whose values show display names), template cards grouped under category headings, and a right-side drawer for the selected template. The whole card opens it. The host keeps selection in its URL (`/settings/notifications/templates/:templateId` in the templates), owns the page header and permission-protected route, and reuses its existing Notification management module.

Components are plugin-owned shadcn base-nova `Button`, `Input`, `Select`, `Badge` and `Sheet` under `client/components/ui`, generated with the package-local registry configuration. Their foundations are Base UI, `class-variance-authority` and `cn`. The directory composes these primitives; semantic lists, headings, definition lists and preformatted source need no interactive primitive. Theme colors and spacing use host tokens. Desktop cards use a responsive grid; narrow layouts stack filters, cards and preview content. Text wraps and source panels have bounded independent scrolling.

Copy is written for administrators: a detail shows who provides it, when it is sent, who receives it, sending conditions, delivery channels with set-up/on state, language and the preview with fictional sample data, then variables. The template with placeholders, the HTML version and technical identifiers (template ID, package, channel names) are collapsed. Registrant text is translated in the browser from translation keys. A message that combines every language hides the language choice; otherwise the preview language follows the interface language and lists language names. HTML is inert escaped source, deliberately avoiding a second rendering engine and external requests. Interface translations do not change authored scenario metadata or invent message translations. The example task renderer remains English-only. Invitation messages retain all ten language blocks and an English subject.

The public block mounts through a lazy host page and a leaf `client/templates` export. No edit, toggle, save or test-send action is present. Empty registry, no matching scenario, denied access, missing detail and retryable failure are distinct states. Unauthorized API results clear the data surface; preview callbacks accept no user-supplied business values.

Acceptance checks cover desktop and narrow English presentation, real directory reads and synthetic preview, category/channel/search filtering, visible missing configuration, navigation to the existing module, direct API denial, no remote HTML resources and no writes/sends from browsing. Package tests cover strict request input and source registration lifecycle; runtime and screenshot evidence is recorded in the delivery report.
