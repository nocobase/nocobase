# Move a development snapshot to dedicated demo environments

This is a breaking change to the unpublished snapshot, not an in-place production rollout. Keep the earlier plugin/app build available until the application adapter is updated and verified on an isolated database.

1. Confirm separate database, storage and credentials for the demo deployment. Mode `off` disables management and simulation; never switch an instance holding demo data into production use.
2. Replace `clearAll` plus scoped `clear` with one required `clear(context)` that clears all business tables/files/caches, preserves system identities/configuration and tolerates empty/partial context. The same function is used after failed imports. Do not merely rename a scoped cleanup and claim it clears the instance.
3. Remove `keepAccounts`. Account disable/reuse is now unconditional. Keep `roleScopes`, ownership checks and application authorization.
4. Remove model-default backup/restore code. The model is provisioned in the plugin provider's `ready()` phase and survives data operations. Application-owned Agents with explicit model selections must be configured for the environment model after it is ready; importing business rows must not install or remove model services. The plugin supports Agents 1.0 only: it uses `agents.models.services`; there is no host adapter and no fallback to older `agents.online.services`. Replace `runLegacyOnlineConversation` with `runOnlineConversation` around OnlineAgent session operations ([model simulation](simulation.md#online-conversation-persistence)).
5. Remove deployment reset cron variables and `demoMode.data.reset`. Remove `legacySchedule`, `replaceLegacy` and the old data-status `reset` field from application UI/config schemas. Configure the one daily schedule through `/demoMode/configuration/schedule`. Remove the old `demoMode.resetData` schedule from any existing Scheduler storage before enabling the new schedule.
6. Register Demo Agents with `{ id, title, defaultEnabled, execute }`. Remove proxy `scope`/`matches`; call `prepare()` without an argument. `run` selects by server environment mode. Direct `execute` still refuses when demo mode or that adapter is disabled. Keep normal authorization and table/operation write rules.
7. An incremental migration adopts an existing per-import model binding into the environment binding before startup; its model name and credential are preserved. Validate on a database copy first, back up database/storage/configuration, and retain the previous image for rollback. A fresh disposable database remains an option for adapters that cannot upgrade their own business state. Never reset a database merely to upgrade the plugin.
8. Verify startup before import, import, visitor-created data, clear, reset, interrupted import, account reuse, model identity/key persistence, disabled mocks, and mode-off refusal. Run the application's owning type checks and affected tests before replacing its vendored plugin.

## Application-scoped deployment configuration

Register `defineDemoModeConfig()` from `@nocobase/app-plugin-demo-mode/config` in the application's `defaultAppConfigs({ demoMode: defineDemoModeConfig(), ... })` map. Keep the Server plugin registration too. Configuration factory registration is required for environment mappings and validation; the plugin no longer reads `process.env` itself.

Rename the old `NOCOBASE_DEMO_ALLOW_TABLES` variable to `NOCOBASE_DEMO_WRITABLE_COLLECTIONS`; replace physical table values with logical collection names and rename the YAML field to `demoMode.allowCollections`. Remove `NOCOBASE_DEMO_QUICK_SIGN_IN`, `NOCOBASE_DEMO_DATA_MODELS`, `NOCOBASE_DEMO_DATA_MODEL_BASE_URL` and the old `demoMode.data` section. Set `demoMode.quickSignIn` in application configuration when needed. Use the settings UI's dataset model toggle, online-chat toggle and model selection for usage policy. The local simulated endpoint is automatic; configure real model endpoints and credentials through Agents model services. Old model deployment controls are no longer read. Existing persisted model bindings and UI policies remain intact.

Replace preview `NOCOBASE_DEMO_WRITABLE_TABLES` as well. Update capability registrations from `table` to `collection`, UI fields from `tables`/`fixedTables` to `collections`/`fixedCollections`, and the API path to `/collections`. GET now returns `{ name, title? }` items. Startup converts previously saved physical-table selections through the default connection metadata; an unresolved old selection produces an actionable error instead of silently granting or dropping access.
