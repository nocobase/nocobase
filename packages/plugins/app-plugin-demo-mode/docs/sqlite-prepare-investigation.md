# SQLite prepare-path investigation

This is a static investigation performed on 2026-10-29 while the Demo Mode formal comparison was frozen at production commit `7cc61197c940070fedbebeb53e83d7ba92215b9d`. It does not implement a statement cache, modify the measured code or instruments, or report a new measurement. The installed dependencies inspected here are `better-sqlite3` 13.0.3 and Knex 3.3.0; the workspace driver is `@nocobase/db-sqlite` 0.1.0-beta.6.

## Actual source chain

The driver's [`createKnexClient`](https://github.com/nocobase/nocobase/blob/7cc61197c940070fedbebeb53e83d7ba92215b9d/packages/libs/db-sqlite/src/index.ts#L129) uses `preciseIntegerClient(BetterSqlite3)`. Its [`_query` override](https://github.com/nocobase/nocobase/blob/7cc61197c940070fedbebeb53e83d7ba92215b9d/packages/libs/db-sqlite/src/precise-integers.ts#L56) calls `connection.prepare(query.sql).safeIntegers(true)` on every query. For readers it obtains `columns()` before `.all(bindings)` and converts big integers using the declared column types. Other queries use `.run(bindings)` and preserve `lastInsertRowid`/`changes`. There is no prepared-statement reuse map in this path.

The inspected installed Knex sources are `knex/lib/dialects/better-sqlite3/index.js` and `knex/lib/dialects/sqlite3/index.js`. The former also prepares each `_query` independently and closes the native connection in `destroyRawConnection`. The inherited `_stream` first awaits `_query`/the full result and then writes rows to the stream; it does not use a native statement iterator. The application's transaction path goes through Knex and the driver's existing failed-commit rollback adapter.

## Correctness and bounds

A statement cache would lengthen the interval between prepare and execution. SQLite may reprepare at execution after DDL, including changes from another connection. Reading column metadata before `.all()` would then risk using old names/types for integer conversion even though the native row builder updates its own keys. A candidate must address execution-time metadata, zero-row results, `RETURNING`, view/column changes and schema changes outside the metadata registry. No current failure reproduction is claimed by this static observation.

Other required boundaries are physical-connection ownership and disposal, transactions/savepoints and failed-commit rollback, native busy/reentrant callbacks, externally opened iterators, DDL/PRAGMA/ATTACH/raw operations, errors and connection close. A cache must not retry an uncertain write after an error. Registry invalidation and native statement invalidation are different mechanisms.

An entry-count and SQL-text-size limit bounds strongly referenced cache entries and keys. It does **not** bound native statement bytes: eviction only drops a JavaScript reference, and this public API provides no deterministic per-statement finalize. Native allocations, queued finalization and compiled-statement complexity require separate evidence. Repeated SQL, a simulated cache hit rate, the destructor path, and the difference between RSS/V8/external counters do not establish ownership of a measured memory peak.

## Decision and deferred diagnostic

No statement cache is included in this PR, and no SQL diagnostic resource window was requested. A possible future investigation would count actual prepares per physical connection and simulate a strictly bounded 32/64-entry hash cache without retaining statements, SQL text, bindings or rows. Scalar synchronous-boundary memory observations and natural GC events could locate prepare repetition within one complete application reset. It would use no forced GC or allocation-profile reads. Such a diagnostic would establish only repetition and phase correlation, not native-memory attribution or improvement.

Only after evidence supports a candidate would a separate implementation need correctness tests for the boundaries above and a profiler-free full-application pilot. A conditional design could limit entries and SQL bytes per physical connection, keep statements private, avoid reuse while busy, invalidate on uncertain schema/state/error boundaries, and preserve the original error without replaying DML. A strict native-byte budget cannot be promised merely by calling that design bounded. The current Demo Mode fixture result and the negative/mixed CRM narrow-clone pilot remain separate from this investigation.
