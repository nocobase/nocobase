# 邮件插件完整测试清单

本清单按功能整理，共 15 个功能模块、41 个子模块、192 条用例。每条用例都有名称、编号、操作步骤、预期结果和实际验证结果。

## 阅读与使用

先阅读子模块的准备要求，再按用例逐步操作，并对照预期结果记录实际情况。编号用于关联问题和复测记录；名称说明要验证的功能。

优先级沿用原清单：核心表示优先验证，重要表示主要功能，增强表示体验改进；原清单未标注的项目记为“待评定”。涉及后台故障、授权安全或数据库维护的用例，操作步骤会明确要求测试人员或管理员配合。

实际验证结果目前均为“待验证”，因为尚未提供执行记录，本次也没有运行产品测试。填写结果时使用“通过、失败、阻塞、不适用、待验证”，并补充实际现象、测试版本、邮箱服务、执行人、时间和证据链接。不能把预期结果直接作为通过记录。

Gmail、Microsoft 和 IMAP/SMTP 邮箱应分别记录结果。“邮箱服务已接受发送请求”不等于“邮件已送达”；涉及收到邮件的验证，应检查受控收件箱。“结果未确认”需要进一步核对，不能直接判为成功或重复发送。

## 执行准备

- 准备普通用户 A、普通用户 B 和管理员，并明确各自权限。
- 准备三类可用邮箱服务，以及尚未配置和已停用的服务。
- 准备正常、暂停、需重新授权、已撤销授权、连接中和删除中的账号。
- 准备多个账号、同一服务下的多个邮箱，以及重复绑定测试资料。
- 准备收件箱、已发送、草稿、垃圾箱、垃圾邮件、归档和自定义文件夹。
- 准备已读、未读、星标、待办、备注、标签、附件、富文本和纯文本邮件。
- 准备同一会话、不同会话、无会话编号及同主题邮件。
- 准备主发件地址、可发送和不可发送别名、多个签名和模板。
- 准备 0、1、100、101 个受控收件人，以及混合分隔符、重复和错误地址。
- 记录主题、正文及附件的实际限制，准备限制内、恰好到达限制和超限的数据。
- 由测试人员准备授权失效、同步进度过期、服务错误、超时、断网和重复通知场景。
- 删除及永久删除用例使用专用测试数据；组织、部门和成员范围不作为当前测试前提。
