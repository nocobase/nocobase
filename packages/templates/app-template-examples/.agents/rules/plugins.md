# Demonstration plugins

Read this before working with the Mail, Mail Example and OnlineAgent demonstrations this template registers.

Mail and Mail Example are registered here with three offline providers in `server/config/mail.ts`. Open `/mail-example` to prepare the demo accounts and messages. These fixtures use `@example.test` addresses and never send mail to external services; keep this example out of Default applications. The Mail plugin's synchronized Skill describes its public integration contract.

## OnlineAgent example

Agents is registered in the CLI, server and client composition roots. Reuse its public `agentsRoute`, `runtimesRoute` and `modelsRoute` under the application-owned Agents navigation group. Preserve `/agents` and `/runtimes` with their matching page grants, including the `/runtimes/connect` child for registration. Preserve `/models` and its `settings:agents.services` read permission; model mutations require `manage`. Page access does not grant agent or team-runtime management: the plugin still checks `agents.agents`, `agents.runners` and runtime ownership. Do not substitute settings grants for page grants or deep-import plugin pages.

The application integration lives in `client/components/online-agent/` and the installed Registry UI in `client/extensions/nocobase-agent-chat/`. Header, keyboard shortcut and homepage share one authenticated `ChatProvider`. Keep the identity reset: the SDK panel storage key and query cache are not user-scoped. Reset before mounting a new user's provider, dispose old subscriptions, and never reuse Default's configuration or database. The panel's model readiness gate disables only native Send, not Runner Send, drafts, history or Stop. Runner sending uses the selected Agent or bound conversation availability. Revalidate the chat catalog when opening the panel and on window focus; a request failure is not an empty catalog.

Runner chat also needs this application's branded business CLI. `package.json` declares `nocobase-examples`; `server/config/agents.ts` aligns its served package while preserving the application-name Runner identity. Keep these names and the default run credential path aligned. Build it with `pnpm nocobase cli build --universal` (Node.js 24+ on the execution machine), or bundle Node.js with a platform build, before Runner chat. Serve it from `storage/runners/dist`; do not commit archives, substitute the development CLI, change an existing registration identity, or add automatic heavyweight packaging to `postinstall`. See [the CLI setup](../../online-agent.md#build-the-application-business-cli).

Use the SDK's `useConversationActions` under the identity's `ChatProvider`; its Provider lifetime guards asynchronous command results and retained Undo actions. Archive Undo must still work after its row leaves the list, while old-account callbacks must neither write cache nor initiate another request. Keep the composer's body mounted across mobile/desktop transitions and mobile close/reopen; delayed upload completion must recheck current readiness before accepting a message.

The minimal chat example uses the built-in `online` Agent and an enabled offered chat model, without a Runner, custom Agent, tools, Skills or automatic resend; the separate AI form demonstration explicitly selects its application-owned proposal tool scope. Shared stream recovery is optional and managed by the plugin. Configure credentials through Models, never client code or `config.yml`. [OnlineAgent usage](../../online-agent.md) describes setup and verification boundaries. The application-owned HTTP model fixture in `tests/fixtures/online-agent-model.ts` verifies the real standalone server without external requests or real credentials; it is not evidence of real-provider connectivity.

## AI form assistance

Keep `/ai-form-fill`, its homepage/navigation entry and localized UI local to Examples; this business demonstration is not a framework feature to copy into Default. The page is authenticated with an explicit `authz: 'skip'` because it edits only a browser draft and has no saved business records or separate page grant. Adding real record access requires independent server permission checks; UI context never grants record/tool access. Setup, ownership and verification commands are in [AI Form Fill](../../online-agent.md#ai-form-fill-browser-drafts-only).

The Agents plugin owns generic open `context.ui.items`, exact SDK tool-name renderer registration and `AIFormRegistry` helpers. Examples owns `shared/ai-form-fill.ts`, `server/providers/ai-form-fill.ts`, `client/pages/ai-form-fill/` and the proposal card/editor in `client/components/online-agent/`. Register `examples_form_proposal` through the existing `agentsToken.onlineAgent.configurator` and select only the named `examples-form-fill` Native scope; never add this tool to the plugin's default/global tools or claim Runner executes browser callbacks. Retain the tool's strict schema and explicit minimal `public.input`/`public.output`; SDK `toModelOutput` is not the public projection API.

Preserve one `ChatProvider`. Its keyed authenticated lifetime must also own the form registry and `AIToolRendererProvider`, covering both page and shared panel; keep the existing panel/cache reset and readiness logic. The renderer map uses `AIToolRendererProps`, preserves SDK state/error/approval semantics and leaves unknown tools on the normal fallback. Renderer providers inherit/override exact keys; nested form registries are isolated. Do not share registry instances across identities.

`useAIForm` returns a ref callback for `<form ref={ref}>`, not `{ ref, context }`. Registration, selecting message context and allowing an Apply action are separate decisions. Register safe fields with `useChatUIContextSource`, expose `registry.snapshot(id)` through its side-effect-free async reader and select it only from explicit user intent with `sources.selectUI`. The installed composer must await `sources.snapshotUI()` at Send before `buildPageContext`; registering `uiSources`/rendering chips alone must not upload values. Keep non-form UI kinds open and separate from authorized business `context.items`; reject invalid/over-budget JSON rather than trimming it, and explicitly exclude secrets.

Apply only from the card's exact server-linked source: assistant `metadata.sourceUserMessageId` plus the same conversation and one matching loaded user message. Registry supplies `context.sourceMessage` and its saved `context.sourceContext`; if the source/linkage is missing, disable Apply. Never use the latest user message, current composer selection or model-provided allowed ids. Validate output and final edited values, compare id/instance/identity/revision with that source, then call `registry.apply` with a stable conversation/message/tool operation key. Preserve read-only fields, unknown-field/path rejection, live-instance checks, revision conflicts, repeat-click deduplication and honest applied/partial/failed results. Record A→B→A and manual edits after Send must invalidate old proposals.

Adapters advance revision synchronously on every draft mutation. Async preparation must honor `signal` and check `isCurrent()` immediately before a synchronous browser commit, not before an intervening await. Third-party setters are not automatically transactional: adapters own atomicity/rollback, truthful partial results and safe cancellation. Dismissal, mount, history and reconnect never call the setter. Local Apply never submits/saves a record, calls a business write endpoint, emits fabricated SDK output or uses `addToolOutput`/continuation; the proposal tool is already complete.

Use the form-specific component/logic/browser entry points in [verification](../../online-agent.md#focused-form-verification), with disposable configuration, databases, storage and local model fixtures. The browser server loads built `dist`; rebuild first and launch its source fixture with `node --experimental-import-meta-resolve --import tsx tests/fixtures/online-agent-browser-server.ts` so `agentsToken` resolves from the same deployed package as the built application. Do not replace this with a workspace-source token, restart someone else's run or treat a skipped browser test as acceptance. Report its actual printed `Local:` application URL, not an inferred Vite/default port.

The Users plugin's Skill covers user administration and application-owned role assignment. Registering, updating and customizing plugins in general is covered by [plugins](../skills/nocobase-app-development/references/plugins.md).
