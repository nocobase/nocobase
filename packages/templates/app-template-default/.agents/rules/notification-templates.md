# Notifications

The notification plugins own every notification page; the application only registers them. `@nocobase/app-plugin-notification/client` adds System settings › Messages › Notifications (channels, notification kinds and delivery records, for the `notification` settings item's `read`; testing a channel and retrying a delivery need `manage`) and Personal settings › Messages › Notifications (each person's channel choices per kind). `@nocobase/app-plugin-notification-in-app/client` adds the `/inbox` page and the header's inbox button. `@nocobase/app-plugin-notification-web-push/client`, when registered, adds the browser push devices section and column to the personal page. Do not copy these pages into `client/pages/` or `client/extensions/`.

Send to people with `notify(kind, { to: userIds, data, target, idempotencyKey })` from the notification service after registering the kind with its channel policies; read the installed Notification Skill's `references/template-directory.md` for kind registration, previews and coverage. Keep `send()` for addresses that are not users, such as an operations group or an external mailbox.

Customize in this order: plugin options (such as `notificationInApp({ headerButton: false })`), then the plugins' extension points (entry renderers and pending sources for the inbox, channel type views and personal sections for the settings pages), and only then `routeComponentOverrides` with the route id of the page to replace: `@nocobase/app-plugin-notification-in-app:inbox`, `@nocobase/app-plugin-notification:notificationSettings` or `@nocobase/app-plugin-notification:notificationPreferences`.

For an existing application, follow the installed upgrade Skill's version-selected workflow and `references/notification-template-upgrade.md`: delete the copied inbox block, the inbox page and the notification template page with its routes, register the plugins, and move any custom inbox renderer or source into the extension points. Retain custom kinds, grants and data.
