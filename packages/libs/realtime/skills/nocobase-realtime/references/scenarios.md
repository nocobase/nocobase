# Business scenarios

| Scenario                            | Announcement                                                           | Authoritative recovery                                        | Polling decision                                                                                                               |
| ----------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Task/approval board                 | Committed creation, assignment and status changes                      | Authorized list/detail API; invalidate the right query prefix | Low-frequency reconciliation for failed announcements; stop active-job reads at terminal state                                 |
| Personal inbox                      | Owner-scoped invalidation after durable notification/read-state writes | Notification plugin's inbox and unread-count APIs             | Reuse its refresh hooks; do not create another notification store                                                              |
| Background CSV export               | Persisted queued/running/progress/completed/failed state               | Owner-only export history, progress and download endpoints    | Reconcile running jobs; keep files and restart recovery in the jobs/business service                                           |
| Mail synchronization                | Start, progress, empty completion, failure, retry, cancellation        | Owner's persisted synchronization run                         | A changed-message event alone cannot report an empty successful run                                                            |
| Knowledge indexing                  | Committed chunking changes and optional external indexer callbacks     | Persisted space/document state plus indexer status            | Keep status polling when the external indexer supplies no notification; partial failure does not mean all pending work stopped |
| Agent output/session transcript     | Last persisted revision or sequence                                    | Fetch records after the saved cursor; deduplicate by sequence | Retain bounded reconciliation; never coalesce individual log entries or use event IDs as cursors                               |
| Approval/lifecycle execution        | Committed transition invalidation                                      | Current record, history and effects API                       | Time-due effects or out-of-band configuration may still need a timer                                                           |
| Computer presence/deployment health | Available lifecycle notifications                                      | Heartbeat expiry or external host probe                       | Keep time-based reads: time can change the answer without a database write                                                     |
| Permission revocation               | Policy invalidation/session control                                    | Reauthorization plus the protected HTTP endpoint              | Clear forbidden data; do not keep retrying 403 or show a pre-revocation late response                                          |

The Examples application's Realtime plugin provides tasks, personal inbox and persisted CSV exports, plus a capability lab for subscription denial, pause/resume, coalescing, reconnect and resource permission changes. The Office Flows example demonstrates lifecycle invalidation. Its source plugin is `@nocobase/app-plugin-realtime-example`; install/register examples only when the user requests demonstrations. Production features belong in their owning application or plugin.

Choose invalidations for lists and snapshots, persisted cursors for ordered logs, and complete versioned snapshots for replaceable progress. Distinguish transient announcement retry from repeating the underlying business mutation. Removing polling requires producer coverage and a recovery path for publication failure, disconnected clients and external changes.
