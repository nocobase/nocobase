# S3 and compatible storage

Use `driver: 's3'` for Amazon S3 or a service that implements the S3 API. Native Aliyun OSS credentials and ECS RAM roles use the separate [`oss` driver](oss.md).

## Configure a disk

The standard application configuration includes an empty disk named `s3`. Set its bucket and choose it as the default in `config.yml`:

```yaml
drive:
  default: s3
  disks:
    s3:
      driver: s3
      bucket: your-bucket
      region: us-east-1
      visibility: private
      supportsACL: false
      credentials: {}
```

This example uses the AWS SDK's default credential chain and bucket policy rather than object ACLs. Set the region to match the bucket. These options can also be declared under `disks` in `server/config/drive.ts`, using `defineAppConfig` and `AppDriveConfig` as in the [filesystem example](fs.md#configure-a-disk).

The application Provider removes only the object-configured `s3` placeholder when its bucket is empty. Do not select that placeholder as the default until its bucket is configured. Other disk names are not filtered this way, and a factory named `s3` is preserved.

## Credentials and compatible endpoints

`credentials` is a required object, even when empty. If both `accessKeyId` and `secretAccessKey` are non-empty, the adapter passes that explicit pair to the AWS SDK. Otherwise it omits explicit credentials and lets the SDK resolve its default chain. Supply both fields together when using static credentials; a partial pair falls back to the chain rather than reporting a configuration error.

For an S3-compatible service, configure its endpoint and signing region. This example assumes a service that expects path-style requests:

```yaml
drive:
  default: objects
  disks:
    objects:
      driver: s3
      bucket: your-bucket
      region: us-east-1
      endpoint: https://objects.example.com
      forcePathStyle: true
      supportsACL: false
      visibility: private
      credentials:
        accessKeyId: your-access-key-id
        secretAccessKey: your-secret-access-key
```

Use the endpoint, region, and addressing mode required by the service. Keep real credentials in deployment configuration rather than committed source. This disk configuration exposes a static key pair, not arbitrary AWS client options or a `sessionToken` field. For temporary credentials, use the SDK's default chain or a [custom factory](custom-drivers.md) when you need to supply a custom SDK client or credential provider.

| Field              | Meaning                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `driver`           | Required literal `s3`.                                                                                                                     |
| `bucket`, `region` | Required bucket name and signing region.                                                                                                   |
| `credentials`      | Required object; empty for the default credential chain, or a complete explicit key pair.                                                  |
| `visibility`       | Required `private` or `public`.                                                                                                            |
| `endpoint`         | Optional S3 API endpoint.                                                                                                                  |
| `forcePathStyle`   | Optional addressing mode; the adapter leaves the SDK default when omitted.                                                                 |
| `supportsACL`      | Whether object ACL operations are used; the Flydrive default is `true`.                                                                    |
| `cdnUrl`           | Optional base for public links; it does not change API requests or signed URLs. Use a trailing slash when the base includes a path prefix. |
| `encryption`       | Optional server-side encryption algorithm forwarded to S3 writes, such as `AES256`.                                                        |

## Visibility and URLs

Set `supportsACL: false` when the bucket or service does not accept object ACLs. The driver then omits ACL headers on writes, reports configured visibility, and makes `setVisibility()` a no-op. Actual access is controlled by the service's bucket policy. With ACL support enabled, visibility operations make ACL requests and require the corresponding permissions.

`getUrl(key)` constructs a public link using `cdnUrl` when configured, otherwise the endpoint or S3 URL. It neither makes an object public nor signs the URL. For private objects, use `getSignedUrl(key, { expiresIn: '5 mins' })`; `getSignedUploadUrl()` creates a temporary upload URL and accepts options such as `contentType`. The client must be able to reach the API endpoint used for signing. A public CDN does not make an internal signed endpoint reachable.

## Verify

Use a disposable prefix to check upload, download, metadata, and deletion with the intended credentials. Test listing or copy/move if the feature uses them. Open public or signed links from the client's network, and check signed uploads with the actual request headers. Filesystem fakes cannot verify S3 permissions, addressing mode, ACL compatibility, or network reachability.
