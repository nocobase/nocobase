# Personal task workspace

`/my-issues/owned` and `/my-issues/executing` share the personal workspace, titled **My tasks-α** (Chinese: **我的任务-α**). The two scopes retain the Projects plugin's existing fixed owner/executor filters and permissions. Tasks (`/issues`) is still an independent page. The single personal navigation entry uses the existing `pm-my-issues` page grant. `/follow-ups` is an authenticated legacy alias that replaces the URL with `/my-issues/owned`, retaining the complete query and fragment; `tab=following|mine` names a workspace partition, not an owner/executor scope.

## Following and navigation

Following remains the existing explicit star operation, persisted by the follow-ups service with its five-item limit, saved order, authorization and seen markers. Missing or malformed following preferences are an empty collection. Owned blocked/review tasks are no longer automatically followed; existing stored choices are preserved without guessing their origin. The CLI's `follow-up` commands and response contracts stay compatible.

Initial reads show loading or an error with Retry. Ordinary failed background reads keep the last valid workspace and expose the error. A confirmed overview 401/403 immediately unmounts active task content and actions, including the full-detail outlet, without waiting for each independent detail query to fail. Follow buttons also stop accepting operations after such a denial, even with successful cached overview data. Session draft hosts remain mounted; draft-return buttons open only local input and attachment names with sending unavailable. Follow/unfollow does not modify the overview until the server acknowledges the write. A successful first follow selects that task. An acknowledged removal of the selected followed task chooses the first remaining saved item; the last removal returns to the full task region. Task filters do not modify the following collection.

`issue=<id or identifier>` selects workspace content independently of the task list's search, filters, sorting and view. User selections and partition changes push history entries; removal/permission fallbacks replace the invalid selection. A valid non-followed task remains a temporary selection; reading it does not follow it. Explicit full-detail links use the current owned/executing child route, preserving the query and fragment and native modifier-click behavior. Full-detail routes hide the inline conversation so only one visible conversation marks updates seen.

## Layout and drafts

The workspace measures its own content width, including the effect of the sidebar. The provisional three-column budget is 69rem: a 12rem following rail, at least 30rem for reading/replying, at least 24rem for the task table and theme gaps. Below that budget, and for explicit/saved non-table views, Following and My tasks are separate reachable partitions. Selecting content presents a clear Back control. These sizes require rendered verification in Compact and Spacious, light and dark, around the threshold and at 375px; they are not certified by component tests.

The following rail receives a current task only while its content is actually displayed. A narrow list-only partition retains every unread badge and has no `aria-current` row, even though the workspace keeps a deterministic first-task fallback internally.

The preview's return control does not determine whether its summary starts folded. Only the actual phone breakpoint does: a full-width desktop temporary preview keeps its following and full-detail actions visible, while phones retain the existing expandable summary bar.

The personal task outlet keeps the same container across following changes. It uses the complete existing IssuesView, rather than the legacy capped owner-card list. Each workspace content region isolates vertical overscroll; horizontal scrolling remains native. Panel scroll positions are held in this workspace session. The table retains its own scrolling and query controller.

`IssueDraftProvider` keeps session-only ComposerSession instances keyed by task ID. Lightweight hosts keep the original Projects `useAttachmentUploads` mounted across panel changes without mounting hidden detail queries or marking those tasks seen. The composer consumes that session for content, mode, pending submission, reply target and folded/open state. Draft-return buttons remain after closing content or removing the last follow. A denied/deleted task hides cached task content and offers only the user's retained draft with sending unavailable. Leaving the personal page or changing viewer releases this session; there is no persistent preference, browser storage or cross-refresh draft recovery.

## PM-336 integration

PR #10844 consumes the published PM-336 PR #10830 commit `bc5cc3a20225fe7dd0aa0f64a6dc71399ef2b865` through a history-preserving merge. Its authorized `taskTrees`/`taskTrees/children`, generation, pagination and attention semantics remain unchanged. Later PM-336 fixes must be synchronized sequentially; this dependency does not imply acceptance or remote merging of either draft PR.

Both personal scopes use the same `IssuesView → GroupedIssueListView → IssueTable` as Tasks. `IssuePresentationContext` supplies optional `compact`, `onPreview`, `rowAction` and `selectedId`, plus `reportPage` for the real `IssuesPage.view` and semantic `queryIdentity`. The identity contains the resolved view, fixed/URL filters and viewer permissions, excluding workspace selection/partition and fragment. Internal grouped scope/query keys stay private. The workspace no longer resolves views itself: first-visit table, saved choices and explicit URL priority come from the shared controller. Standalone Tasks retains full-detail row navigation and the original full table; flat trash remains in `list-view.tsx`.

The compact table combines identifier/title, retains status, attention/progress and group/parent disclosures, and adds the original follow operation. A keyboard-accessible portalled information popover shows priority, owner, executor, updated time and labels. A header popover exposes all existing table sorts; the current field/direction remains visible. Plain row or identifier activation temporarily previews without following. Native modifier links retain the full scoped href, query and fragment. Disclosure, information, sort and follow controls do not navigate. Compact indentation is capped at three levels to keep the reading space usable; the tree remains fully expandable. The same mounted grouped controller retains expansion, loaded child pages and scroll when selection or column presentation changes.

The overlapping personal container was merged by section, retaining `TableCreateStateContext`, `useTableCreateState().report/visible`, the loaded-table/empty-state creation policy, `IssueDraftProvider` and upload hosts, PhoneBar, hash-preserving scope tabs and the workspace. No endpoint, protocol field, schema, migration or persistence was added by the presentation integration.

## Verification still required

Browser tooling passes actual functions to `Locator.evaluate`; a string containing an arrow expression returns the function value rather than invoking it with the element. Column checks collect content width, computed rem/69rem threshold and rendered columns together, attach the measurements and print them on failure. Scroll checks require a real bounded ancestor and fail if none exists, rather than substituting absent dimensions. The standalone geometry regression renders synthetic DOM only; it verifies these browser callbacks, not Studio interaction acceptance. Workspace e2e cleanup runs in `afterEach`, so a cleanup request after an exhausted test deadline cannot replace the original failed action. Named steps and bounded action deadlines retain the original failure location without extending test timeouts.

Before acceptance, independently review the integration and verify real desktop/narrow UI, keyboard focus, reduced motion, modifier links/history, Chinese IME, long titles, large feeds/task collections, empty personal results with existing follows, permissions, input/menu visibility and independent scroll in both theme presets/color schemes. Include failed first/last saves, quota, refreshed invalid selection, live updates, group/parent disclosures, draft attachments and only-current-panel seen requests. CLI-only agent runs cannot produce authenticated browser screenshots; component/model tests do not replace these checks.
