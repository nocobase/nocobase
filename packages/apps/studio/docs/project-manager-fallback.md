# Project manager fallback

The project manager settings expose `fallbackAfterSeconds` (default 120, integer 1–3600). Only runs whose agent id is `studio-project-manager` register an ordered model selection policy. Delegated agents keep their existing model-selection rules and are not reassigned before their separate queue timeout.

Every queue episode persists `queueEnteredAt`; eligibility starts at `max(queueEnteredAt, availableAt)`. Merging input leaves the queue episode intact. Requeueing resets it, so delayed execution and retry backoff do not consume the delay. Existing queued rows are backfilled in bounded batches by `202610120002_ag_add_queue_entered_at`.

The runner's existing claim poll triggers selection. Before the threshold, a compatible first-choice runner reserves priority even when busy. After it, a fallback may claim using its request's actual free capacity. With no compatible first-choice runner, a fallback may claim immediately. Without an idle fallback, the original run remains queued and the first choice can still claim. A threshold can be followed by one polling interval of delay.

Selection rechecks the current queue episode under the existing agent lock and guarded queued-to-dispatched update. Assembly, admission, capacity, identity and policy checks still apply; assembly failure rolls back the claim and its selection history. The execution snapshot records the requested first choice, actual selected model, queue start, elapsed time and either `preferredQueued` or `preferredUnavailable`.

Protocol support alone does not establish project manager compatibility. `workspace.key`, used for its separate workspace, was implemented in commit `ddfe1b1874`, but the runner manifest was already beta.7 before that commit, so package versions cannot certify support. Protocol 10 introduces the explicit `workspaceKey` capability; new runners advertise it and payloads with a separately named workspace require it. Supported older protocols and older package versions remain eligible when the runner declares this capability, including backports. Runners without it continue taking ordinary delegated work but cannot take project manager payloads. Update the application before its runners, so older servers reject protocol 10 cleanly rather than receiving an unknown capability word.

The Now line reads the same assembled-payload compatibility checks as selection, distinguishing offline, incompatible, policy/identity restrictions, capacity, agent concurrency and same-thread work. Runner names are shown only to machine managers or their owners; capacity is sampled diagnostic data, while final claim admission uses the live transaction and the runner's request.

## Delegated steps

`delegationQueueTimeoutSeconds` defaults to 600 (integer 1–86400). The next RunnersSweep pass applies changes to still queued steps. The 30-second server sweep works without claim polling or a page open and catches up after a restart. It only withdraws issue worker runs whose immutable first input records a manager mention and the original acting user. Historical records without that explicit source are conservatively skipped. Appended input cannot adopt a human-created run or reset its clock.

The withdrawal takes the claim's agent lock, rechecks the queue episode, attempt and available time, and conditionally ends only queued work as cancelled with `delegatedQueueTimeout`. It neither stops held work nor counts as implementation failure. The ending and a unique pending report commit together. A dispatcher wakes on end events and scans persisted pending reports every 30 seconds; failures retain a redacted error and back off up to one hour. The stored cause, elapsed time and sample time are unchanged on retries. Delivery locks the pending row and commits the original agent's unmentioned reply, the existing `@report:<runId>` guard, the manager input and the done marker together. Deleted dispatch comments fall back to the issue root with their source id; permission failures remain pending with an explicit error. Completed/failed reports use the same durable entrance; ordinary cancellation remains silent and historical endings are not backfilled.

The existing comment run limit is enforced. Below it the reply wakes the manager normally. At the limit the input is persisted and the owner notified; Now explicitly says it is waiting for manual continuation. Multiple held comments are retained together until continuation, rather than replacing one another. Delivery completion means a reply and retained trigger committed, not that the manager has started running.

Every manager round evaluates each candidate worker against the actual acting user's identity, subject, tools, capabilities, policy, variables, directory, total slots (including jobs), tool capacity and concurrency. `canStartNow` is a timestamped advisory snapshot, never a reservation. The Agent queue, Now and timeout report share the claim's read-only diagnostics and distinguish full capacity, another owner's personal machines, missing tools, tool/model authentication or configuration, unsupported workloads, offline machines and other restrictions. Private machine details are omitted from public timeout replies. Built-in principles allow reassignment only after confirmed withdrawal, preferring a suitable immediately available agent; otherwise requeue the original or let the manager move the issue to blocked and explain its waiting condition. Custom principles are retained; the fixed role keeps the withdrawal boundary.
