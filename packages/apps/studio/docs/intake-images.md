# Images in requirement intake

"Let an agent organize" copies selected PNG/JPEG uploads into chat attachments, associates the copies with the first message, and asks the agent to download and read every image with its image tool. The agent must describe verifiable details from each image before combining them with the requirements and supported text documents into a proposed plan. If any image cannot be read, it must identify the file and reason and stop without proposing a partial plan. A completed run alone is not evidence that the images were read.

Preparation errors keep the form open. Reading or tool failures after handoff appear in chat using the existing reply and run failure mechanisms. "Return to edit requirements" restores the text, project and selected source uploads; users can remove or replace images and choose another agent before explicitly organizing again. An earlier run must finish or be stopped in chat first. Each new organization creates a new conversation and fresh attachment copies, even for the same agent; it does not guarantee another runner machine. The existing chat composer can also request another attempt on that conversation's original attachments.

The retained input belongs to the current signed-in application instance and survives route and chat panel changes. It is cleared when discarded, when its proposed tasks are created, or on identity exit. It is held in memory only: refreshing the page, closing the tab or opening another tab does not restore this draft. Submitted messages and their chat attachments remain in their conversation independently. Source uploads still follow the existing orphan retention policy, so very old drafts may require uploading files again.

There is no OCR service, automatic capability probe or new runner eligibility rule. Supported tools and their configured model must actually be able to read the image. PNG/JPEG support here is a transport and retry path, not a guarantee about every configured model. Rule-based split continues to use image filenames only. The text attachment completeness checks reuse PM-307 / PR #10816, which is included as a dependency of this change.

Each image submission adds one batch source ownership lookup, one source read and one chat upload per image, followed by the existing message attachment transaction. Runner downloads use the existing conversation authorization and file storage. Unsent copies from failed preparation use the existing orphan cleanup. No database work is added to polling, heartbeats, claims or scheduled jobs.
