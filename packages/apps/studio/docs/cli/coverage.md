# Studio on the command line: coverage

`nb-studio` ships no business commands. Every command is an API route whose `x-cli` extension names it, listed for the caller by `GET /api/cli/manifest`; `nb-studio <words> --help` and `nb-studio docs <words>` show its arguments and flags, and `--json` answers the cli-envelope. The [command reference](reference/index.md), generated from the API document by `scripts/gen-cli-reference.mjs`, lists every command by area with who may run it and the action it needs; `tests/cli/__snapshots__/manifest.test.ts.snap` keeps the exact list for a person with every permission and for a run whose agent holds every action. The CLI's own commands are `login`, `logout`, `whoami`, `profile list|use|remove`, `docs` and `completion` ([getting started](getting-started.md)).

## What a run may call

A run is offered a command when its route takes a run token and its agent is given the action the route names (403 `RUN_ACTION_FORBIDDEN` otherwise): `agent list` (whom work can go to), `app list`, `app get`, `app logs`, `app deploy`, `app rollback`, `attachment upload`, `attachment delete`, `conversation title set`, `deploy list`, `deploy get`, `deploy logs`, `deploy request`, `env list`, `env get`, `inbox list`, `intake drafts` (on an intake request), `issue search`, `issue get`, `issue create`, `issue update`, `issue delete`, `issue restore`, `issue comment add`, `issue comment list`, `issue attachment list`, `issue attachment download`, `issue dependency add`, `issue dependency remove`, `issue runs`, `issue design-proposal`, `kb tree`, `kb list`, `kb search`, `kb read`, `kb download`, `kb propose`, `kb upload`, `plan create`, `plan get`, `plan list` (in a conversation), `pr list`, `pr link`, `pr open`, `preview list`, `preview status`, `preview logs`, `preview down`, `project list`, `project get`, `project update`, `release list`, `report metrics`, `report usage`, `run self`, `run context`, `run get` and `run events`.

Besides the projects plugin's, release management's, the knowledge base's and the Reports page's actions an agent may be given, two are actions of their own, held by a person while they hold their base action and by a run only when its agent is given the action and the run holds the base too: `studio.git/open-pr` and `studio.previews/manage` (base `pm.issues/edit`). An agent may also be given `pm.issues/delete` and `pm.projects/manage`, off by default. New agents are given `studio.git/open-pr` and `studio.previews/manage`. Every caller holds `agents.agents/view`, `pm.plans/use` and `studio.inbox/read`, and every run `agents.runs/self`. [Agents in a run](agents.md) says how a run finds and calls them.

## Kept off the command line

| What                                                                                                                                                                                                                                                                                    | Why                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Better Auth's endpoints under `/api/auth/`                                                                                                                                                                                                                                              | The browser's sign-in and session flow; `nb-studio login` and `logout` call the device authorization and sign-out themselves.                         |
| The authorization rules, database explorer, notifications, scheduler and workflow plugins' routes, `GET /api/healthz`                                                                                                                                                                   | Back-office pages Studio does not mount (`server/cli/provider.ts`); the routes stay documented for scripts.                                           |
| The runner protocol (`/api/agents/runners/register`, `claim`, `heartbeat`, `jobs/*`, `runs/*`) and `/api/agents/dist/*`                                                                                                                                                                 | Only a runner and the CLI's own installer call them.                                                                                                  |
| The GitHub App manifest flow (`POST /api/git/connections/startAppManifest`) and the OAuth authorization (`POST /api/git/authorizations/{id}/authorize`)                                                                                                                                 | Browser redirects. Add a GitHub App in Settings › Git; authorize yourself with `git authorization start` (device flow) or `use-token`.                |
| GitHub webhooks                                                                                                                                                                                                                                                                         | Called by GitHub, signed.                                                                                                                             |
| Upload targets: `POST /api/builds/{buildId}/uploadArtifact`, `POST /api/knowledge/tickets/{id}/redeem`, release management's raw upload and its per-App upload tickets                                                                                                                  | The CLI streams to them with a ticket (`deploy --file`, `release upload`, `kb upload`); scripts that upload with curl keep the documented routes.     |
| The issue board's columns, start options, mention candidates, the projects permission bootstrap, API key identities, `/api/git/marks`, `/api/deploys/marks`, `/api/inbox/notices`, the agents vocabulary, the people picker, `chatAgents`, conversation start from a page and mark-read | Helpers of the pages; `issue search`, `issue status list`, `agent list`, `inbox list` and `conversation create` cover what a person types.            |
| Dry runs of unsaved environment and registry settings                                                                                                                                                                                                                                   | The forms' checks before saving; `env check` and `registry check` check saved ones.                                                                   |
| Removing a dependency by its row id                                                                                                                                                                                                                                                     | `issue dependency remove` does the same by the other issue.                                                                                           |
| The invitation link's `lookup` and `accept`                                                                                                                                                                                                                                             | The sign-up page's; the link's token is the credential.                                                                                               |
| The knowledge plugin's own space, search, document, file and proposal-creation routes; the agents plugin's `run get`, `run events` and usage report                                                                                                                                     | The same capabilities as Studio's `kb` views, `run get`, `run events` and `report usage`, which add Studio's subjects, issue visibility and projects. |

## UI-only tasks

What a person does only in the web page, and where. The `nb-studio-cli` Skill carries the same list for agents guiding someone.

| Task                                            | Where                                                                                                                                 |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Approve `nb-studio login` on a machine          | The page `nb-studio login` opens (`/device?user_code=…`): check the code, choose Approve                                              |
| Sign in, register, reset a password             | `/login`, `/register` (from an invitation link), `/forgot-password`                                                                   |
| Accept an invitation                            | The invitation link, which opens the sign-up page                                                                                     |
| Add a GitHub App connection                     | Settings › Git › Add connection › GitHub App, then install the app on the account GitHub shows                                        |
| Connect your own GitHub account through OAuth   | Avatar › Account settings › Git (or `nb-studio git authorization start`, the device flow)                                             |
| Add a runtime (install the runner on a machine) | Agent team › Runtimes › Add runtime: copy the one-line install and run it on the machine                                              |
| Check unsaved environment or registry settings  | Releases › Environments, the environment's or registry's form › Check (saved ones: `nb-studio env check`, `nb-studio registry check`) |
| Change your password                            | Avatar › Account settings › Account and security                                                                                      |
| Language, theme, sounds, default chat agent     | Avatar › Account settings › Preferences                                                                                               |

## Not yet

Merging a pull request, deciding approvals and approving deployment requests stay a person's: opening them to agents' runs needs the owner's confirmation. A CLI-only installer, without registering a runtime, is not offered.
