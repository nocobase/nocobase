# Per-attempt worktrees

Every new worker uses a unique directory and a `runner-run-<attempt hash>-<repository hash>` local branch. The remote target continues to come from `workspace.dirs[].branch`; `RepoReport.branch` and `targetBranch` name that target, while `localBranch` names the private alias. Push with `git push origin HEAD:refs/heads/<target>`. Ordinary non-fast-forward failures require merging or rebasing before another ordinary push.

Each repository cache keeps `refs/runner/resume/<namespace>/<generation>` and immutable `refs/runner/saved/<namespace>/<generation>/<attempt hash>/<head>`. The namespace hashes application, subject, repository URL and target branch. Saving serializes only publication of these local refs, verifies the immutable ref, and advances resume only when the old head is an ancestor. Divergent saved heads remain reachable and the next worktree merges them in deterministic ref order. A conflict leaves the index and merge state intact and the workspace notes list the pending heads. No synthetic merge or reset represents concurrent changes.

The worker stops the tool and its descendant/tagged processes before saving. Completion pushes agent commits first, then snapshots remaining changes locally and reports the save result. Worktrees are deleted only after the terminal reporting path returns. A `RUN_INPUT_PENDING` response keeps them available for another turn; after a local snapshot the worker does not automatically push again in that attempt. Failure, cancellation, shutdown and lost leases use the same local saving path; lost leases make no new server reports. Daemon orphan recovery stops the previous processes before saving from the protected workspace record.

Unresolved merges, rebases, cherry-picks, changed local branch identity, initialized submodules, invalid metadata and failed Git operations preserve the original worktree. A parent gitlink cannot preserve submodule commits or objects, so submodules conservatively require recovery in the original directory. Recovery paths are reported in subsequent workspace notes. Normal cleanup and artifact cleanup cannot delete recovery directories. Read-only checkouts never create continuation commits or refs; successful cleanup deletes only their own registered worktree.

The task's continuation state keeps all target namespaces, active/recovery directories, initialization state and persistent tool container keys. Its directory participates in the existing two-stage server cleanup authorization. Cleanup refuses while an active or recovery directory remains. After authorization it removes only the task's refs and registered session containers. Cache object pruning remains disabled to protect legacy reference clones. Shared pnpm storage and clone/copy imports are unchanged.

Legacy repository branches and non-ignored working files are imported under the legacy directory lock. All local branch heads get immutable saved refs; no existing branch is reset or pushed. The original directory remains under its existing cleanup protection. Unresolved operations and initialized submodules block migration and retain the source. This conservative migration does not automatically delete the legacy clone.

Codex runs in the current checkout and stores its `CODEX_HOME` in a persistent per-application/subject/agent/thread/tool container. Claude Code, OpenCode and Pi start in that stable container; the newest workspace notes name the actual absolute code paths. Claude Code also receives these paths as `additionalDirectories`. The existing server session ID and thread scoping remain authoritative; the container never points to a shared mutable `current` symlink. The adapters receive the current skill bundle on every turn.

The opt-in `tests/adapters/cross-worktree.smoke.test.ts` records a random memory marker in a first conversation, deletes worktree A, resumes the same ID, and requires the tool to write that marker in B. A new/recovered session does not pass. Set `NOCOBASE_RUNNER_WORKTREE_SMOKE=1` to run available authenticated tools. Missing tools skip with an explicit reason. Codex migration copies only the assigned conversation rollout into the persistent home, leaving authentication, configuration and other conversations untouched. Legacy Claude Code, OpenCode and Pi conversations need tool-specific verification on an authenticated machine; a missing legacy conversation must not be described as a successful resume.

This change integrates that commit without revising its selection rules. PR #10794 remains a prerequisite for deployment; verify its merge and the integrated PM-300 head's CI before upgrading.

Validation must distinguish local Git integration, fake-tool daemon integration and authenticated real-tool inference. The deterministic daemon scenario starts two unmarked writers of one task while the first is still running, cancels the first after it wrote an uncommitted file, and starts a third run that reads both writers' contents. Real-tool conversation tests establish only the tested tool version's behavior. Tools absent from a machine require that same smoke on a machine where they are installed; adapter fixtures alone cannot establish conversation memory.

A clean request reruns initialization and allocates a new continuation generation, starting from the remote target or its configured base. Previous saved generations remain reachable for recovery and task cleanup; they are not merged into the new generation. A concurrent older-generation writer saves into its own generation without overwriting the clean request. Read-only runs never change the continuation generation.

Git object and reference writes use `core.fsync=objects,reference` with `core.fsyncMethod=fsync`; protected workspace/state records synchronize both the file and its containing directory before a saved worktree can be deleted. See [Git fsync configuration](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corefsync). A physical power-cut test has not been performed.
