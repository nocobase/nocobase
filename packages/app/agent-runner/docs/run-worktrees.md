# Per-attempt worktrees

Every new worker uses a unique directory and a `runner-run-<attempt hash>-<repository hash>` local branch. The remote target continues to come from `workspace.dirs[].branch`; `RepoReport.branch` and `targetBranch` name that target, while `localBranch` names the private alias. Push with `git push origin HEAD:refs/heads/<target>`. Ordinary non-fast-forward failures require merging or rebasing before another ordinary push.

Verified empty-remote initialization works with older Git without `worktree add --orphan`. The cache writes an unreferenced empty bootstrap commit, creates a detached worktree, and makes only that worktree's HEAD point at its unique unborn branch. The first real commit is a root commit, without the bootstrap parent; concurrent empty attempts retain separate HEADs and indexes. No target or shared branch is reset.

Each repository cache keeps `refs/runner/resume/<namespace>/<generation>` and immutable `refs/runner/saved/<namespace>/<generation>/<attempt hash>/<head>`. The namespace hashes application, subject, repository URL and target branch. Saving serializes only publication of these local refs, verifies the immutable ref, and advances resume only when the old head is an ancestor. Divergent saved heads remain reachable and the next worktree merges them in deterministic ref order. A conflict leaves the index and merge state intact and the workspace notes list the pending heads. No synthetic merge or reset represents concurrent changes.

The worker stops the tool and its descendant/tagged processes before saving. Completion pushes agent commits first, then snapshots remaining changes locally and reports the save result. Successful worktrees are deleted after the terminal reporting path returns. Normal cancellation saves and removes a safely stopped worktree before sending cancelAck, because the server may release the worker immediately after that acknowledgement. A `RUN_INPUT_PENDING` response keeps them available for another turn; after a local snapshot the worker does not automatically push again in that attempt. Failure, cancellation, shutdown and lost leases use the same local saving path; lost leases make no new server reports. A failed stop verification is sticky for the attempt: later cleanup cannot silently discard the recovery directory.

Worker and supervisor observations persist process identities outside the disposable worktree, including Linux boot identity and process start ticks. Restart recovery stops only still-matching identities, checks workspace cwd/open-descriptor holders, and includes preservation results in the orphan status event and failure detail. Observation cannot prove that an unobserved child did not escape its ancestry, group and tag. Consequently an unfinished orphan attempt is conservatively retained with `recovery-required`, even if known processes were stopped; it is not automatically committed or deleted after a restart. Recover its files in the reported original directory after confirming that all writers have stopped. Retrying the failure report is idempotent and does not snapshot a still-writing directory. Platforms without readable process identities use the same preservation fallback.

Cancellation recovery carries the original attempt, preservation detail and `localSave` results in its acknowledgement. The server stores the detail and a status event in the cancellation transaction and explicitly acknowledges receipt; the same owner and attempt can retry after cancellation without reopening the run. Spool errors, network failures, missing acknowledgements and lost ownership retain the run record until the preservation report is confirmed. Cancellation intent is kept in that record; when rewriting it fails, restart recovery can discover cancellation through the owned server status. A failed status query leaves the state unknown; it does not imply lease expiry. Preserve the sole retry record and directory while status is unknown or a terminal refusal has not confirmed preservation delivery. An older server that cannot acknowledge preservation after cancellation requires upgrading the server before this recovery record can be cleared safely.

Unresolved merges, rebases, cherry-picks, changed local branch identity, initialized submodules, invalid metadata and failed Git operations preserve the original worktree. A parent gitlink cannot preserve submodule commits or objects, so submodules conservatively require recovery in the original directory. Recovery paths are reported in subsequent workspace notes. Normal cleanup and artifact cleanup cannot delete recovery directories. Read-only checkouts never create continuation commits or refs; successful cleanup deletes only their own registered worktree.

The task's continuation state keeps all target namespaces, active/recovery directories, initialization state and persistent tool container keys. Its directory participates in the existing two-stage server cleanup authorization. Cleanup refuses while an active or recovery directory remains. After authorization it removes only the task's refs and registered session containers. Cache object pruning remains disabled to protect legacy reference clones. Shared pnpm storage and clone/copy imports are unchanged.

Legacy repository branches and non-ignored working files are imported under the legacy directory lock. All local branch heads get immutable saved refs; no existing branch is reset or pushed. The original directory remains under its existing cleanup protection. Unresolved operations and initialized submodules block migration and retain the source. This conservative migration does not automatically delete the legacy clone.

Codex runs in the current checkout and stores its `CODEX_HOME` in a persistent per-application/subject/agent/thread/tool container. Claude Code, OpenCode and Pi start in that stable container; the newest workspace notes name the actual absolute code paths. Claude Code also receives these paths as `additionalDirectories`. The existing server session ID and thread scoping remain authoritative; the container never points to a shared mutable `current` symlink. The adapters receive the current skill bundle on every turn.

Legacy Claude Code migration copies only the assigned JSONL transcript and its session-specific companion/subagent directory into the project key for the persistent container; the source and unrelated conversations remain untouched. Pi copies only the assigned legacy JSONL, preserves its session ID and history entries, and updates the copy's cwd header for the persistent container, using explicit `--session-dir`. OpenCode retains the same ID/history and moves a legacy `location.directory` through its [public move operation](https://github.com/anomalyco/opencode/blob/dev/packages/protocol/src/groups/session.ts), then verifies the destination before prompting. A missing/unsupported move or unconfirmed migration fails without replacing the conversation. Pi's [session lookup and cwd rules](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/session-manager.ts) are the basis for its header migration. Each worker supplies only the assigned legacy cwd and the existing per-thread scoped container.

Pi migration writes and validates a complete transcript in a unique temporary file beside the destination, then publishes it atomically without replacement. Retrying accepts an existing target only when its complete original history matches and all appended records are valid; subsequent messages remain untouched. A partial or divergent preexisting target is an explicit recovery error, with both copies preserved for repair. Interrupted temporary writes never become resumable transcripts.

The worker explicitly loads current checkout `AGENTS.md` and `CLAUDE.md` and lists its `.agents/skills` and `.claude/skills` entries on every turn, because fixed launch containers cannot discover changing repository roots automatically. The opt-in `tests/adapters/cross-worktree.smoke.test.ts` separately tests new containers and legacy repository-cwd upgrades: record a random marker, delete A, resume the same ID, write memory in B, verify B's new repository instructions/skill marker, and measure the tool's default cwd. New/recovered sessions, writes in the container, stale instructions and recreating A fail. Codex migration copies only the assigned rollout, leaving authentication, configuration and other conversations untouched. Synthetic adapter fixtures do not establish authenticated tool behavior.

On a machine with the corresponding supported and authenticated tool, run `NOCOBASE_RUNNER_WORKTREE_SMOKE=1 pnpm --filter @nocobase/agent-runner test tests/adapters/cross-worktree.smoke.test.ts --maxWorkers=1`. Add `-t 'claude legacy'`, `-t 'opencode legacy'` or `-t 'pi legacy'` for a specific upgrade case. Also run that tool's `persistent` case, recording its detected version, original/final session identity, cwd and assertions; never attach conversation files or authentication data. Missing binaries or authentication are explicit skipped validation, not successful migration.

This change integrates that commit without revising its selection rules. PR #10794 remains a prerequisite for deployment; verify its merge and the integrated PM-300 head's CI before upgrading.

Validation must distinguish local Git integration, fake-tool daemon integration and authenticated real-tool inference. The deterministic daemon scenario starts two unmarked writers of one task while the first is still running, cancels the first after it wrote an uncommitted file, and starts a third run that reads both writers' contents. Real-tool conversation tests establish only the tested tool version's behavior. Tools absent from a machine require that same smoke on a machine where they are installed; adapter fixtures alone cannot establish conversation memory.

A clean request reruns initialization and allocates a new continuation generation, starting from the remote target or its configured base. Previous saved generations remain reachable for recovery and task cleanup; they are not merged into the new generation. A concurrent older-generation writer saves into its own generation without overwriting the clean request. Read-only runs never change the continuation generation.

Git object and reference writes use `core.fsync=objects,reference` with `core.fsyncMethod=fsync`; protected workspace/state records synchronize both the file and its containing directory before a saved worktree can be deleted. See [Git fsync configuration](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corefsync). A physical power-cut test has not been performed.

A cancelling worker stores its cancellation intent and preservation report independently of the event spool. Spool storage failure does not block direct cancellation recovery delivery. Until the server explicitly acknowledges preservation details, the worker retains its run record, spool and unsafe directory; restart recovery retries without converting cancellation to failure. Unknown server status and terminal refusals do not prove receipt, and removing an application registration does not discard unconfirmed recovery work. Workspace preservation metadata also retains the original stop-verification reason when cancellation intent storage fails.
