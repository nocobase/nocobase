# Per-attempt repository worktrees

Every repository run gets a linked worktree from the machine's shared bare cache and a private local branch. Repository runs do not hold the task directory lock; a second unmarked writer can start immediately. A shared cache lock protects fetch, worktree registration, ref publication and removal only. In-place directory work retains its exclusive directory lock. Older runners retain their existing workspaceBusy protocol behavior.

Studio selects the earliest associated open pull request whose fresh host response confirms its head belongs to the same repository; equal association times are ordered by pull request number. Forks and unknown or unreadable sources are excluded. Without a qualifying pull request, the initial target follows the configured branch rule (`agent/<KEY>` by default). Local branch aliases are separate from this starting target. Agents may switch or create branches and push any branch in the repository with `git push origin HEAD:refs/heads/<branch>`, without force pushing or rewriting published history. After switching branches, use an explicit `nb-studio pr open --head <branch>`; `pr link` and `pr unlink` manage issue associations within existing identity permissions. Read-only steps still change, commit and push nothing. Automatic local saving never pushes or rewrites another run's history.

Each application/task/repository/target namespace has one `refs/runner/resume/<namespace>` reference. Under a short cache lock, a saved head advances this reference only when the previous head is its ancestor. A divergent head goes to a separate `refs/runner/saved/<namespace>/<id>` reference. The next run starts from resume and lists additional saved refs and commit IDs in its workspace notes for manual integration. It does not merge saved heads or a diverged remote automatically. If remote is ahead of resume by fast-forward, the next checkout uses remote; a diverged remote is explicitly reported. A clean checkout starts from remote without deleting earlier local refs.

All endings use the same order: stop the tool, kill remaining descendant/tagged process groups and check for current holders, commit non-ignored repository changes locally, publish the continuation reference, remove the worktree, and prune stale Git worktree entries. Normal cancellation finishes this sequence before acknowledging cancellation. A forced worker exit performs the same local finalization from the supervisor after killing its processes. Pending-input completion can save a snapshot without removing the worktree before another turn.

Continuation commits use the checkout's effective `user.name` and `user.email` for both author and committer, with no attribution trailers. When a run supplies `workspace.git.author`, preparation also sets that identity in the existing writable worktree's Git configuration, matching the identity passed to the tool even if the machine's global Git identity differs. Their title identifies the changed file and additional file count; the body identifies work in progress saved when a run is interrupted or ends. Missing or invalid identity retains the original worktree without creating a commit and reports the required Git configuration through the existing recovery status and run result. Existing continuation commits are not rewritten.

Agent-created branches live in the shared repository cache, survive worktree removal and remain available for checkout in later runs. Stash entries survive too, but the stash stack is shared by every worktree of the cache, including other tasks' runs: record a stash's commit ID and restore it with `git stash apply <sha>` rather than relying on `stash@{0}` or `git stash pop`. When the agent ends a run on another named branch, non-ignored uncommitted changes are committed on that branch, whose own ref preserves the head; it neither advances the original target's resume ref nor adds a saved ref under its namespace. Only a detached HEAD with commits no branch or remote-tracking ref reaches is recorded as an additional saved ref. Automatic repository reporting treats a switched branch as informational: it reports no failure and never pushes that head to the original target. Cleanup only deletes this attempt's recorded `runner-run-*` alias after its worktree is removed, no other worktree has it checked out, and Git confirms every commit is reachable from fetched `origin` tracking refs. Local continuation refs do not count as published evidence. Unpublished aliases or uncertain evidence are retained; agent-created branches are never cleaned up, even if already published or named with a similar prefix.

If stopping, committing or ref publication fails, retain the original directory and show its path in the existing text status/failure detail. A clean, pushed attempt whose removal already started (`removing`) is retried by GC or the next run under its attempt lock: stop remaining cwd holders, remove the residual directory, and prune its cache registration. After saving and confirming the push, deletion failures remain pending (`removing=true`, `recoveryRequired=false`); partial checkout contents are not inspected or committed again. Startup and GC also retry old recovery records only when every repository has a removal marker and pushed SHA and the reason reports a failed `git worktree remove`. Other recovery records retain their protection. Git stderr is preserved in the removal log and reason. Pure deletion failures retain their reason for retry without blocking later tasks; uncommitted or unpublished work and uncertain ownership still require recovery. Unresolved Git operations and initialized submodule objects are kept in their original directory. There is no additional cancellation recovery protocol, structured preservation acknowledgement or persistent writer-identity registry. Current descendant, process-tag and Linux cwd observations are best-effort checks, not containment; processes that escape these observations need host/service isolation. Storage failure can prevent text reporting; no reliable preservation-report delivery is promised.

Read-only runs may continue when an older recovery directory exists; their notice identifies that directory and states that the new checkout does not contain its pending changes. Write runs retain the recovery instruction. Read-only runs neither publish local continuation refs nor push, and discard their worktree after stopping. Cleanup rechecks activity and preserves failed directories; task completion cleanup removes only that task's continuation refs/state and external Codex home. Shared caches, pnpm store, other worktrees and unrelated task state remain isolated. Legacy clones are not imported; existing GC rules govern them, and the next new worktree starts from remote unless this implementation already saved a local resume head.

Codex uses an external CODEX_HOME scoped by application, task, agent and thread. Its login/configuration links continue to use the existing host integration, and it links the real home's plugin bundles (`plugins/`) and plugin catalog (`cache/`) so a new home does not download them again. All tools launch in the actual current code directory, loading that checkout's instructions and skills. Claude, Pi and OpenCode start fresh when the attempt directory changes. Old transcripts and Codex rollout directories are not migrated: losing the prior session once during upgrade is an accepted tradeoff. Source fixtures do not establish authenticated tool behavior.

Core validation covers real daemon/worker processes with deterministic tool scripts and local Git remotes: concurrent unmarked writers, local continuation after completion/failure/cancellation, separate divergent refs, stopped processes before saving, failure directory retention, normal and forced cancellation, shared cache isolation, external Codex state and older protocol compatibility. Authenticated tool inference and a deployed Studio/runner upgrade must be reported separately if not executed. Fault injection, physical power-cut and disk-full stress are follow-up validation, not claims of this delivery.

## Run temporary directories

Linux and macOS agent runs allocate `/tmp/n-<8 hex namespace>/<16 hex attempt>` independently of inherited TMPDIR. The namespace hashes the current UID and canonical runner home; the attempt hashes its unique workDir. Both directories must be real directories owned by the current UID with mode 0700. The literal path and realpath must each fit within 40 UTF-8 bytes (32 bytes on ordinary Linux and 40 with macOS `/private/tmp`). Allocation uses exclusive mkdir, rejects existing attempt directories and unsafe namespaces, and reports setupFailed instead of falling back to a long path. TMPDIR, TMP and TEMP are runner-reserved and receive the same path after workspace variables are applied. Every adapter passes that environment to its tools; their children inherit it. Workspace notes explicitly permit temporary writes there.

A lock in the private namespace protects allocation through final cleanup. Worker finally removes the temporary directory only after stopping writers; intermediate snapshots leave it available. Supervisor recovery performs cleanup after its existing process checks, waiting at most two seconds for a temporary-directory lock held by GC. If cleanup still fails, it logs the retention reason and continues credential removal, result reporting and exit completion; subsequent GC can reclaim the retained directory. Shutdown and upgrade use those same paths. Failed stops retain the directory and existing recovery metadata. Automatic GC and manual gc scan only this runner's namespace, acquire each lock without waiting and reread run records and workspace metadata. Any corresponding record, recovery-required workspace or observed process holder prevents deletion. Manual gc lists candidates without deleting unless --apply is supplied. The namespace itself remains as an empty private parent. No mapping state, server protocol change, migration or changes to repository/session/store layout are required.

### Real runner acceptance on dev-2 or lima

Install the reviewed runner artifact through the machine owner's normal installation process, record its version and commit, then let that runner schedule a fresh agent run. Do not upgrade a shared machine from an implementation task. The machine must have Linux or macOS, a writable private namespace under /tmp, repository dependencies installed with pnpm install, writable Studio storage and an available listening port. Studio defaults to SQLite; an external database is not required for this check.

Inside the newly scheduled run, record the platform and all three temporary variables. Check equality, byte lengths of the path and realpath, UID, 0700 permissions and a successful write. Create a net.Server at `$TMPDIR/tsx-<uid>/<pid>.pipe`, connect to it and close both endpoints; retain the sanitized result. Run `pnpm --filter @nocobase/studio dev`, save startup logs, and request the application entry printed as `Local:` including its actual Hono port and base path. Record HTTP status and content; a Vite response alone does not establish readiness. Stop the application before ending the run. In a subsequent verification step, check that the recorded temporary directory no longer exists and a second active run's directory still does. Report Linux and macOS execution separately; simulation is not a macOS machine result.
