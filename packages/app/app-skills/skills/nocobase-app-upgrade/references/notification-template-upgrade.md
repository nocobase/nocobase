# Reconcile notification template administration

Follow the version-selected upgrade entry point in the parent Skill. Fetch BASE and TARGET template tarballs and TARGET's compatible `@nocobase/app-skills` first. This reference applies only when TARGET contains `client/pages/settings/notification-routes.ts` and the Notification package exposes `notificationTemplateRegistryToken` plus `client/templates`. A dependency update alone does not replace application source or register this page. Before a target release is published, candidate-package checks are useful but do not establish a published upgrade pass.

1. Record the clean application checkpoint, template package and baseline version. Preserve a representative business page, custom notification renderer/fixture, notification workflows, channel/mailer configuration, stored grants and business records for comparison. Keep secrets out of evidence.
2. Compare BASE → TARGET and BASE → application. Bring in compatible package ranges through TARGET's manifest. Reconcile `client/pages/settings/notification-templates.tsx`, `notification-routes.ts`, the route composition, `client/runtime.ts`, `server/providers/notification-management.ts`, its provider registration and English/Chinese settings labels. Preserve custom route names, page permission IDs and existing deep links. When TARGET's `notificationTemplateRoute` has the `notificationTemplate` child route (`:templateId`), bring it in with the page that reads that parameter and redirects older `?template=<id>` links, so each template keeps a shareable address. Default's runtime route factory consumes the provider's derived `client.notificationTemplates.invitationConfigured` boolean, so a configured built-in invitation mailer enables the real directory automatically after restart. The provider and Users directory use the exported safe `describeInvitationEmailChannel` projection; never publish mailer credentials or copy a full server configuration into `client`. A bare application without notification business keeps the menu absent.
3. Reuse the application's existing `notificationManagement` group under System settings. Apply `includeNotificationTemplateRoutes` to the complete host route contributions, or insert `notificationTemplateRoute` once into the existing module. Keep its path relative to any path-bearing ancestors so the stable application URL remains `/settings/notifications/templates`; do not register a second module. If applying the newer settings navigation source in the same upgrade, follow its upgrade reference and attach the group to its existing system category. Preserve the host's module container and log view. Do not invent channel-editing or test-send tabs.
4. Reconcile application-owned send call sites into source registration. Preserve custom content and sender selection; extract a pure shared builder only when needed. Keep callback-based or non-enumerable messages explicitly listed as uncovered. Never replace business workflows with Examples or force a direct invitation mailer through persistent notification storage.
5. Synchronize Skills through the upgraded CLI. Verify list/detail/preview as an administrator and direct API denial as a restricted user. Check actual language policy, configured/missing/disabled channels, synthetic-only rendering, search/category/channel filters and desktop/narrow layout. Browse and preview must leave notification history, business data and configuration unchanged.
6. Verify retained custom content, records, grants, workflow behavior and old deep links after restart. Run affected application checks and record exact BASE/TARGET versions, tarball integrity, dependency resolution, source conflict decisions and results. Advance `nocobase.defaultTemplateVersion` only after this reconciliation and the retained-data checks succeed.

There are no new tables or migrations for this directory. Rolling back source and compatible packages removes the view and registrations without deleting notification history or custom business state. Do not roll back or rewrite existing executed migrations.
