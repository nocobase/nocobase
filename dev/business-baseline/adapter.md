# Evaluator adapter contract

An evaluator-owned ES module exports `createAdapter({ scenario, baseURL, evidenceDir, signal })`. It returns asynchronous `reset(seed)`, `execute(action, input)` and `close()` methods. Initialization only configures the adapter; network work belongs in the timed methods. Honor the supplied abort signal in HTTP/browser operations. `reset` clears only the isolated scenario test database, creates native test users for actor aliases and explicitly assigns the requested business roles, then inserts the supplied deterministic catalog and fixture records. Every case starts from this fixture; `document`, state aliases, `foreignDocument` and `foreignChild` resolve to actual persisted IDs. `ownTask` resolves to the active case's task assigned to `reviewer`. Retain the initial full database snapshot and original record revisions at reset. All alias translations and actual route/field/selectors are retained in adapter source. The evaluator may add fixture records but may not change the frozen expected values.

`execute` returns `{ value, evidence: [relativeArtifactPath, ...] }`. `value` contains normalized observations, not a Boolean verdict. The frozen runner checks the expected subset itself. Record raw HTTP method/path/status and sanitized response, or actual browser action/visible state, in the evidence file. Every step needs an existing nonempty evidence file under `evidenceDir`, with no secrets. `evidence` may include screenshots or database snapshots. An independent reviewer confirms observation provenance; a file's presence alone cannot establish authenticity.

## Actions

| Action           | Required behavior and normalized value                                                                                                                                                                                                                                                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create`         | Call the real API as `actor` with `record`; return `accepted`, `state`, `totalMinor`, `childCount` from the response and persisted reread. Store returned ID as `document`.                                                                                                                                                                                           |
| `update`         | Call real API against `target` (default `document`), retaining the originally read revision unless specified; return `accepted` and persisted fields.                                                                                                                                                                                                                 |
| `transition`     | Call actual business action as actor; return `accepted` and persisted `state`. Return `effectCount` as the number of history effects for that action on that record since reset. A rejected request must leave persisted state unchanged.                                                                                                                             |
| `read`           | Call list, detail, child or candidate endpoint specified by `surface`; return `visible` from the returned IDs or `accepted` for access. `query` applies actual search/filter parameters.                                                                                                                                                                              |
| `concurrent`     | Send both actual requests concurrently with independent operation keys and the same starting revision. Return `successes` counting persisted state changes, plus final `state` and `effectCount` from history. Submission receipt replay of an identical operation is not a second effect.                                                                            |
| `snapshot`       | Read via trusted test database fixture, not a business API with expanded grants; return `documentCount`, `childCount`, `totalMinor`, `state`, `completedTasks`, `fixtureIntact` or `unchanged`. `fixtureIntact` compares with reset; `unchanged` compares full stored parent/child values against the latest explicit snapshot or reset snapshot when none was taken. |
| `failChildWrite` | Through a test-only repository fault hook, fail after the first child has actually been written inside the save transaction. Preserve proof that the first write occurred. Return `accepted: false`, `firstChildWritten: true`; never simulate failure before the handler or expose a production failure endpoint.                                                    |
| `ui`             | Use Playwright Chromium, native sign-in and actual page controls for the named flow. Return the observed fields and save screenshot plus action trace. No direct API substitute for the interaction.                                                                                                                                                                  |

Use `accepted: false` only for an actual non-success response (401/403/404/409/422 or the product's documented rejection), with the persisted data check where expected. A transport error is blocked, not a rejected business request. Native app success envelopes may carry a business error; inspect the actual contract. For hidden data, `visible: []` means no protected IDs in any returned payload or count; a documented rejection is also normalized to no visibility with its raw response retained.

Actors are `owner`, `otherOwner`, `reviewer`, `otherReviewer`, `outsider` (signed in with no business grants) and `anonymous`. `reviewer` is assigned to `owner` documents; owner and reviewer are distinct users. Reviewer access is restricted to assigned submitted/decided work. None of these actors is an administrator. Only fixture setup/snapshot may use trusted in-process test privileges. Create a foreign document owned by `otherOwner` with a child alias `foreignChild`, reviewed by `otherReviewer`, for every fixture. Candidate scopes must distinguish active permitted `allowed` from disabled `inactive` and inaccessible `restricted` references.

`record` uses evaluator names, independent of database column names. `reference` and `item` resolve supplied catalog aliases. `owner`, `reviewer`, `state`, `totalMinor`, `childId` are malicious-input fields in relevant cases and must reach the actual request body rather than being removed by the adapter. Omitted values remain omitted. For owner/status/reviewer forgery, return `forbiddenEffect` from a persisted reread; the product may reject the request or ignore the forbidden fields. Retain the raw request acceptance separately. Never turn an absent route or unsupported feature into a passing observation. Raise `UNIMPLEMENTED_FEATURE` for missing business behavior (fail); use `BLOCKED` only for evaluator/infrastructure inability and include the concrete cause.

The adapter implements generic actions only, never switches on assertion IDs, and cannot import expected values or generate canned observations. Preserve source, hash and raw traces. Freeze before/after field mappings once each application's interface is discovered; changes require a logged evaluator correction and rerunning the entire affected scenario within a separately recorded test attempt. Test hooks for transactional faults are evaluator code, not a prescribed business implementation. If the hook cannot be implemented, keep the rollback assertion blocked and the build unsuccessful.
