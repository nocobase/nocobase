Build employee onboarding in this clean Default application. HR coordinators create onboarding cases for employees, select a permitted active department, and maintain a child checklist of tasks with explicitly assigned responsible users. Departments can be inactive or restricted. Users need usable business pages and the existing user/role administration to manage explicit assignments. Reuse existing execution history; do not add a separate workflow management page.

A coordinator can save an incomplete draft, add/edit/remove tasks, and activate a valid case with at least one task. Each task needs a title and a responsible user. Task assignees see only tasks assigned to them and only the case information needed to do them. They mark their own tasks complete. A case becomes completed only when all its tasks are complete. Coordinators can edit only their own draft cases; active and completed checklist definitions cannot be changed. Repeated or concurrent task completion must record one effect, and an old edit must not overwrite activation or completion.

Provide employee/case search, status filters, department candidate search/filtering, task progress and clear action availability. Saving a case and its task list must be atomic, including a failure after an earlier task write. Server checks must cover lists, details, child endpoints, candidates and all actions. Other coordinators, other task assignees, unassigned signed-in users and anonymous users must not read or alter protected work. Recheck candidate scopes on save, prevent attaching another case's task, and prevent forged coordinator, assignee or case state. Include repeatable synthetic data, automated browser and server tests, and installation, startup, test and isolated-data reset instructions.
