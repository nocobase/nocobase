Build a purchasing request feature in this clean Default application. Provide supplier and material catalogs, purchasing requests and request lines. Use one currency, CNY. Each request belongs to its applicant and has one explicitly designated reviewer who is a different person. Suppliers and materials can be active or inactive and can be restricted to particular users. Users need usable business pages and the existing user/role administration to manage explicit assignments. Reuse existing execution history for decisions; do not add a separate workflow management page.

Applicants can save incomplete drafts, find permitted active suppliers and materials by search and filters, and add, edit and remove lines. Quantities must be positive integers. Unit prices must be nonnegative amounts with at most two decimal places. Show line amounts and the total; calculate and validate amounts on the server as well, rejecting forged totals, invalid quantities, excessive precision and unsafe totals. Saving the request and all lines must be atomic: a failed line write leaves no partial new request and preserves an existing request exactly.

The states are draft, submitted, rejected and approved. Applicants may edit only their own draft or rejected requests. Submission requires a valid supplier and at least one valid line. Only the assigned reviewer may approve or reject a submitted request, never their own request. Rejected requests can be corrected and resubmitted. Approved requests are final. Repeated or concurrent submission/decision requests must produce only one state change and history effect. An edit based on old data must not overwrite a decision.

Enforce permissions on the server for lists, details, lines, catalog candidates and every write/action, including direct requests that bypass page controls. Applicants see only their own requests; reviewers see only their assigned work. Other applicants, other reviewers, unassigned signed-in users and anonymous users must not read or alter protected records. Recheck catalog scope when saving, prevent moving another request's line, and prevent forged applicant, reviewer and state changes. Buttons must reflect these same rules. Include repeatable synthetic data, automated browser and server tests, and installation, startup, test and isolated-data reset instructions.
