# Binding the actual runtime

The original Git archive remains unchanged. Before preparing any scored application, install the fixed lockfile, then run `node dev/business-baseline/runtime.mjs bind before` once. This refuses existing profiles and first checks the working package sources against the original Git commit, including runtime TypeScript and Skill sources omitted from the narrower reference-resource manifest. The installed pnpm lockfile must match the frozen repository lockfile exactly. The profile records actual resolved package paths/names/versions, SHA-256 hashes of installed external package files and dependency links, and workspace build artifacts and dependency links. Retain the profile and its SHA-256 with the runner/environment record; review this binding before scoring. Package credentials, application configuration and storage are excluded.

`config`, `start` and `evaluate` recompute this inventory and refuse drift before invoking the application or evaluator adapter. Source changes, installed file changes, lockfile changes and link redirection are errors. After native Skill synchronization, copies under the application's `.agents/skills` must match their actually resolved package sources, with no extra/missing Skills. The instance marker pins the selected profile hash. Collect this receipt in evidence. The inventory includes the installed workspace dependency set, so installation or rebuilding packages between paired runs requires a fresh comparison rather than silently enrolling different code.

For after runs, use an independently reviewed JSON registration with `beforeProfileSha256` and `changes: { "packages/app/app-skills/skills/<path>": { "sha256": "<exact new file hash>", "reason": "..." } }`. The only other permitted prefix is `packages/templates/app-template-examples/`. List every added or changed reference/example source file; no wildcard allowances. Run `node dev/business-baseline/runtime.mjs bind after <registration.json>`. It requires exactly those source changes and preserves before-round lockfiles, external artifacts, workspace dist and dependency resolutions byte for byte. Unregistered changes remain errors. Use `node dev/business-baseline/instance.mjs prepare <scenario> after`, then pass `after` to config/start/reset too. After instances live in `../.business-baseline/private-after-<scenario>/.business-baseline/after-<scenario>`, preserving every before build. Set `BASELINE_ROUND=after` for the evaluator. Keep all registration/profile receipts with the pair. Do not rebind an already scored application.

The common environment adjustment is `bounded-tailwind-client-v1`: isolated instances replace only `@import 'tailwindcss';` in `client/styles.css` with `@import 'tailwindcss' source(none);` followed by `@source './';`. All other CSS, theme imports, Tailwind plugins and `tailwind.config.mjs` plugin content paths remain unchanged. This limits automatic application scanning to `client` while retaining registered plugin style sources. It is applied before either scored round, recorded in the instance marker and protocol, and is outside the original archive. The helper only binds original or already bounded clean CSS; it refuses to overwrite developed styles. Existing preparation-only smoke copies can enroll with `node dev/business-baseline/instance.mjs bind smoke before`.

Actual generated application code, tests and data are the build's output, not a replacement runtime profile. Keep the generated diff and application manifest/lock changes in the run evidence. Builders use the frozen installed dependency set; an application requiring additional packages needs a separately recorded environment comparison. No business assertions, IDs, expected values, deadlines or denominator change with this environment registration.

## Private isolation and recovery

The preparation helper copies selected public source from the original Git commit, then copies only the dependency/artifact paths listed in the existing profile. Files use independent inodes (`copyFile`, never hard links), and relative symlinks retain their original bytes within the complete private layout. The virtual store’s Docs workspace link needs only its public package manifest; unrelated task files and documentation assets are not copied. Root command links come from the root manifest’s explicit dependencies. No runtime configuration, credential file, database or untracked source is copied. `.npmrc` is excluded from source copies and Git source comparison. This omission does not authorize package installs or profile changes.

`assertPrivateBoundary` rejects any `node_modules` entry in the private root’s ancestors, then checks every transitive symlink’s resolved destination and every regular file’s link count. Absolute links, missing targets, links leaving the private root and hard-linked files stop preparation or runtime checks. The dependency copy validates each enumerated file/link against the old profile while copying; it fails on changed/missing required bytes. Unlisted post-freeze dist output is omitted without touching the shared tree. A failed preparation leaves its partial directory for inspection; do not overwrite it or reuse it as a scored application.

The command environment uses `NOCOBASE_SKIP_WORKSPACE_DEPENDENCY_BUILD=1`, which the existing App build script already supports. It also sets Node’s `--no-global-search-paths`, removes inherited `NODE_PATH` and shared-workspace PATH entries, and clears application/tool-root overrides. Frozen pnpm shims embed absolute NODE_PATH fallbacks; the native Node flag disables those fallbacks while retaining their byte-level identity. The native flag does not disable standard ancestor module lookup. Private roots therefore live beside the checkout under the task directory, and preparation, identity checks and resource verification reject ancestor `node_modules` entries before use. Both CJS and ESM probes must fail to resolve a missing private dependency, even when the synthetic shared checkout contains it. These controls apply to both future rounds. They do not make an earlier drifted sample comparable.

Runtime verification detects the private root marker, compares canonical root-relative resolutions and artifacts with the unchanged original profile, and uses the source checkout’s Git object database read-only to compare private source against the pinned commit. The marker must identify the expected checkout and its original physical root under the checkout’s sibling `.business-baseline` directory. Checkout-nested legacy trees are preserved as evidence and rejected by the new entry points. The source checkout and the private tree are never joined by filesystem links. No new profile is enrolled. A guarded build records its actual result, private before/after verification, boundary receipt and shared inventory hashes under the private root’s `.business-baseline/build-receipts/`. Shared pre/post equality preserves its starting state, including any already-recorded drift; it does not certify the shared tree against the old profile.

The original before profile contains compiled output only for `@nocobase/dev-config`; most workspace packages export source during development and had no dist at freeze time. Exact recovery must preserve that absence. The production packager may therefore reject missing dependency dist when dependency builds are skipped. Retain that failure together with unchanged private/shared inventories rather than rebuilding dependencies, replacing the profile or reporting packaging success. A separately reviewed packaging environment is needed if full production packaging is required; the original fixed-resource source-mode experiment remains distinct. Keep all interrupted/non-comparable samples and perform any later functional diagnosis on their sealed source separately.
