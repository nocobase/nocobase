Add Server-only queue-backed subscriptions for committed synchronization inserts. The application provides `@nocobase/queue` through its existing QueueServiceProvider; Mail does not create its own queue service or persist event-log/sequence tables. Select the event backend, concurrency, retry and retention independently with `mail.queue` (or mapped `MAIL_QUEUE`), naming a configuration under `queue`; omitted, it follows `queue.default`, while `mail.jobs` continues to choose synchronization/sending tasks. Reject an invalid explicit queue name instead of silently using another backend. Without the host queue service, Mail logs a warning and ignores event subscriptions and publication without preventing normal Mail startup, synchronization or sending. Keep existing Mail synchronization, sending and frontend invalidation semantics unchanged.

Listeners receive a cancellation signal and asynchronous unsubscription must be awaited during shutdown. Queue workers await listeners and own their configured retries and retention; Redis instances compete for work rather than broadcasting to every instance. Keep business effects idempotent. Publication happens after commit without an event outbox, so failed acceptance or process termination in that window can lose events; neither listener nor publication failures retry committed synchronization. There are no incremental event-read or checkpoint APIs, and existing messages are not automatically backfilled.
