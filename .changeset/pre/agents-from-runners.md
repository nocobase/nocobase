Discover agents from what runners report instead of having people create them. Each coding tool and normalized model a runner reports becomes one agent (`source: 'runner'`, a deterministic id, named from a model catalog such as "Claude · Opus 5.5"), pending until someone who manages agents writes what it is good at and enables it (`PATCH /api/agents/{agentId}` with `description`, `effort`, `enabled`); an application keeps agents of its own with `agents.ensureSystem`, and sets every discovered agent's instructions and actions with `agents.setDefaults`. A model a run reports unavailable is marked on that runner until the runner reports its models again, and an agent no runner reported for 14 days is shown without a runner and left out of `roster`. Online agents, consultations, the online executor, agent presets, creating, archiving and deleting agents, the chat model choice and the default chat model settings are removed; conversations go to an enabled agent and say why one cannot answer (`othersPersonal` added, `AGENT_NOT_ENABLED`). Model services remain for the application's own model calls through `models.gateway` (renamed from `online.gateway`). Claims carry `workspace.key` and `workspace.readOnly` from the subject's assembly (`SubjectAssembly.workspaceKey`, `readOnly`). The migration `202610240020_ag_runner_agents` adds the new columns, removes every existing agent (rows kept and marked deleted so history still names them), cancels their queued runs, withdraws their pending run requests and clears default chat agents.
