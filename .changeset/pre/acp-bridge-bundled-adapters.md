The bridge manages the ACP adapters for Codex and Claude Code instead of fetching them with npx for every session: the first time one is needed it installs the pinned version (`@agentclientprotocol/codex-acp@2.2.2`, `@agentclientprotocol/claude-agent-acp@0.89.1`) once, with the `npm` on PATH and without optional dependencies, into `adapters/` beside the bridge's state file, and from then on runs it with the Node.js running the bridge against the `codex` or `claude` installed on the computer (`CODEX_PATH`, `CLAUDE_CODE_EXECUTABLE`), so a session no longer waits seconds for npx. Nothing of either adapter ships inside this package. The install starts in the background when the bridge first looks for agents; a session starting meanwhile waits up to 90 seconds for it. A managed adapter needs Codex 0.160.1 or Claude Code 2.1.200 or newer; with an older agent, a Claude Code that is a Windows batch file, no npm or a failed install, the bridge falls back to an adapter installed on PATH, then to npx with the same pinned version. `NOCOBASE_ACP_ADAPTERS=installed` prefers an adapter installed on PATH over the managed one. `BridgeOptions.adapters` names another directory for the managed adapters. `resolveAgent` takes an optional fourth argument, `ResolveOptions`, which installs and runs managed adapters only when it names their directory (`adapters`); a `ResolvedAgent` may carry the environment its launcher adds and whether it is a managed adapter (`managed`), and an `AgentLauncher` describes a managed adapter in `managed`.
