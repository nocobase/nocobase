Remove a runner's working directories once their work is over. Every ten minutes the runner reports each working directory it keeps for an application, with the last run that worked in it, its size, whether it holds work that was never pushed, and when it was last used (`POST /api/agents/runners/workspaces`). The application finds each run's subject and asks the subject's binding whether its work is over (the new optional `SubjectBinding.workspaces.settled`), and answers which directories may go. The runner removes them, except a directory with changes not committed or commits its remote task branch lacks, which it keeps and reports as unpushed. Whether a branch was merged is never judged from the default branch's history, so squash merges count as merged once the application says the work is over. A runner keeps reporting only to an application whose heartbeat answer announces it (`HeartbeatResponse.workspaces`); older runners and older applications keep the existing retention rules. The owner may cap what the working directories take (`nocobase-runner register --workspace-limit 40G`, or `nocobase-runner config set workspace-limit 40G`): over the cap, the runner removes the directories whose work is over first, then pushed directories least recently used, and never removes unpushed work. `nocobase-runner gc` lists every working directory with its size, application, subject, server status, unpushed state and last use, and with `--apply` removes what the rules allow, filtered by `--ended`, `--older-than` and `--subject`; `--force` also removes unpushed work. The application keeps each runner's last report (`agRunners.workspaceUsage`, added by a migration) and shows it as `Runner.workspaceUsage`.
