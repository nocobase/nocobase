Replace workflows with a project manager and agents discovered from runners. Issues have six fixed statuses (Backlog, In progress, Blocked, In review, Done, Cancelled); a new issue is started now or later, and "Start" on a backlog issue wakes the project manager. One project manager (`studio-project-manager`) executes every issue given to agents: each turn it hands one step to an agent by what the agent's description says it is good at, from a roster of the enabled agents with whether a runner can take their work and how busy they are, asks a person (Blocked) or hands the issue over for acceptance (In review), and starts each comment with a "Next" line. It works in a directory of its own without a checkout; a step that changes no code is handed over as read-only and runs in a read-only checkout alongside the step that writes. Its settings (Agents › Project manager, `GET`/`PATCH /api/projectManager`, `project-manager get|update`) choose the agent it runs with and a fallback, its allocation principles (built in, editable, restorable) and how many runs agents' comments may start per issue (20 a day by default). Besides failing checks and conflicts, a linked pull request whose checks all passed wakes it once per head commit (`prChecksPassed`, switch `wakeOnChecksPassed` per repository). The issue page's "Now" line says what the issue waits for (`GET /api/issueProgress/{issueId}`), and the pull request toggle reads "Complete the issue when merged" or "Merging does not change the issue". The Agents page lists the agents discovered from runners to enable; online agents, the project assistant, chat model choice, agent presets, workflows, stage rules, design proposals, approvals, checklists, executor admission rules, retrospective rules and putting small knowledge bases into prompts are removed; conversations and AI intake pick an enabled agent. A finished run reads "Turn ended".

Upgrading: let running agent runs finish (or stop them) first. The migrations map issue statuses to the fixed ones, hand every issue an agent executed to the project manager, remove all existing agents (their names stay in history) and cancel their queued runs, delete workflows, stage guards, approvals and checklists, and withdraw the inbox decisions about them; nothing is woken, and an open issue shows "Hand over to the project manager" until someone does. Working directories, `agent/<KEY>` branches and pull requests are kept. Afterwards, enable the agents your runners report (Agents) and choose the project manager's agent (Agents › Project manager).
