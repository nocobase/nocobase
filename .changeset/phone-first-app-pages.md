Make phone layouts part of every application page from the first delivery: the application development Skill adds a phone experience guide (first screen, list cards, compact filters, one-row tabs, forms, overlays, touch and phone verification), replaces the old "the toolbar wraps and the table scrolls" acceptance rule, and updates its workflow, templates, examples and screenshot tool to match. The templates' `DataTable` gains `renderCard` to show rows as cards below 768px and a `DataTableSortMenu` for sorting without column headers; on phones it keeps the selection column's "Select all on this page" above the cards. `PageHeader` keeps a single action on the title's row and wraps several actions onto one row under a title that keeps at least 12rem, and `PageContainer` uses tighter spacing on phones, and `DataTableSortMenu` gains a `compact` icon form, so a list's search, filter and sort share one row above the first card. The Examples list examples and their published Skill copies now show phone cards, and the customer list demonstrates a phone filter sheet with the applied count. Overlay forms guard unsaved changes with a navigation guard, so Cancel, the close button, Escape and browser back all ask before discarding, and the list example shows how to render one set of filters inline and in the phone sheet without duplicate IDs.
