Send knowledge back for changes. A decider sends a pending proposal back with a comment (`POST /api/knowledge/proposals/:proposalId/requestChanges`), and someone who may edit sends a document's current version an agent wrote back to it (`POST /api/knowledge/docs/:docId/requestChanges`). The proposal waits as `revising` and the new `proposal.changesRequested` event lets the application wake its proposer; the next proposal from the same source for the same target replaces it (`superseded`), and may name it in `replacesId`, its review shows the diff from what was sent back to whoever may read that one, and the version it becomes records the comment in `revision`. The proposal list gains a "Sent back" tab, the review bar a "Send back" action and a document's menu "Ask the agent to revise". A unique `openKey` keeps one open proposal per target and source, so concurrent requests cannot both open one. Adds the migration `202610260003_kb_proposals_add_revisions`; pending proposals that already share a target and source all stay pending, the oldest holding the key.
